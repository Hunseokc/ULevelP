# 02. 요구사항

ID 앞부분은 영역입니다. 각 항목의 **인수 조건**을 모두 만족해야 끝난 것으로 봅니다. "단계"는 [01-plan.md 7장](01-plan.md#7-단계별-일정)의 단계입니다. 테이블·컬럼 이름은 [04-data-model.md](04-data-model.md)를 따릅니다.

## 1. 인증 (FR-AUTH) · P0

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-AUTH-1 | 구글 계정으로 로그인·로그아웃 | 상단 메뉴의 로그인 버튼 → 구글 동의 → 원래 페이지로 돌아옴. 로그아웃하면 기기에 남은 세션이 지워짐 |
| FR-AUTH-2 | 첫 로그인 때 `profiles` 행이 자동으로 생김 (`role = 'user'`) | 새 계정으로 로그인하면 `profiles`에 행이 하나 생김 |
| FR-AUTH-3 | 운영 값(소유자 표시 `profiles.role`, 녹음 한도 `take_quota_bytes`) 지정은 DB에서만. 기능을 열고 막는 데는 `role`을 쓰지 않음(키 등록 여부로 정함, FR-KEY-GATE) | 클라이언트가 `profiles.role`·`take_quota_bytes`를 바꾸려 하면 거부됨 (테스트) |
| FR-AUTH-4 | 계정 삭제 | SETTING → 계정 삭제 → 확인 문구 입력 → 해당 사용자의 모든 행과 Storage 녹음이 지워지고 로그아웃됨. 드라이브에 저장된 녹음은 사용자 드라이브에 남는다고 안내 |
| FR-AUTH-5 | 로그인 상태가 모든 페이지 상단 메뉴에 보임 | 로그인 시 이메일 앞부분이나 이니셜, 비로그인 시 `LOGIN` |

## 2. 곡 (FR-SONG) · P1

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-SONG-1 | 플레이어에서 영상을 열면 그 영상의 곡을 찾아 위치·구간·속도를 불러옴 | 같은 영상은 사용자당 곡 하나(`unique (user_id, video_id)`) |
| FR-SONG-2 | 노션에 없는 곡일 때 "노션 추가" 버튼이 하던 일을 "곡 추가"로 | 제목·채널은 유튜브 플레이어에서 읽고, 실패하면 oEmbed(`https://www.youtube.com/oembed?format=json&url=…`)로 채움 |
| FR-SONG-3 | 위치·구간·속도는 바뀌면 4초 뒤, 재생 중에는 30초마다 자동 저장. 탭이 숨겨지거나 페이지를 닫을 때도 저장 | 지금 `practice.js`와 같은 시점에 저장됨 |
| FR-SONG-4 | 곡 상태: 연습 중 / 보류 / 완료. 곡 목록 정렬: 연습 중 → (상태 없음) → 보류 → 완료, 같은 상태면 최근 연습일 순 | 지금 `Code.gs` `listSongs`와 같은 순서 |
| FR-SONG-5 | 곡 메모, 곡 삭제 | 삭제하면 그 곡의 연습 기록·녹음도 지워진다고 확인 후 삭제 |
| FR-SONG-6 | "이어서 연습" 주소는 저장하지 않고 계산 | `practice.html?v=영상ID&t=위치&a=A&b=B&r=속도` (지금 형식 유지) |

## 3. 연습 기록 (FR-SESSION) · P1

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-SESSION-1 | 곡마다 하루에 한 줄. 여러 기기에서 연습해도 시간과 반복 횟수가 더해짐 | 두 기기에서 동시에 저장해도 행이 하나만 생기고 합이 맞음 (`add_practice` 함수 테스트) |
| FR-SESSION-2 | 합친 시간이 1분이 안 되면 아직 행을 만들지 않고, 플레이어가 남은 시간을 다음 저장에 다시 보냄 | 지금 `keep` 동작과 같음 |
| FR-SESSION-3 | 날짜는 사용자 기기의 현지 날짜 | 클라이언트가 `YYYY-MM-DD`를 보냄 |
| FR-SESSION-4 | 연습 기록에 마지막 구간, 속도, 메모 | 구간은 저장할 때마다 최신 값으로 바뀜 |

## 4. 녹음 (FR-TAKE) · P1

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-TAKE-1 | 지금 플레이어의 녹음 흐름 유지: 녹음 → 멈춤 → 자동 업로드, 실패하면 다시 올리기·파일 저장 | 지금 화면과 같은 버튼과 메시지 |
| FR-TAKE-2 | 녹음은 그날 그 곡의 연습 기록에 붙음. 연습 기록이 없으면 0분으로 만듦 | 1분 미만 연습이어도 녹음하면 연습 기록이 생김 |
| FR-TAKE-3 | 녹음 정보: 녹음 시각, 구간, 속도, 길이, 형식, 크기 | `takes` 행 |
| FR-TAKE-4 | 저장소는 Supabase Storage. 사용자별 한도(기본 200MB)를 넘으면 업로드 전에 안내 | 한도를 넘는 업로드는 서버에서도 거부됨 |
| FR-TAKE-5 | 형식은 `audio/mp4`(m4a) 우선, 안 되면 `audio/webm`. 최대 30분 | 지금 `practice.js`와 같음 |
| FR-TAKE-6 | 녹음 삭제 | 파일과 행이 같이 지워짐 |

## 5. 비로그인 기기 기록 (FR-LOCAL) · P1

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-LOCAL-1 | 로그인하지 않아도 플레이어는 동작하고 상태는 그 기기(localStorage `ulp:v:<영상ID>`, D19)와 주소에 남음 | 지금과 같은 동작, 키 이름만 `ulp:` 접두어 |
| FR-LOCAL-2 | 처음 로그인했을 때 이 기기에 기록(`ulp:v:*`)이 있으면 계정으로 옮길지 물어봄. 같은 기기에 guitar-practice 기록(`pp:v:*`)이 있으면 "guitar-practice 기록도 가져올까요?"를 따로 물어봄 | 옮기면 영상마다 곡이 생기고 위치·구간·속도가 들어감. 이미 있는 곡은 건드리지 않음. `pp:v:*`는 지우지 않음. 어느 질문이든 한 번 답하면 다시 묻지 않음 |

## 6. 기록 화면 (FR-LOG, FR-LIB) · P2

노션이 해 주던 열람 기능을 앱 안에 만듭니다. 화면 구성은 [03-design.md 8장](03-design.md#8-화면)을 따릅니다.

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-LOG-1 | 날짜별 연습 시간 달력(최근 12주, 진하기로 시간 표시) | 날짜를 누르면 그날 기록 목록 |
| FR-LOG-2 | 날짜별 기록 목록: 곡, 연습 시간, 반복 횟수, 구간, 속도, 녹음 | 녹음은 바로 재생 가능 |
| FR-LOG-3 | 이번 주·이번 달 총 연습 시간 | |
| FR-LIB-1 | 곡 목록: 상태별 필터, 상태 바꾸기, 메모 | 첫 화면 PLAYER 프레임과 플레이어 곡 목록 서랍도 같은 데이터 |
| FR-LIB-2 | 곡 상세: 그 곡의 연습 기록 타임라인, 녹음 목록 | |
| FR-LIB-3 | 녹음 두 개를 골라 번갈아 듣기 (실력 변화 비교) | 두 녹음을 같은 화면에서 재생, 하나를 재생하면 다른 하나는 멈춤 |

## 7. 노션 템플릿·내보내기·가져오기 (FR-NX) · P3

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-NX-1 | 공식 노션 템플릿 페이지를 공개하고 SETTING에서 링크 | 템플릿 구조는 [04-data-model.md 6장](04-data-model.md#6-노션-템플릿-대응표)과 같음 |
| FR-NX-2 | 내보내기: 내 데이터를 zip으로 받음 (CSV + 녹음 파일 + 안내문) | CSV 열 이름이 템플릿 속성 이름과 정확히 같음. 노션 DB의 "CSV로 병합"으로 넣으면 값이 제자리에 들어감 |
| FR-NX-3 | 가져오기: 노션의 "Markdown & CSV" 내보내기 zip을 올리면 서비스로 옮김 | 곡은 영상 ID로, 연습 기록은 (곡, 날짜)로 맞춰서 합침. 결과 요약(추가·갱신·건너뜀·오류)을 보여줌 |
| FR-NX-4 | 가져오기는 미리보기 후 확정 | 확정 전에는 DB에 쓰지 않음 |
| FR-NX-5 | 내보내기·가져오기는 로그인한 모든 사용자 | 노션 키 없이, 실시간 연동과 별개로 동작 |

## 8. 키를 등록한 사용자의 기능 (FR-KEY, FR-SYNC, FR-NOTE) · P4, P5

노션 실시간 연동과 학습 노트는 **소유자 전용이 아니라 해당 키를 등록한 로그인 사용자** 누구나 씁니다(D13·D15). 노션 키 → FR-SYNC, Gemini 키 → FR-NOTE. 비용(노션·Gemini 사용량)은 각자 키로 나갑니다. 옛 ID FR-OWN-*와의 대응은 `개발산출물/결과/R2_설계개정.md`에 있습니다.

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-KEY-1 | SETTING의 연동 키 칸(로그인한 사용자 모두)에서 노션 토큰·노션 DB 링크 3개(학습 영상 노트는 선택), Gemini 키·모델을 **따로** 등록 | 저장 후 화면에는 "설정됨 (끝 4자리 · 갱신일)"만 보이고 키 원문은 응답·네트워크 어디로도 다시 내려오지 않음. 입력란은 `type="password"` `autocomplete="off"` |
| FR-KEY-2 | 키는 Supabase Vault에 암호화 보관. 저장은 본인만(`save_*_key` RPC), 원문 조회는 service role만(`get_*_key`) | `anon`·`authenticated`로는 어떤 경로로도 키 원문을 읽을 수 없고, 남의 `user_id`로 저장할 수 없음 (테스트, NFR-SEC-8) |
| FR-KEY-3 | 연결 확인 버튼: 노션 DB 3개의 속성 이름 점검, Gemini 키 유효성 | 지금 `/health`처럼 빠진 속성 이름을 알려줌. 노션 404 → 페이지 연결 안내, 401 → 키 다시 등록 안내 |
| FR-KEY-4 | 연결 해제(노션·Gemini 각각) | 해제 뒤 `integrations` 행과 Vault 비밀이 모두 없음(SQL 확인). 노션을 해제하면 실시간 연동도 꺼짐 |
| FR-KEY-5 | 키 등록 캐시(D14): 브라우저는 "등록됨·끝 4자리·갱신 시각"만 `ulp:keys`에 둠 | 키 저장·해제 때 갱신, 서버가 키 없음(412)·키 오류를 주면 지우고 다시 읽음, 로그아웃하면 지움. 읽기 실패는 "키 없음"으로 처리하지 않음 |
| FR-KEY-GATE | 키가 필요한 기능은 그 키를 등록한 사용자만 | 화면은 캐시로 버튼을 비활성하고 안내를 보임. Edge Function은 `get_*_key`가 0행이면 412 `NO_KEY`로 거부 |
| FR-SYNC-1 | 노션 키를 등록하고 연동을 켠 사용자가 서비스에서 저장한 곡·연습 기록·녹음·노트가 노션에도 반영됨 | 저장 후 1분 안에 노션에 보임. 노션 쪽 결과물은 지금 Apps Script가 만드는 것과 같음 (녹음은 본문 오디오 블록 + `녹음` 속성) |
| FR-SYNC-2 | 노션에서 바뀐 것 가져오기: 노션에 새로 생긴 곡, 곡의 상태·메모, 연습 기록 메모 | 앱을 열 때(5분 간격 제한)와 버튼으로 실행 |
| FR-SYNC-3 | 동기화 상태 표시: 대기 중 건수, 실패 건수, 마지막 성공 시각, 최근 오류 | SETTING 연동 키 칸 (`sync_status()`) |
| FR-SYNC-4 | 처음 연동할 때 기존 노션 데이터를 서비스로 전부 가져옴 | 그 사용자의 지금 노션 기록이 서비스에 다 들어오고, 두 번 돌려도 중복이 생기지 않음. 녹음 한도를 넘는 녹음은 건너뛰고 건수를 알려줌 |
| FR-SYNC-5 | 노션 연동이 켜진 사용자는 녹음을 Storage에 저장(드라이브 켜기 숨김) | 드라이브를 켠 상태에서는 연동을 켤 수 없다고 안내 ([03 5.2](03-design.md#52-구글-드라이브-p6)) |
| FR-NOTE-1 | 학습 노트 요청: 유튜브 링크, 태그(화성, 사운드 디자인, DAW/MIDI, 리듬, 편곡, 믹싱), 메모 | 지금 `notes.html`과 같은 입력 |
| FR-NOTE-2 | 분석 진행 상태(대기·분석 중·완료·실패)와 실패 이유 | 화면을 닫았다 열어도 상태가 보임 |
| FR-NOTE-3 | 노트를 앱 안에서 보기: 요약, 태그별 표, 주요 구간(누르면 플레이어 그 시간으로), 연습 과제 | 지금 노션 페이지에 들어가는 내용과 같음 |
| FR-NOTE-4 | 노트를 노션 학습 영상 노트 DB에도 생성 (노션 연동이 켜져 있으면) | FR-SYNC-1과 같은 경로 |
| FR-NOTE-5 | Gemini 키가 없는 사용자는 노트 만들기 버튼이 비활성 (D14) | 유튜브 링크를 넣어도 비활성이고, 버튼 옆에 "SETTING에서 Gemini 키 등록" 안내와 링크. 캐시를 조작해 요청해도 서버가 412로 거부 |
| FR-NOTE-6 | 이미 만든 노트는 키를 지워도 본인 데이터로 남음 | Gemini 키 해제 뒤에도 노트 목록·보기·내보내기 동작 |

## 9. 구글 드라이브 (FR-DRIVE) · P6

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| FR-DRIVE-1 | SETTING에서 "녹음을 구글 드라이브에 저장" 켜기 | `drive.file` 권한 동의 후 켜짐. 드라이브에 `ULeveLP 녹음` 폴더 생성 |

| FR-DRIVE-5 | 끄기 | 이후 새 녹음은 Storage로. 드라이브 파일은 그대로 남음 |

## 10. 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-SEC-1 | 클라이언트에는 Supabase URL과 공개(anon) 키, 구글 클라이언트 ID만 둔다. 서비스 키는 Edge Function에만, 사용자가 등록한 노션 토큰·Gemini 키는 Vault에만 |
| NFR-SEC-2 | 모든 사용자 테이블에 RLS를 켜고, "다른 사용자 행 읽기·쓰기·삭제 불가"를 테이블마다 자동 테스트로 확인 |

| NFR-SEC-4 | Storage 경로는 `{user_id}/…`, 본인 폴더만 접근 |

| NFR-SEC-7 | (XSS ③, D20) 외부 스크립트는 정확한 버전의 단일 파일(UMD) + `integrity`(sha384) + `crossorigin="anonymous"`. SRI를 걸 수 없는 제공자 스크립트(YouTube IFrame API, Google Identity Services)는 CSP에서 정확한 경로로만 허용 ([03 2.2](03-design.md#22-외부-스크립트-불러오기-umd--sri-d20)). 확인: X1 (b) |
