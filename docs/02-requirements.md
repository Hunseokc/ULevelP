# 02. 요구사항 정의서 (Kotlin + Google Cloud Run)

> **문서 버전:** 2026-10-30
> **표기 규칙:** 각 요구사항 ID는 도메인 영역을 나타내며, 명시된 **인수 조건(Acceptance Criteria)**을 모두 통과해야 구현 완료로 인정합니다.

## 1. 인증 및 계정 관리 (`FR-AUTH`) · P0

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-AUTH-1** | **Google OAuth 로그인 및 로그아웃** | • 상단 메뉴 `LOGIN` 클릭 시 Google OAuth 2.0 동의 화면을 거쳐 로그인하고 원래 보던 페이지로 복귀한다.<br>• 로그아웃 시 브라우저에 저장된 인증 토큰과 키 등록 캐시(`ulp:keys`)가 즉시 삭제된다. |
| **FR-AUTH-2** | **신규 가입 시 프로필 자동 생성** | • 최초 Google 로그인 시 `users` 및 `profiles` 테이블에 기본값(`role = 'user'`, `storage_provider = 'gcs'`, `take_quota_bytes = 209715200` [200MB])으로 행이 자동 생성된다. |
| **FR-AUTH-3** | **운영 권한 및 쿼터 변조 방지** | • `profiles.role`(`user` / `owner`)과 `take_quota_bytes`는 서버 API(`PATCH /api/v1/me`) 요청 본문에 포함되더라도 무시·거부되며, 오직 DB 관리자만 변경할 수 있다.<br>• 기능 활성화 여부는 `role`이 아닌 키 등록 여부(`FR-KEY-GATE`)로만 판단한다. |
| **FR-AUTH-4** | **계정 탈퇴 및 데이터 완전 삭제** | • `SETTING` → 계정 삭제 → 확인 문구 입력 시 `DELETE /api/v1/me`를 호출한다.<br>• 서버는 클라우드 스토리지(`takes/{userId}/*`)의 모든 오디오 파일, 암호화 보관된 외부 API 키, DB의 모든 하위 레코드(`songs`, `sessions`, `takes`, `notes`, `analysis_jobs`, `notion_sync`, `sync_outbox`)를 트랜잭션으로 영구 삭제한다.<br>• 사용자의 Google Drive에 이미 업로드된 파일은 본인 드라이브에 남는다는 점을 사전 안내한다. |
| **FR-AUTH-5** | **상단 메뉴 계정 상태 표시** | • 모든 페이지 상단 네비게이션 바 우측 끝에 비로그인 시 `LOGIN`, 로그인 시 사용자 이름 이니셜(또는 이메일 앞부분)을 표시한다. 클릭 시 `settings.html` 계정 섹션으로 이동한다. |

## 2. 연습 곡 관리 (`FR-SONG`) · P1

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-SONG-1** | **영상별 단일 곡 조회 및 상태 복원** | • 플레이어(`practice.html`)에서 유튜브 영상을 열면 `GET /api/v1/songs/by-video/{videoId}`로 해당 사용자의 곡 정보를 조회한다.<br>•同一 사용자 내에서 같은 `videoId`는 하나의 곡만 존재한다(`UNIQUE (user_id, video_id)`).<br>• 우선순위: URL 쿼리 파라미터(`?t=&a=&b=&r=`) > 서버 저장 값 > 기기 로컬 저장소(`ulp:v:{videoId}`). |
| **FR-SONG-2** | **곡 추가 및 메타데이터 자동 채움** | • 등록되지 않은 영상을 연습할 때 "곡 추가"를 누르면 `POST /api/v1/songs`로 곡을 생성한다.<br>• 클라이언트가 유튜브 플레이어(`getVideoData()`)에서 제목·채널명을 읽지 못한 경우, Kotlin 서버가 `https://www.youtube.com/oembed`를 호출해 제목(`title`)과 아티스트(`artist`)를 자동으로 채운다. |
| **FR-SONG-3** | **재생 상태 자동 저장** | • 마지막 위치(`pos`), 구간(`a`, `b`), 속도(`rate`) 변경 시 4초 디바운스 후, 재생 중에는 30초 주기로, 그리고 탭 숨김(`visibilitychange`) 및 페이지 닫기(`pagehide`, `keepalive: true`) 시점에 `POST /api/v1/practice/save`로 자동 저장한다. |
| **FR-SONG-4** | **곡 상태 분류 및 정렬 규칙** | • 곡 상태는 `practicing`(연습 중), `paused`(보류), `done`(완료) 3가지를 지원한다.<br>• 목록 조회 시 정렬 순서: **연습 중 → 보류 → 완료** 순이며, 동일 상태 내에서는 **최근 연습일(`last_date`) 내림차순 → 최근 수정일 내림차순**으로 정렬한다(기존 `Code.gs` `listSongs`와 동일). |
| **FR-SONG-5** | **곡 메모 수정 및 삭제** | • 곡별 상태와 메모를 수정(`PATCH /api/v1/songs/{id}`)할 수 있다.<br>• 곡 삭제(`DELETE /api/v1/songs/{id}`) 시 해당 곡에 속한 모든 연습 기록(`sessions`)과 녹음(`takes`, 스토리지 파일 포함)이 함께 삭제됨을 경고한 뒤 삭제한다. |
| **FR-SONG-6** | **이어서 연습 URL 동적 계산** | • "이어서 연습" 링크(`practice.html?v={videoId}&t={pos}&a={a}&b={b}&r={rate}`)는 DB 컬럼으로 중복 저장하지 않고 API 응답 DTO 및 노션 동기화/내보내기 시점에 동적으로 계산한다. |

## 3. 연습 세션 기록 (`FR-SESSION`) · P1

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-SESSION-1** | **일별·곡별 단일 세션 누적 합산** | • 한 곡에 대해 하루(`date`, `YYYY-MM-DD`)에 하나의 `sessions` 행만 생성한다(`UNIQUE (user_id, song_id, date)`).<br>• 여러 기기(예: 아이패드와 PC)에서 동시에 같은 곡을 연습하고 저장해도 DB `ON CONFLICT DO UPDATE`를 통해 연습 시간(`seconds`)과 반복 횟수(`loops`)가 유실 없이 원자적으로 합산된다. |
| **FR-SESSION-2** | **1분 미만 신규 세션 생성 보류 (`kept`)** | • 당일 해당 곡의 세션이 아직 없을 때 전달된 연습 시간(`addSeconds`)이 **60초 미만**이면 DB에 행을 생성하지 않고 `{ kept: true, pendingSeconds: addSeconds }`를 반환한다.<br>• 플레이어는 `kept: true`를 받으면 미저장 시간을 초기화하지 않고 유지했다가 다음 자동 저장 시 합산하여 다시 전송한다. (단, 이미 당일 세션 행이 존재하면 60초 미만이어도 즉시 합산한다.) |
| **FR-SESSION-3** | **사용자 현지 날짜 기준 기록** | • 연습 날짜는 서버 시각이 아닌 사용자 기기의 현지 날짜(`YYYY-MM-DD`)를 기준으로 기록한다. |
| **FR-SESSION-4** | **구간·속도 최신화 및 세션 메모** | • 연습 기록 저장 시 해당 시점의 연습 구간(`a`, `b`)과 속도(`rate`)로 세션의 최신 상태를 갱신한다.<br>• 기록 화면(`log.html`)에서 각 연습 세션에 대한 메모(`memo`)를 작성·수정할 수 있다. |

## 4. 오디오 녹음 (`FR-TAKE`) · P1

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-TAKE-1** | **플레이어 녹음 및 자동 업로드 흐름** | • 기존 플레이어의 녹음 UX(녹음 시작 → 정지 → 자동 업로드, 실패 시 재시도 버튼 및 로컬 파일 다운로드 버튼 제공)를 그대로 유지한다. |
| **FR-TAKE-2** | **당일 세션 자동 보장 (`ensureSession`)** | • 녹음 파일 업로드 시 당일 해당 곡의 `sessions` 행이 아직 없으면(연습 시간 1분 미만인 경우 포함), 연습 시간 `0초`, 반복 `0회`인 세션을 자동으로 먼저 생성한 뒤 녹음(`takes`)을 연결한다. |
| **FR-TAKE-3** | **녹음 메타데이터 기록** | • 각 녹음마다 녹음 시각(`recorded_at`), 당시 구간(`a`, `b`), 속도(`rate`), 재생 길이(`duration_sec`), MIME 타입(`mime`), 파일 크기(`size_bytes`), 저장소 종류(`storage`), 저장소 키(`storage_key`)를 기록한다. |
| **FR-TAKE-4** | **개인별 스토리지 쿼터(200MB) 제어** | • 기본 스토리지(`gcs` / `supabase`) 사용 시 사용자별 누적 녹음 용량이 `profiles.take_quota_bytes`(기본 200MB)를 초과하면 업로드를 `413 Payload Too Large` (`code: "TAKE_QUOTA_EXCEEDED"`)로 거부한다.<br>• `SETTING` 화면에 현재 사용량 / 전체 한도 막대그래프를 표시한다. |
| **FR-TAKE-5** | **지원 오디오 포맷 및 파일 크기 제한** | • 지원 MIME: `audio/mp4`(m4a 우선), `audio/webm`(weba), `audio/ogg`, `audio/mpeg`, `audio/wav`, `audio/aac`.<br>• 단일 녹음 파일 최대 크기는 50MB(최대 녹음 시간 30분)로 제한한다. |
| **FR-TAKE-6** | **녹음 재생 및 삭제** | • 재생 요청 시 60분간 유효한 Presigned URL을 발급하여 브라우저 `<audio>`에서 즉시 스트리밍한다.<br>• 녹음 삭제 시 스토리지의 실제 오브젝트와 DB `takes` 행을 함께 삭제하고 사용량 쿼터를 즉시 반환한다. |

## 5. 비로그인 기기 기록 및 마이그레이션 (`FR-LOCAL`) · P1

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-LOCAL-1** | **비로그인 로컬 저장 모드** | • 로그인하지 않은 상태에서도 플레이어는 정상 동작하며, 영상별 위치·구간·속도는 `localStorage`의 `ulp:v:{videoId}` 키와 URL 파라미터에 저장된다. |
| **FR-LOCAL-2** | **최초 로그인 시 기기 기록 계정 이관** | • 로그인 직후 `profiles.migrated_local_at`이 `null`이고 브라우저에 `ulp:v:*` 데이터가 존재하면 "이 기기에서 연습하던 기록을 계정으로 옮길까요?" 확인 창을 띄운다.<br>• 같은 기기에 자매 앱(`guitar-practice`)의 `pp:v:*` 기록이 있으면 별도로 가져올지 물어본다(`pp:v:*` 원본은 삭제하지 않음).<br>• 승인 시 `POST /api/v1/songs/migrate-local`을 호출해 일괄 등록(이미 서버에 있는 곡은 유지)하고 `migrated_local_at`을 현재 시각으로 기록하여 다시 묻지 않는다. 거절해도 `migrated_local_at`을 기록해 재질문을 방지한다. |

## 6. 인앱 기록 및 보관함 화면 (`FR-LOG`, `FR-LIB`) · P2

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-LOG-1** | **12주 연습 달력 (히트맵)** | • `log.html`의 `기록` 탭에서 최근 12주간의 날짜별 총 연습 시간을 정사각형 달력(연습 시간 구간별 잉크 농도 4단계, 기록 없는 날은 테두리 선만)으로 표시한다.<br>• 특정 날짜 칸을 클릭하면 해당 날짜의 연습 세션 목록을 하단에 표시한다. |
| **FR-LOG-2** | **날짜별 연습 기록 상세 및 즉시 재생** | • 선택된 날짜의 연습 곡명, 연습 시간(분), 반복 횟수, 연습 구간, 속도, 메모, 그리고 그날 녹음한 테이크 재생 버튼을 표시한다. |
| **FR-LOG-3** | **주간·월간 누적 연습 시간 요약** | • `기록` 탭 상단에 이번 주(월~일) 총 연습 시간과 이번 달 총 연습 시간을 표시한다. |
| **FR-LIB-1** | **곡 보관함 필터 및 상태/메모 편집** | • `log.html`의 `곡` 탭에서 전체 / 연습 중 / 보류 / 완료 상태 필터(필 버튼)를 제공한다.<br>• 각 곡의 제목, 아티스트, 상태, 마지막 연습일, 총 누적 연습 시간을 보여주며 상태와 메모를 즉시 변경할 수 있다. |
| **FR-LIB-2** | **곡 상세 타임라인 (`log.html?song={id}`)** | • 곡을 클릭하면 곡 상세 화면으로 전환되어 헤더(`▶ 이어서 연습` 바로가기 포함), 날짜별 연습 시간 막대 타임라인, 전체 녹음 테이크 목록을 보여준다. |
| **FR-LIB-3** | **녹음 A/B 비교 듣기** | • 곡 상세의 녹음 목록에서 과거 녹음과 최근 녹음 2개를 체크박스로 선택하면 하단(또는 상단)에 **A/B 비교 재생 패널**이 열린다.<br>• A 재생 중 B를 누르면 A가 자동으로 일시정지되어 연주 실력 변화를 직관적으로 비교할 수 있다. |

## 7. 노션 템플릿 및 내보내기/가져오기 (`FR-NX`) · P3

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-NX-1** | **공식 노션 템플릿 제공** | • `연습 곡`, `연습 기록`, `학습 영상 노트` 3개 인라인 DB와 플레이어 임베드가 포함된 공식 노션 템플릿 링크를 `SETTING`에서 제공한다. |
| **FR-NX-2** | **서비스 데이터 노션 호환 ZIP 내보내기** | • 로그인한 모든 사용자는 노션 API 키 없이도 내 데이터를 `ULeveLP-export-YYYY-MM-DD.zip`으로 다운로드할 수 있다.<br>• 구성: `읽어주세요.txt`, `연습 곡.csv`, `연습 기록.csv`, `학습 영상 노트.csv`, `학습 영상 노트/*.md`, `녹음/*.m4a` (녹음 제외 옵션 지원).<br>• CSV는 UTF-8 BOM을 포함하며 노션 템플릿 속성명과 100% 일치해 노션의 "CSV로 병합" 기능으로 즉시 임포트된다. |
| **FR-NX-3** | **노션 백업 ZIP 가져오기** | • 노션에서 "Markdown & CSV(하위 페이지 포함)"로 내보낸 ZIP 파일을 업로드하면 서버(`POST /api/v1/import/notion/preview`)가 CSV와 오디오 파일 구조를 해석한다.<br>• 곡은 `video_id` 기준, 연습 기록은 `(song_id, date)` 기준으로 매칭하여 덮어쓰기(멱등성 보장)로 병합한다. |
| **FR-NX-4** | **가져오기 미리보기(Dry-run) 및 확정** | • ZIP 업로드 시 DB에 바로 쓰지 않고 **신규 곡 수, 갱신 곡 수, 연습 기록 수, 녹음 파일 수, 파싱 오류 행 목록**을 미리보기로 제시한다.<br>• 사용자가 "가져오기 확정"을 눌렀을 때만 DB 및 스토리지에 반영한다. |

## 8. 외부 연동 키 관리 (`FR-KEY`) · P4

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-KEY-1** | **노션·Gemini 키 개별 등록 및 마스킹** | • `SETTING`의 연동 키 섹션에서 노션(토큰 + DB ID 3개)과 Gemini(API 키 + 모델명)를 각각 독립적으로 등록할 수 있다.<br>• 입력 필드는 `type="password" autocomplete="off"`이며, 저장 이후에는 `"설정됨 (끝 4자리 · YYYY-MM-DD)"`만 표시되고 **어떤 API 응답으로도 키 원문은 다시 내려오지 않는다.** |

| **FR-KEY-5** | **클라이언트 키 상태 캐시 (`ulp:keys`) 및 게이트웨이** | • 브라우저는 키 원문이 없는 상태 요약(`{ uid, notion: { hint, updatedAt }, gemini: { hint, updatedAt } }`)만 `localStorage` `ulp:keys`에 캐시하여 버튼 활성화에 사용한다.<br>• 키가 없는 사용자가 강제로 API를 호출하면 서버가 `412 Precondition Failed` (`code: "NO_KEY"`)로 거부하며, 노션 401 또는 Gemini 400/403 발생 시 클라이언트는 캐시를 무효화하고 키 재확인 안내를 표시한다. |

## 9. 노션 실시간 양방향 동기화 (`FR-SYNC`) · P4

| ID | 요구사항명 | 상세 설명 및 인수 조건 |
| --- | --- | --- |
| **FR-SYNC-1** | **서비스 → 노션 자동 반영 (Push)** | • 노션 실시간 연동을 켠 사용자가 곡 추가/수정, 연습 저장, 녹음 업로드, 학습 노트 생성, 또는 항목 삭제를 수행하면 `sync_outbox` 대기열을 통해 **1분 이내에 노션 DB에 동일하게 반영**된다.<br>• 녹음은 기존 `Code.gs`와 동일하게 당일 연습 기록 페이지 본문 하단에 캡션 문단(`🎙 HH:MM · 구간 · 속도 · 길이`) + 오디오 블록을 추가하고 `녹음` 파일 속성에도 첨부한다(20MB 초과 시 10MB 단위 멀티파트 업로드).<br>• 서비스에서 삭제된 항목은 노션 페이지를 보관함(`archived: true`)으로 이동시킨다. |
| **FR-SYNC-2** | **노션 → 서비스 증분 반영 (Pull)** | • 연동을 켠 사용자가 앱을 열 때(마지막 Pull 이후 5분 경과 시) 또는 `SETTING`의 "지금 가져오기" 버튼을 누르면 `POST /api/v1/notion/sync/pull`을 실행한다.<br>• `last_edited_time > last_pull_at`인 노션 페이지를 조회하여, 노션에서 새로 추가한 곡(크롬 확장 프로그램 등으로 넣은 곡 포함), 곡의 제목·아티스트·상태·메모·구간, 연습 기록의 메모를 서비스 DB에 반영한다.<br>• Pull로 인해 반영된 변경사항은 다시 `sync_outbox`에 들어가지 않아야 한다(무한 루프 방지). |
| **FR-SYNC-3** | **동기화 상태 모니터링** | • `SETTING`에서 현재 동기화 활성화 여부, 대기 중(`pending`) 건수, 5회 이상 실패(`failed`) 건수, 마지막 Push/Pull 시각, 최근 오류 메시지를 확인할 수 있다. |
| **FR-SYNC-4** | **초기 전체 동기화 (`full` 모드)** | • 처음 "연동 켜기"를 누르면 기존 노션 DB 3개의 전체 데이터(과거 연습 기록 시간·반복 횟수 및 노션에 올라가 있는 녹음 파일 포함)를 읽어 서비스 DB와 스토리지로 이관하고 `notion_links` 매핑을 생성한 뒤 `enabled = true`로 전환한다.<br>• 두 번 실행해도 중복 행이 생기지 않으며(멱등성), 200MB 녹음 한도를 초과하는 녹음 파일은 건너뛰고 건수를 결과에 안내한다. |
| **FR-SYNC-5** | **구글 드라이브 저장소와의 상호 배타 제어** | • 백엔드 동기화 워커는 사용자의 Google Drive 파일을 백그라운드에서 읽을 수 없으므로, 노션 연동이 켜진 동안에는 녹음 저장소를 기본 클라우드 스토리지로 고정한다(드라이브가 켜진 상태에서 노션 연동을 켜려 하면 드라이브 저장을 먼저 끄도록 안내). |

## 12. 비기능 요구사항 (`NFR`)

| 분류 | ID | 요구사항 내용 및 검증 기준 |
| --- | --- | --- |
| **보안 (XSS/CSP)** | **NFR-SEC-1** | • 모든 HTML 응답(또는 `<meta>`)에 엄격한 CSP를 적용한다. Cloud Run 서빙 시 `frame-ancestors 'none'`을 추가하여 Clickjacking을 원천 차단한다.<br>• 외부 텍스트(유튜브 제목, 노션 속성, Gemini 분석 결과, CSV 입력값)는 반드시 `textContent` 또는 `esc()` 이스케이프를 거쳐 렌더링하며, 외부 URL은 `safeUrl()`(`https:` 프로토콜만 허용)을 통과해야 한다(기존 X1 정적 테스트 및 X2 Playwright 페이로드 테스트 통과 필수). |
| **보안 (인증/권한)** | **NFR-SEC-2** | • 모든 API 엔드포인트(공개 계산 API 및 `/api/health` 제외)는 유효한 JWT를 요구하며, 모든 DB 쿼리는 인증된 `userId`를 조건절에 강제한다.<br>• 타 사용자의 `songId`나 `sessionId`를 참조해 세션·녹음을 생성하려는 시도는 `403 Forbidden` 또는 `404 Not Found`로 차단한다(사용자 A/B 교차 침투 통합 테스트 필수). |
| **보안 (시크릿)** | **NFR-SEC-3** | • 브라우저 `localStorage`에는 어떠한 API 키·토큰 원문도 저장하지 않는다(세션 JWT 제외).<br>• 모든 신규 로컬 스토리지 키는 `ulp:` 접두어를 사용하며, 동일 Origin의 타 앱 키(`pp-api`, `pp-key`, `sn-token`)를 읽지 않는다. |
| **운영 / 비용 보호** | **NFR-OPS-1** | • **Rate Limiting:** Cloud Run 실행 비용 보호를 위해 Gemini 학습 노트 분석은 **사용자당 동시 실행 1건, 일 최대 20건**(`429 RATE_LIMITED`)으로 제한한다.<br>• 노션 수동/자동 Pull은 **사용자당 5분 간격**(`retryAfter` 반환)으로 제한한다. |
| **디자인 / UX** | **NFR-UX-1** | • 모든 신규 화면(`log.html`, `note.html`, `settings.html` 개편)은 [`DESIGN.md`](../DESIGN.md)의 규칙(웜 뉴트럴 배경, 명도 대비 강조, 파란색은 링크·근음 한정, 필 버튼, 직각 카드, 터치 타겟 최소 44px, 모바일 390px 가로 스크롤 없음)을 준수한다. |
| **오프라인 복원력** | **NFR-UX-2** | • 연습 중 일시적으로 네트워크가 끊겨도 플레이어 재생과 연습 시간 카운트는 중단되지 않으며, 연결이 복구되면 누적된 미저장 연습 시간을 다음 자동 저장 요청에 합산하여 전송한다. |
