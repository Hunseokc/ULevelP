### RZ-3 리뷰에서 나온 것 (PR #45 코멘트가 원본)
- **R-1 (완료, PR #45 `076eabc`):** `ci.yml` Docker 롤백 단계 `! curl … | grep -q`는 레거시 컨테이너가 안 떠도 통과(로컬 재현 exit 0). 수정(`BODY=$(curl …)` + `if grep …; then exit 1; fi` + `src="home.js"` 긍정 검사, 실측 legacy 0·spa 1·서버 없음 7)
- **R-2 (수정, PR #46 — RZ-M 전 머지 필요):** Cloud Run에서 같은 출처 POST·PUT·DELETE가 CORS 403. Ktor가 forwarded header를 처리하지 않아 출처를 `http://<run.app>`로 보고 브라우저의 `Origin: https://<run.app>`을 거부. 저장소 Variables가 비어 있어 `ALLOWED_ORIGINS`=`https://hunseokc.github.io`. `ulevelp:rz3` 로컬 재현: 같은 출처 Origin → 403, Origin 없음 → 401, run.app 추가 후 → 401. 운영 실측(2026-11-03, 배포 전): 같은 출처 POST → 403 확정. 수정: `ktor-server-forwarded-header` + `install(XForwardedHeaders)`(프로토콜 헤더만 신뢰), 테스트 `ForwardedHeadersTest` Z7. Docker 실측 같은 출처 401·evil 403·`X-Forwarded-Host` 위조 403·Pages 401. 테스트 엔진에선 인증 401이 CORS 403을 덮어써서 Z7은 `/api/health`로 판정
- **R-3~R-5 (선택, 후속):** spa E2E의 조용한 legacy 폴백 가드(`#root` 단언), 배포 스모크에 `id="root"` 확인, Ktor 시작 로그에 UI 모드
- R1 문서 재료: Pages는 노션 임베드용이다(`ci.yml` Version asset URLs 주석). Cloud Run은 `frame-ancestors 'none'`이라 임베드 불가. `PUBLIC_APP_URL` 기본값이 Pages라 노션 "이어서 연습" 링크(`SongService.kt:477-484`)는 Pages 레거시로 간다. Pages의 `config.js` `apiBaseUrl`은 `''`라 Pages에선 `/api` 없음
