### 2.1 `security/CryptoService.kt` 추가분

`CryptoService.Companion` 안에 아래 함수를 추가한다:

```kotlin
fun fromEnvOrNull(
    env: Map<String, String> = System.getenv(),
    envKey: String = "APP_MASTER_KEY",
    keyVersion: Short = 1
): CryptoService? {
    val raw = env[envKey]?.trim()?.takeIf { it.isNotEmpty() } ?: return null
    return fromBase64Key(raw, keyVersion)
}

/** 32자리 16진수(하이픈 허용)를 검증한 뒤 하이픈을 제거하고 소문자 32자로 정규화한다 */
fun normalizeNotionDatabaseId(dbId: String): String =
    validateNotionDatabaseId(dbId).replace("-", "").lowercase()
```

```kotlin
interface IntegrationCheckClient {

        songsDb: String,

    ): NotionCheckResponse

    suspend fun checkGemini(

        model: String

class HttpIntegrationCheckClient(
    private val notionBaseUrl: String = "https://api.notion.com/v1",
    private val geminiBaseUrl: String = "https://generativelanguage.googleapis.com/v1beta",
    private val httpClient: HttpClient = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(5)).build()
) : IntegrationCheckClient {
    companion object {
        const val NOTION_VERSION = "2022-06-28"
        val REQUIRED_SONGS_PROPS = listOf(
            "곡명", "아티스트", "상태", "이어서 연습", "유튜브 링크",
            "마지막 위치(초)", "구간 시작(초)", "구간 끝(초)", "속도", "마지막 연습일"
        )
        val REQUIRED_SESSIONS_PROPS = listOf(
            "기록", "곡", "날짜", "연습 시간(분)", "구간", "속도", "반복 횟수", "녹음"
        )
        val REQUIRED_NOTES_PROPS = listOf(
            "제목", "URL", "태그", "채널", "요약", "키워드", "난이도", "메모"
        )
    }

```
- `HttpIntegrationCheckClient.checkNotion`:
  - `withContext(Dispatchers.IO)`에서 `GET $notionBaseUrl/databases/$songsDb`, `GET $notionBaseUrl/databases/$sessionsDb`, 그리고 `notesDb != null`이면 `GET $notionBaseUrl/databases/$notesDb` 호출 (헤더 `Authorization: Bearer $token`, `Notion-Version: 2022-06-28`).
  - 상태 코드 처리:
    - `401` 또는 `403` → `throw ApiException(HttpStatusCode.BadRequest, "PROVIDER_KEY_INVALID", "노션 통합 토큰이 유효하지 않습니다. 토큰을 다시 확인해 주세요.", source = "notion")`
    - `404` → `throw ApiException(HttpStatusCode.NotFound, "NOTION_OBJECT_NOT_FOUND", "노션 데이터베이스를 찾을 수 없습니다. 노션 페이지에 통합(Connections)을 연결했는지 확인해 주세요.", source = "notion")`
    - 그 외 비정상 상태 → `throw ApiException(HttpStatusCode.BadGateway, "NOTION_API_ERROR", "노션 API 호출에 실패했습니다 (HTTP $status).", source = "notion")`
  - 각 DB 응답 JSON의 `properties` 객체에 `REQUIRED_SONGS_PROPS`, `REQUIRED_SESSIONS_PROPS`, (`notesDb != null`일 때 `REQUIRED_NOTES_PROPS`)의 키가 모두 존재하는지 확인한다.
  - 하나라도 빠져 있으면 누락된 속성 이름들을 모아 `throw ApiException(HttpStatusCode.BadRequest, "NOTION_SCHEMA_MISMATCH", "노션 데이터베이스에 필수 속성이 없습니다: ${missing.joinToString(", ")}", source = "notion")`.
  - `GET $notionBaseUrl/users/me`를 호출해 `bot.workspace_limits.max_file_upload_size_in_bytes`가 있으면 `MB`(`bytes / 1048576`)로 변환, 실패하거나 없으면 기본값 `5`.
- `HttpIntegrationCheckClient.checkGemini`:
  - `withContext(Dispatchers.IO)`에서 `GET $geminiBaseUrl/models/$model` 호출 (헤더 `x-goog-api-key: $apiKey` — URL 쿼리에 키를 넣지 않는다).
  - 상태 코드 처리:
    - `400`, `401`, `403` → `throw ApiException(HttpStatusCode.BadRequest, "PROVIDER_KEY_INVALID", "Gemini API 키가 유효하지 않거나 권한이 없습니다.", source = "gemini")`
    - `404` → `throw ApiException(HttpStatusCode.NotFound, "GEMINI_MODEL_NOT_FOUND", "지정한 Gemini 모델($model)을 찾을 수 없습니다.", source = "gemini")`
    - 그 외 비정상 상태 → `throw ApiException(HttpStatusCode.BadGateway, "GEMINI_API_ERROR", "Gemini API 호출에 실패했습니다 (HTTP $status).", source = "gemini")`
  - 성공 시 응답 JSON의 `displayName`(없으면 `model`)을 읽어 `GeminiCheckResponse(ok = true, provider = "gemini", model = model, displayName = displayName)` 반환.

## 5. 처리 순서·트랜잭션 경계

### 5.1 `saveNotion(userId, input)` / `saveGemini(userId, input)` (트랜잭션 1개)
1. `cryptoService` 확인(`null`이면 `throw ApiException(HttpStatusCode.ServiceUnavailable, "CRYPTO_UNAVAILABLE", "서버 암호화 키(APP_MASTER_KEY)가 설정되어 있지 않습니다.")`).
2. **입력 정규식 검증 및 `InvalidIntegrationKeyException` → `InvalidInputException`(`400`) 변환 (중요 — 변환하지 않으면 `StatusPages`에서 500이 됨):**
   - 노션 DB ID는 필드별로 각각 검증·정규화한다:
     ```kotlin
     fun normalizeDbField(fieldName: String, raw: String): String =
         try {
             CryptoService.normalizeNotionDatabaseId(raw)
         } catch (_: InvalidIntegrationKeyException) {
             throw InvalidInputException("$fieldName 형식이 올바르지 않습니다 (32자리 16진수 ID가 필요합니다).")
         }
     val normSongsDb = normalizeDbField("songsDb", input.songsDb)
     val normSessionsDb = normalizeDbField("sessionsDb", input.sessionsDb)
     val normNotesDb = input.notesDb?.takeIf { it.isNotBlank() }?.let { normalizeDbField("notesDb", it) }
     ```
   - `token` / `apiKey`가 비어 있지 않을 때 암호화 호출도 `try { cryptoService.encryptProviderKey(...) } catch (e: InvalidIntegrationKeyException) { throw InvalidInputException(e.message) }`로 감싸 `400 INVALID_INPUT`으로 변환한다.
   - Gemini `model`은 `if (!GEMINI_MODEL_REGEX.matches(input.model)) throw InvalidInputException("model 형식이 올바르지 않습니다.")`.
3. `DatabaseFactory.dbQuery(database)` 안에서:
   - `IntegrationsTable`에서 `(userId, appId, provider)` 기존 행 조회.
   - 새 키 문자열이 주어졌으면 위에서 만든 `EncryptedPayload`를 사용한다.
   - 새 키 문자열이 비어 있고 기존 행이 있으면 기존 `encryptedSecret`, `iv`, `keyVersion`, `hint`를 그대로 유지(`FR-KEY-2`).
   - 새 키 문자열이 비어 있고 기존 행이 없으면 `throw InvalidInputException("최초 등록 시 노션 통합 토큰(token)이 필요합니다.")` (Gemini는 `"최초 등록 시 Gemini API 키(apiKey)가 필요합니다."`).
   - 기존 행이 없으면 `IntegrationsTable.insert`, 있으면 `IntegrationsTable.update` (`config`, `encryptedSecret`, `iv`, `keyVersion`, `hint`, `updatedAt = OffsetDateTime.now(ZoneOffset.UTC)`).
   - 갱신된 행을 읽어 `IntegrationDto` 반환.

### 5.2 `checkNotion(userId, appId)` / `checkGemini(userId, appId)`
1. **트랜잭션 1 (읽기 전용):** `IntegrationsTable`에서 `(userId, appId, provider)` 조회 → 없으면 `412 NO_KEY`. `cryptoService.decryptProviderKey`로 평문 키와 `config` 복호화.
2. **트랜잭션 밖:** `checkClient.checkNotion(...)` 또는 `checkClient.checkGemini(...)` 호출 후 결과 반환.

### 5.3 `delete(userId, appId, provider)` (트랜잭션 1개)
1. `IntegrationsTable.deleteWhere { (IntegrationsTable.userId eq userId) and (IntegrationsTable.appId eq appId) and (IntegrationsTable.provider eq provider) }`.
2. 만약 `provider == "notion" && appId == "ulevelp"`이면 같은 트랜잭션 안에서 `NotionSyncTable.update({ NotionSyncTable.userId eq userId }) { it[enabled] = false; it[leaseUntil] = null; it[leaseOwner] = null }` 실행(`FR-KEY-4`).

- 어떤 API 응답이나 로그에도 노션 토큰·Gemini API 키 원문이나 암호문 바이트를 내려보내지 않는다(`hint` 끝 4자리만 반환).

- Gemini 점검 시 API 키를 URL 쿼리(`?key=...`)에 넣지 않는다(반드시 `x-goog-api-key` 헤더로 전송).
- 쿼터 막대를 그릴 때 `style="width: ..."` 인라인 속성을 쓰지 않는다(`<progress id="quotaBar" class="tl-bar">` 사용).
- 다음 step(K4-2)을 이어서 진행하지 않는다.
