## 2. 시그니처

### 2.1 `storage/StorageClient.kt` & `SupabaseStorageClient.kt` 확장

```kotlin
interface StorageClient {
    suspend fun upload(key: String, bytes: ByteArray, contentType: String)
    suspend fun createSignedUrl(key: String, expiresInSec: Int): String
    suspend fun delete(key: String)
    /** 오브젝트 바이트 배열을 내려받는다. 없거나 실패하면 StorageException */
    suspend fun download(key: String): ByteArray
}
```
- `SupabaseStorageClient.download(key: String): ByteArray`:
  - 요청: `GET $supabaseUrl/storage/v1/object/$bucket/$key`
  - 헤더: `Authorization: Bearer $secretKey`, `apikey: $secretKey`
  - `withContext(Dispatchers.IO)`에서 `httpClient.send(request, HttpResponse.BodyHandlers.ofByteArray())` 호출.
  - 상태 코드 `200..299`이면 `response.body()` 반환, 아니면 `throw StorageException("Supabase Storage download 실패: HTTP ${response.statusCode()}")`.
- `FakeStorageClient.download(key: String): ByteArray`:
  - `objects[key] ?: throw StorageException("Fake object not found: $key")`.

```kotlin
/** loadExportData가 DB에서 읽어 온 내보내기용 스냅샷 */
class ExportBundleData internal constructor(

class ExportImportService(
    private val db: Database?,
    private val storageClient: StorageClient?,
    private val publicAppUrl: String,
    private val clock: Clock = Clock.systemUTC()
) {
    /**
     * 1단계: DB에서 사용자의 곡·세션·녹음·노트 행을 조회한다.
     * DB가 연결되어 있지 않으면 여기서 503 DB_UNAVAILABLE 예외를 던진다(스트리밍 시작 전).
     */
    suspend fun loadExportData(userId: UUID): ExportBundleData

    /** 2단계: 조회한 ExportBundleData와(includeAudio=true면) 스토리지 오디오를 ZipOutputStream으로 out에 쓴다 */
    suspend fun writeExportZip(data: ExportBundleData, includeAudio: Boolean, out: OutputStream)

    /** 노션 백업 ZIP 바이트를 파싱하여 미리보기 캐시에 저장하고 요약을 반환한다 (DB 쓰기 없음) */
    suspend fun previewNotionZip(userId: UUID, zipBytes: ByteArray): ImportPreviewResponse

    /** previewToken에 해당하는 파싱 데이터를 DB와 Storage에 반영한다 */
    suspend fun confirmNotionZip(userId: UUID, previewToken: UUID): ImportConfirmResponse

    companion object {
        const val MAX_ZIP_BYTES = 104_857_600L           // 100MB
        const val MAX_UNZIPPED_BYTES = 209_715_200L      // 200MB (Zip Bomb 방어)
        const val MAX_PREVIEW_AUDIO_BYTES = 52_428_800L  // 미리보기 1건당 메모리 보관 오디오 합계 한도 50MB
        const val MAX_ZIP_ENTRIES = 1_000
        const val PREVIEW_TTL_SECONDS = 900L             // 15분
        const val MAX_PREVIEWS_PER_USER = 1              // 사용자당 최신 미리보기 1개만 유지 (단일 인스턴스 전제)
        const val MAX_TOTAL_PREVIEWS = 10                // 서버 전체 최대 10개 유지
        const val UTF8_BOM = "\uFEFF"

        /** 파일 확장자(소문자) -> 지원 오디오 MIME 타입 매핑 표 (K4-3에서도 공용으로 사용) */
        val EXT_TO_MIME: Map<String, String> = mapOf(
            "m4a" to "audio/mp4",
            "mp4" to "audio/mp4",
            "weba" to "audio/webm",
            "webm" to "audio/webm",
            "ogg" to "audio/ogg",
            "mp3" to "audio/mpeg",
            "wav" to "audio/wav",
            "aac" to "audio/aac"
        )

        /** RFC 4180 CSV 셀 이스케이프 (쉼표, 큰따옴표, 줄바꿈이 있으면 큰따옴표로 감싸고 내부 "는 ""로) */
        fun csvCell(value: String?): String

        /** UTF-8 BOM을 제거하고 RFC 4180 CSV 텍스트를 행(List<List<String>>)으로 파싱한다 */
        fun parseCsv(rawText: String): List<List<String>>

        /** "m:ss–m:ss" 또는 "m:ss-m:ss" 문자열에서 (a, b) 초(BigDecimal 소수 1자리) 쌍을 복원한다. 실패 시 (null, null) */
        fun parseSegment(raw: String?): Pair<BigDecimal?, BigDecimal?>

        /**
         * 오디오 파일명과 소속 세션 날짜에서 recordedAt(UTC OffsetDateTime, 초 단위 절삭)을 복원한다 (K4-3 공용).
         * 1) "^(\\d{4}-\\d{2}-\\d{2})_(\\d{2})(\\d{2})(\\d{2})_" (ZIP 내보내기 형식, UTC 초 단위) -> UTC OffsetDateTime
         * 2) "^(\\d{4}-\\d{2}-\\d{2})\\s+(\\d{2})(\\d{2})(?:\\s+|\\.|$)" (노션 업로드 형식, Asia/Seoul 분 단위) -> +09:00 파싱 후 UTC 변환
         * 3) 그 외 또는 파싱 실패 -> sessionDate.atStartOfDay().atOffset(ZoneOffset.UTC)
         */
        fun parseRecordedAtFromFilename(filename: String, sessionDate: LocalDate): OffsetDateTime
    }
}
```

### 2.3 `routes/ExportImportRoutes.kt` (package `ulevelp.routes`)

`TakeRoutes.kt`·`SongRoutes.kt`처럼 `SupabaseAuthPlugin`을 설치한다.

```kotlin
fun Route.registerExportImportRoutes(
    jwtVerifier: SupabaseJwtVerifier?,
    profileService: ProfileService,
    exportImportService: ExportImportService
)
//   install(SupabaseAuthPlugin) — 하위 경로:
//   get("/export/zip")                 GET  /api/v1/export/zip?includeAudio=true
//   post("/import/notion/preview")     POST /api/v1/import/notion/preview (multipart/form-data, part "file")
//   post("/import/notion/confirm")     POST /api/v1/import/notion/confirm ({ "previewToken": "..." })
```
- `GET /api/v1/export/zip`:
  - `includeAudio` 쿼리 파라미터: `null`·`""`·`"true"` → `true`, `"false"` → `false`, 그 외 → `InvalidInputException("includeAudio는 true 또는 false여야 합니다.")`.
  - 먼저 `val data = exportImportService.loadExportData(user.id)`를 호출한다(DB 미설정 시 여기서 `503 DB_UNAVAILABLE`이 발생해 JSON 에러로 응답됨).
  - 오늘 날짜(`LocalDate.now(ZoneOffset.UTC)`)로 파일명 `"ULeveLP-export-$today.zip"` 생성.
  - `call.response.headers.append(HttpHeaders.CacheControl, "no-store")`
  - `call.response.headers.append(HttpHeaders.ContentDisposition, "attachment; filename=\"ULeveLP-export-$today.zip\"")`
  - `call.respondOutputStream(ContentType.Application.Zip, HttpStatusCode.OK) { exportImportService.writeExportZip(data, includeAudio, this) }`
- `POST /api/v1/import/notion/preview`:
  - `call.request.isMultipart()`가 `false`이면 `throw InvalidInputException("multipart/form-data 요청이 필요합니다.")`.
  - `Content-Length`가 `ExportImportService.MAX_ZIP_BYTES + 1_048_576L` 초과 시 `throw ApiException(HttpStatusCode.PayloadTooLarge, "ZIP_TOO_LARGE", "ZIP 파일은 100MB 이하만 올릴 수 있습니다.")`.
  - `file` 파트(`PartData.FileItem`)에서 `readRemaining(ExportImportService.MAX_ZIP_BYTES + 1).readByteArray()`로 읽는다.
  - `file` 파트가 없거나 `bytes.isEmpty()`이면 `throw InvalidInputException("ZIP 파일(file 파트)이 비어 있거나 누락되었습니다.")`.
  - `bytes.size > ExportImportService.MAX_ZIP_BYTES`이면 `throw ApiException(HttpStatusCode.PayloadTooLarge, "ZIP_TOO_LARGE", "ZIP 파일은 100MB 이하만 올릴 수 있습니다.")`.
  - `val res = exportImportService.previewNotionZip(user.id, bytes)`
  - `call.response.headers.append(HttpHeaders.CacheControl, "no-store")`
  - `call.respond(HttpStatusCode.OK, res)`
- `POST /api/v1/import/notion/confirm`:
  - `val body = call.receiveJsonObject()`
  - `val previewToken = body.requireUuid("previewToken")`
  - `val res = exportImportService.confirmNotionZip(user.id, previewToken)`
  - `call.response.headers.append(HttpHeaders.CacheControl, "no-store")`
  - `call.respond(HttpStatusCode.OK, res)`

## 3. DTO 및 CSV·녹음 복원 포맷 표

### 3.1 CSV 컬럼 규격 (`docs/04-db-design.md` 4절과 100% 일치)

모든 CSV 파일은 맨 앞에 `UTF-8 BOM`(`\uFEFF`, 바이트 `EF BB BF`)을 붙이고 줄바꿈은 `\r\n`을 쓴다.

1. **`연습 곡.csv` (11열):**
   `곡명,아티스트,상태,유튜브 링크,이어서 연습,마지막 위치(초),구간 시작(초),구간 끝(초),속도,마지막 연습일,메모`
2. **`연습 기록.csv` (9열):**
   `기록,곡,날짜,연습 시간(분),반복 횟수,속도,구간,메모,녹음`
3. **`학습 영상 노트.csv` (8열):**
   `제목,URL,태그,채널,요약,키워드,난이도,메모`

## 5. 처리 순서·트랜잭션 경계

### 5.1 `loadExportData(userId)` & `writeExportZip(data, includeAudio, out)`
1. **`loadExportData(userId)` (트랜잭션 1, 읽기 전용):**
   - `requireDb()` 확인 후 사용자의 모든 `songs`(상태·최근 연습일 순), `sessions`(`date DESC, updatedAt DESC`), `takes`(`recordedAt ASC`), `notes`(`createdAt DESC`)를 조회하여 `ExportBundleData`로 반환한다.
2. **`writeExportZip(data, includeAudio, out)` (트랜잭션 밖):**
   - `includeAudio == true && storageClient != null`이면 `data.takes` 중 `storage == "supabase"`인 각 녹음에 대해:
     - 파일명 `녹음/${sessionDate}_${HHmmss}_${safeSongTitle}_${take.id.take(8)}.${ext}` 생성 (`HHmmss`는 `recordedAt` **UTC 기준** `HHmmss` — 같은 분에 여러 번 녹음해도 파일명과 초 단위 시각이 유지되도록 UTC 초 단위를 씀).
     - `runCatching { storageClient.download(take.storageKey) }`: 성공한 파일만 ZIP의 `녹음/...` 엔트리와 `연습 기록.csv`의 `녹음` 열에 포함한다.
   - `ZipOutputStream(out, Charsets.UTF_8)`에 `읽어주세요.txt`, `연습 곡.csv`, `연습 기록.csv`, `학습 영상 노트.csv`, `학습 영상 노트/*.md`, `녹음/*` 엔트리를 순서대로 쓴다.

### 5.2 `previewNotionZip(userId, zipBytes)`
1. **ZIP 압축 해제 (메모리 내, 트랜잭션 밖):**
   - `ZipInputStream`으로 엔트리를 읽되, 총 읽은 바이트가 `MAX_UNZIPPED_BYTES`(200MB), 엔트리 수가 `MAX_ZIP_ENTRIES`(1000개), 또는 추출한 오디오 엔트리 합계가 `MAX_PREVIEW_AUDIO_BYTES`(50MB)를 넘으면 즉시 중단하고 `InvalidInputException("유효한 ZIP 파일이 아니거나 압축 해제 크기 제한(200MB)을 초과했습니다.")` 발생.
   - 만약 엔트리가 `.zip` 파일이면(노션 이중 압축 백업) 1단계 내부 `ZipInputStream`까지 풀어서 엔트리를 수집한다.
2. **CSV 식별 및 파싱:**
   - `.csv` 엔트리들의 첫 줄(헤더)을 파싱해:
     - `곡명` 컬럼과 (`유튜브 링크` 또는 `이어서 연습`) 컬럼이 모두 있으면 **연습 곡 CSV**로 선택(노션이 `_all.csv`와 일반 `.csv` 두 개를 넣은 경우 `_all.csv`가 아닌 첫 번째 파일 선택).
     - `기록` 컬럼과 `날짜` 컬럼이 모두 있으면 **연습 기록 CSV**로 선택.
   - 연습 곡 CSV가 없으면 `400 INVALID_INPUT`.
   - **연습 곡 행 파싱:**
     - `유튜브 링크` 또는 `이어서 연습`에서 11자리 유튜브 `videoId` 추출. 추출 실패 시 `errors`에 `{ file, row, reason: "유튜브 링크에서 11자리 영상 ID를 찾지 못했습니다." }` 추가 후 건너뜀.
     - 같은 CSV 안에 동일 `videoId`가 여러 번 나오면 **먼저 나온 첫 번째 행만 채택**하고 이후 중복 행은 건너뛴다.
     - `곡명`(비면 `"(제목 없음)"`, 300자 제한), `아티스트`(200자 제한), `상태`(`SongService.normalizeStatus(raw) ?: "practicing"`), `마지막 위치(초)`/`구간 시작(초)`/`구간 끝(초)`(`0..86400`, `a >= b`이면 둘 다 `null`), `속도`(`0.25..2.0`, 기본 `1.00`), `마지막 연습일`(`YYYY-MM-DD`), `메모`(2000자 제한) 파싱.
3. **트랜잭션 1 (읽기 전용 — 기존 곡 조회):**
   - 사용자의 기존 `SongsTable`에서 모든 곡을 `lastDate DESC NULLS LAST, updatedAt DESC` 순으로 읽어 `existingByVideoId`(`videoId -> SongRow`)와 `existingByTitleLower`(`title.lowercase() -> 첫 번째 SongRow`) 맵을 만든다.
   - 파싱된 곡 중 `videoId in existingByVideoId`이면 `updatedSongs`, 아니면 `newSongs`로 분류한다.
4. **연습 기록 및 오디오 매칭 (연습 기록 CSV가 있을 때):**
   - `날짜`: `YYYY-MM-DD` 앞 10자리 추출, 형식 불일치 시 `errors`에 기록 후 건너뜀.
   - **곡 매칭 우선순위 (단일 순서로 고정):**
     ① `곡` 컬럼 값에서 노션 링크 괄호(`replace(Regex("\\s*\\(https?://[^)]+\\)\\s*$"), "").trim()`)를 제거한 제목이 비어 있지 않으면, `parsedSongs`에서 `title.equals(cleanedTitle, ignoreCase = true)`인 첫 번째 곡의 `videoId`와 매칭한다.
     ② ①에서 못 찾고 `곡` 컬럼이 비어 있으면, `기록` 컬럼 값에서 앞의 날짜 접두어(`replace(Regex("^\\d{4}-\\d{2}-\\d{2}\\s+"), "").trim()`)를 제거한 제목으로 `parsedSongs`에서 대소문자 구분 없이 첫 번째 일치하는 곡의 `videoId`와 매칭한다.
     ③ ①·②에서 못 찾으면 기존 DB 곡 맵(`existingByTitleLower`)에서 해당 제목(소문자)과 일치하는 곡의 `videoId`와 매칭한다.
     ④ ①~③ 모두 매칭되지 않으면 `errors`에 `{ file, row, reason: "연결된 연습 곡을 찾을 수 없습니다: <곡명>" }` 기록 후 건너뛴다.
   - 같은 `(videoId, date)` 세션이 CSV에 여러 번 나오면 먼저 나온 첫 번째 행만 채택한다.
   - `연습 시간(분)`: `Math.round(minutes * 60.0).toInt().coerceIn(0, 86400)`초. `반복 횟수`: `0..100000`. `속도`: `0.25..2.0`. `구간`: `parseSegment(raw)`. `메모`: 2000자 이하.
   - `녹음` 열: 쉼표로 나뉜 각 경로에서 `URLDecoder.decode(..., UTF_8)` 후 파일명(마지막 `/` 뒤)을 추출해 ZIP 내 오디오 엔트리와 매칭하고, **3.2절 복원 규칙 표**에 따라 `recordedAt`, `durationSec = 0`, `mime`, `sizeBytes`, `a`, `b`, `rate`를 결정한다.
5. **미리보기 캐시 저장 (원본 `zipBytes` 미보관, 사용자당 1개 유지):**
   - 만료된 캐시(TTL 15분 경과)와 해당 `userId`의 이전 미리보기 엔트리를 제거하고, 전체 개수가 `MAX_TOTAL_PREVIEWS`(10개) 이상이면 가장 오래된 엔트리를 제거한다.
   - 새 `previewToken = UUID.randomUUID()`로 파싱 결과(`parsedSongs`, `parsedSessions`, `parsedTakes`)만 저장하고 `ImportPreviewResponse`를 반환한다.

### 5.3 `confirmNotionZip(userId, previewToken)`
1. `ImportPreviewStore`에서 `(userId, previewToken)`을 원자적으로 꺼내 제거한다(없거나 만료됐거나 `entry.userId != userId`이면 `throw NotFoundException("미리보기 내역이 없거나 만료되었습니다. ZIP 파일을 다시 선택해 주세요.")`).
2. **트랜잭션 1 (곡·세션 Upsert):**
   - 각 곡(`parsedSongs`)에 대해 `(userId, videoId)`로 기존 곡 확인:
     - 없으면 새 `UUID`로 `SongsTable.insert` (`createdSongs++`) + `OutboxRepository.enqueueIfSyncEnabled(userId, "song", songId, "upsert")`.
     - 있으면 `SongsTable.update` (`title`, `artist`, `status`, `pos`, `a`, `b`, `rate`, `lastDate = max(기존, 새값)`, `memo`, `updatedSongs++`) + `OutboxRepository.enqueueIfSyncEnabled(userId, "song", songId, "upsert")`.
   - 각 세션(`parsedSessions`)에 대해 `(userId, songId, date)`로 기존 세션 확인:
     - 없으면 `SessionsTable.insert` (`upsertedSessions++`) + `OutboxRepository.enqueueIfSyncEnabled(userId, "session", sessionId, "upsert")`.
     - 있으면 `SessionsTable.update` (`seconds`, `loops`, `rate`, `a`, `b`, `memo` 덮어쓰기, `upsertedSessions++`) + `OutboxRepository.enqueueIfSyncEnabled(userId, "session", sessionId, "upsert")`.
     - 곡의 `lastDate`가 세션 `date`보다 작거나 `null`이면 `SongsTable.lastDate`도 함께 갱신한다.
3. **녹음 파일 반영 (`parsedTakes`가 있고 `storageClient != null`일 때):**
   - 각 녹음(`take`)에 대해:
     - **사전 중복 및 쿼터 검사(트랜잭션):** 해당 `sessionId`에 동일한 `(session_id = sessionId, recorded_at = take.recordedAt, size_bytes = take.bytes.size.toLong())`를 가진 행이 이미 `TakesTable`에 있으면 건너뛴다(멱등성 보장). 없으면 `ProfilesTable` `FOR UPDATE`로 `usedBytes + take.bytes.size <= takeQuotaBytes` 확인 후 초과면 `skippedTakesByQuota++`하고 건너뛴다.
     - **트랜잭션 밖 업로드:** `val takeId = UUID.randomUUID()`, `val key = "$userId/$takeId.$ext"`, `storageClient.upload(key, take.bytes, take.mime)`.
     - **DB 기록(짧은 트랜잭션, 실패 시 `TakeService`와 동일하게 파일 삭제 보상):** `ProfilesTable` `FOR UPDATE` 쿼터 재확인 → `TakesTable.insert` (3.2절 표의 컬럼값 그대로) → `OutboxRepository.enqueueIfSyncEnabled(userId, "take", takeId, "upsert")` (`importedTakes++`).
4. `ImportConfirmResponse` 반환.

## 9. 금지 사항

- ZIP·CSV 처리를 위해 `build.gradle.kts`에 외부 라이브러리(Apache Commons CSV 등)를 임의로 추가하지 않는다.
- `previewNotionZip` 실행 중 DB(`songs`, `sessions`, `takes`)에 어떤 행도 INSERT/UPDATE하지 않는다(`FR-NX-4`).
- `ImportPreviewStore`에 원본 `zipBytes` 통째로 보관하지 않는다(파싱된 결과만 사용자당 1개 보관).
- `settings.js`에서 미리보기 결과(`songsSample`, `errors`)를 렌더링할 때 `esc()` 없는 `innerHTML`이나 인라인 `style=` 속성을 절대 쓰지 않는다.
- `settings.js`의 기존 `pp-api`·`pp-key`나 `sn-token`·`sn-repo` 코드를 이 step에서 지우지 않는다(`test/security.test.js`의 `STORAGE_LEGACY` 검사가 실패함).
- 다음 step(K4-1)을 이어서 진행하지 않는다.
