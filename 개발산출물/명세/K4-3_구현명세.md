## 5. 처리 순서·트랜잭션 경계

### 5.1 노션 페이지 및 녹음(`takes`) 컬럼 파싱 규칙 (`Code.gs` `readSong` + `K3-1` 3.2절 공통)
1. **곡 페이지(`songsDb`):**
   - `archived == true` 또는 `in_trash == true`이면 건너뛴다.
   - `유튜브 링크`(`url`) 또는 `이어서 연습`(`url`)에서 11자리 `videoId` 추출(없으면 건너뜀).
   - `곡명`(`title` plain_text, 비면 `"(제목 없음)"`, 300자), `아티스트`(`rich_text` plain_text, 200자), `상태`(`select.name` → `SongService.normalizeStatus` ?: `"practicing"`), `마지막 위치(초)`/`구간 시작(초)`/`구간 끝(초)`(`0..86400`, `a >= b`이면 둘 다 `null`), `속도`(`0.25..2.0`, 기본 `1.00`), `마지막 연습일`(`date.start` 앞 10자리 `YYYY-MM-DD`), `메모`(`rich_text` plain_text, 2000자).
2. **세션 페이지(`sessionsDb`):**
   - `곡`(`relation` 배열 첫 번째 `id` = `songNotionPageId`), `날짜`(`date.start` 앞 10자리 `YYYY-MM-DD`), `연습 시간(분)`(`number` → `Math.round(minutes * 60.0).toInt().coerceIn(0, 86400)`초), `반복 횟수`(`number` → 정수 `0..100000`), `속도`(`number` `0.25..2.0`), `구간`(`rich_text` → `ExportImportService.parseSegment`), `메모`(`rich_text`, 2000자), `녹음`(`files` 배열의 각 항목에서 `name` 및 `file.url` 또는 `external.url` 추출).
3. **노션 녹음 파일 → `takes` 컬럼 복원 규칙 (`K3-1` 3.2절 표와 동일):**
   - `recordedAt`: `ExportImportService.parseRecordedAtFromFilename(file.name, session.date)` (`"2026-10-30 1422 Autumn Leaves.m4a"` → 서울 시각 `14:22` → UTC `2026-10-30T05:22:00Z`, 실패 시 `${session.date}T00:00:00Z`).
   - `durationSec`: `0`.
   - `mime`: 파일명 확장자(소문자)를 `ExportImportService.EXT_TO_MIME`으로 매핑(표에 없는 확장자는 건너뜀).
   - `sizeBytes`: 다운로드한 `bytes.size.toLong()` (`1..52_428_800`).
   - `a`, `b`, `rate`: 소속 세션의 `a`, `b`, `rate` 복사. `memo`: `""`.

### 5.2 `enable(userId)` (`full` 모드 초기 동기화)
1. **트랜잭션 1 (사전 검증):** `ProfilesTable`에서 `storageProvider == "drive"`이면 `409 NOTION_SYNC_CONFLICT`.
2. `integrationService.requireDecryptedNotion(userId, "ulevelp")`로 토큰과 DB ID 획득(없으면 `412 NO_KEY`).
3. **트랜잭션 밖 (노션 전체 조회 — 최대 500페이지 캡):**
   - `notionClient.queryDatabase(token, songsDb, ...)` 페이지네이션으로 곡 페이지 수집(누적 500개 `MAX_PAGES_PER_SYNC`에 도달하면 에러 없이 루프를 종료하고 수집된 500개만 반영).
   - `notionClient.queryDatabase(token, sessionsDb, ...)` 페이지네이션으로 세션 페이지 수집(최대 500개).
4. **트랜잭션 2 (곡·세션 멱등 병합 및 `notion_links` 연결):**
   - 각 노션 곡에 대해 `(userId, videoId)` 조회:
     - 없으면 `SongsTable.insert` + `NotionLinksTable` Upsert (`importedSongs++`).
     - 있으면 노션 값으로 `SongsTable.update`(`lastDate = max(기존, 노션)`) + `NotionLinksTable` Upsert (`importedSongs++`).
   - 각 노션 세션에 대해 `songNotionPageId`를 `NotionLinksTable`에서 찾아 로컬 `songId` 확인(없으면 건너뜀):
     - `(userId, songId, date)`로 기존 세션 조회:
       - 없으면 `SessionsTable.insert` + `NotionLinksTable` Upsert (`importedSessions++`).
       - 있으면 `seconds = max(기존, 노션초)`, `loops = max(기존, 노션반복)`, `rate`, `a`, `b`, `memo` UPDATE + `NotionLinksTable` Upsert (`importedSessions++`).
   - **중요:** 노션에서 가져온 항목들에 대해서는 `OutboxRepository.enqueueIfSyncEnabled`를 부르지 않는다.
5. **녹음 파일 이관 (`storageClient != null`일 때 — 다운로드 전 중복 필터 포함):**
   - 각 노션 세션(`sessionPageId`, 로컬 `sessionId`)의 `녹음` 파일 항목(`file.name`, `fileUrl`)에 대해:
     - **다운로드 전 1차 중복 검사(트랜잭션):**
       ① `NotionLinksTable`에 `(userId = userId, entity = "take", notionExtra = "$sessionPageId:${file.name}")`가 이미 존재하거나,
       ② `parsedRecordedAt = ExportImportService.parseRecordedAtFromFilename(file.name, session.date)`에 대해 해당 `sessionId`의 기존 `TakesTable` 행 중 `recordedAt.truncatedTo(ChronoUnit.MINUTES) == parsedRecordedAt.truncatedTo(ChronoUnit.MINUTES)`인 행이 이미 존재하면 **오디오 URL 다운로드를 수행하지 않고 즉시 건너뛴다** (PL3 2회 실행 시 재다운로드 0건 보장).
     - **트랜잭션 밖 다운로드:** `val (bytes, _) = notionClient.downloadExternalFile(fileUrl)` (`bytes.isEmpty() || bytes.size > TakeService.MAX_FILE_BYTES`이면 건너뜀).
     - **쿼터 확인 및 업로드:** `ProfilesTable` `FOR UPDATE`로 `usedBytes + bytes.size <= takeQuotaBytes` 확인(초과면 `skippedTakesByQuota++`하고 건너뜀) → 트랜잭션 밖에서 `storageClient.upload("$userId/$takeId.$ext", bytes, mime)` → 짧은 트랜잭션으로 `TakesTable.insert` (5.1절 3번 컬럼 규칙) 및 `NotionLinksTable`에 `(entity = "take", entityId = takeId, userId = userId, notionPageId = "take-import:$takeId", notionExtra = "$sessionPageId:${file.name}")` INSERT (`importedTakes++`).
6. **트랜잭션 3 (`notion_sync.enabled = true` 활성화 및 로컬 미연결 데이터 Outbox 적재):**
   - `NotionSyncTable`에 `enabled = true`, `lastPullAt = now`, `lastError = null`로 Upsert.
   - 로컬 `songs`·`sessions`·`takes` 중 아직 `NotionLinksTable`에 매핑이 없는(노션에는 없고 앱에만 있던) 항목들을 찾아 `OutboxRepository.enqueueIfSyncEnabled`로 적재한다.

### 5.3 `pull(userId)` (증분 가져오기 — 분 단위 절삭 보정 · 로컬 충돌 보호 · 무한 루프 방지)
1. **트랜잭션 1 (검증):**
   - `integrationService.requireDecryptedNotion(userId, "ulevelp")` 확인.
   - `NotionSyncTable`에서 `userId` 조회 → 없거나 `!enabled`이면 `400 INVALID_INPUT`.
   - `lastPullAt != null`이고 `Duration.between(lastPullAt.toInstant(), now).seconds < 300`이면 `val retry = (300 - elapsed).toInt().coerceAtLeast(1)`과 함께 `throw ApiException(HttpStatusCode.TooManyRequests, "RATE_LIMITED", "노션 가져오기는 5분마다 실행할 수 있습니다. 잠시 후 다시 시도해 주세요.", retryAfter = retry)`.
2. **트랜잭션 밖 (노션 증분 쿼리 — `lastPullAt - 2분` 보정):**
   - 노션은 `last_edited_time`을 분 단위로 절삭해 저장하므로 같은 분 안의 수정이 빠지지 않도록 **`val querySince = lastPullAt?.minusMinutes(PULL_LOOKBACK_MINUTES)`** (`lastPullAt - 2분`)를 필터 `{ "timestamp": "last_edited_time", "last_edited_time": { "after": querySince.toString() } }`에 넣어 `songsDb`와 `sessionsDb`를 각각 조회한다(최대 500페이지 캡).
3. **트랜잭션 2 (DB 반영 — 미처리 로컬 Outbox 우선 보호 및 Outbox 미적재!):**
   - 먼저 `SyncOutboxTable`에서 `user_id = userId AND done_at IS NULL AND attempts < 5`인 미처리 `(entity, entityId)` 집합(`pendingOutboxSet`)을 조회한다.
   - 변경된 각 곡 페이지에 대해 `(userId, videoId)`(또는 `NotionLinksTable`의 `entityId`)로 기존 곡을 찾는다:
     - 만약 기존 곡 `songId`가 있고 `("song", songId) in pendingOutboxSet`이면 **로컬 수정사항이 아직 Push되기 전이므로 덮어쓰지 않고 건너뛴다(로컬 우선)**.
     - 그렇지 않으면 INSERT/UPDATE하고 `NotionLinksTable`을 갱신한다 (`updatedSongs++`).
   - 변경된 각 세션 페이지에 대해 `(userId, songId, date)`로 기존 세션을 찾는다:
     - 만약 기존 세션 `sessionId`가 있고 `("session", sessionId) in pendingOutboxSet`이면 **로컬 수정사항을 보호하기 위해 건너뛴다**.
     - 그렇지 않으면 INSERT/UPDATE하고 `NotionLinksTable`을 갱신한다 (`updatedSessions++`).
   - **절대 `OutboxRepository.enqueueIfSyncEnabled`를 호출하지 않는다 (`FR-SYNC-2`: Pull 반영분은 `sync_outbox`에 들어가지 않아야 함).**
   - `NotionSyncTable.update({ NotionSyncTable.userId eq userId }) { it[lastPullAt] = now; it[lastError] = null }`.
