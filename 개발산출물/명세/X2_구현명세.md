## 3. 페이로드 및 모킹 데이터 표

### 3.1 XSS 페이로드 4종 (`PAYLOADS`)

| ID | 문자열 | 노리는 취약점 |
| --- | --- | --- |
| `P_IMG` | `<img src=x onerror="window.__xss=1">` | HTML 본문(`innerHTML`)에 `esc()` 없이 삽입될 때 실행 |
| `P_SVG` | `"><svg onload="window.__xss=1">` | 속성값이나 태그 내부를 탈출해 새 요소를 만들 때 실행 |
| `P_JS_URL` | `javascript:window.__xss=1` | `href`·`src`에 `safeUrl()` 없이 삽입된 뒤 클릭할 때 실행 |
| `P_ATTR` | `' onclick='window.__xss=1` | 작은따옴표로 감싼 속성을 탈출해 인라인 이벤트 핸들러를 심을 때 실행 |

### 3.2 모킹할 데이터 객체 (`test/e2e/xss.spec.js` 내부 헬퍼)

1. **가짜 로그인 주입 (`setupMockAuthAndApi(page)`):**
   - `page.addInitScript`에서:
     - `window.__xss = false;`
     - `window.__cspViolations = [];`
     - `document.addEventListener('securitypolicyviolation', (e) => { window.__cspViolations.push(e.violatedDirective + ':' + e.blockedURI); });`
   - CDN의 `@supabase/supabase-js` 스크립트(`https://cdn.jsdelivr.net/npm/@supabase/supabase-js@**`) 및 YouTube IFrame API(`https://www.youtube.com/**`) 요청을 `page.route`로 가로채어 오프라인/CI에서도 외부 네트워크 지연 없이 즉시 동작하는 최소 스텁(또는 실제 로컬 응답)을 반환한다:
     - `supabase.createClient` 스텁은 가짜 세션 `{ access_token: 'fake-jwt-token', user: { id: '00000000-0000-4000-8000-000000000001', email: '<img src=x onerror="window.__xss=1">@example.com', user_metadata: { full_name: '"><svg onload="window.__xss=1">' } } }`을 돌려준다 (`auth.js`가 그대로 읽고 `/api/v1/me`를 호출하도록).
2. **모킹할 `/api/v1/*` 응답:**
   - `GET /api/v1/me`:
     ```json
     {
       "id": "00000000-0000-4000-8000-000000000001",
       "email": "<img src=x onerror=\"window.__xss=1\">@example.com",
       "displayName": "\"><svg onload=\"window.__xss=1\">",
       "role": "user",
       "storageProvider": "supabase",
       "driveFolderId": null,
       "takeUsedBytes": 1024,
       "takeQuotaBytes": 209715200,
       "migratedLocalAt": "2026-10-30T00:00:00Z",
       "keys": { "notion": null, "gemini": null }
     }
     ```
   - `GET /api/v1/songs*`, `GET /api/v1/songs/by-video/*`, `POST /api/v1/songs`:
     - 곡 4개를 반환하되 각 곡의 `title`, `artist`, `memo`에 페이로드 4종(`P_IMG`, `P_SVG`, `P_JS_URL`, `P_ATTR`)을 각각 넣고, `resumeUrl`에는 `"javascript:window.__xss=1"`을 넣는다.
   - `GET /api/v1/sessions*`:
     - `summary: { thisWeekSeconds: 3600, thisMonthSeconds: 7200 }`, `calendar: [{ date: "2026-10-30", totalSeconds: 3600, level: 4 }]`, `sessions`에 `songTitle: P_IMG`, `songArtist: P_SVG`, `memo: P_ATTR`, `takes: [{ id: "t1", sessionId: "s1", recordedAt: "2026-10-30T10:00:00Z", a: 10, b: 20, rate: 0.75, durationSec: 15, mime: "audio/mp4", sizeBytes: 1000, storage: "supabase", storageKey: "u/t1.m4a", memo: P_IMG }]` 반환.
   - `GET /api/v1/songs/{songId}`:
     - `song`(위 페이로드 곡), `sessions`(위 페이로드 세션), `takes`(위 페이로드 녹음 2개) 반환.
   - `GET /api/v1/takes/*/url`:
     - `{ url: "javascript:window.__xss=1", expiresIn: 3600 }` 반환 (`safeUrl()`이 이를 빈 문자열로 막아 `<audio src>`에 위험한 스킴이 들어가지 않는지 검증).

## 4. 검증·단언 규칙

모든 E2E 케이스(대조군 E7 제외)가 끝날 때 아래 공통 단언 함수 `assertNoXssOrCsp(page)`를 호출한다:
1. `expect(await page.evaluate(() => window.__xss)).toBe(false)`
2. `expect(await page.evaluate(() => window.__cspViolations)).toEqual([])`
3. 주입한 페이로드 원문(예: `<img src=x onerror="window.__xss=1">`)이 실행되지 않고 화면의 텍스트(`textContent`)로 그대로 보이는지 확인하며, DOM 안에 `img[src="x"]`나 `svg[onload]` 요소가 생성되지 않았는지(`await page.locator('img[src="x"], svg[onload]').count() === 0`) 확인한다.
4. `javascript:window.__xss=1`이 들어간 링크/미디어 속성은 `safeUrl()`에 의해 걸러져 `a[href^="javascript:"]`, `audio[src^="javascript:"]`가 0개인지(`count() === 0`) 확인한다.

## 9. 금지 사항

- `package.json`의 `"test"` 스크립트에 `playwright test`를 합치지 않는다(`npm test`는 단위·정적 검사 전용으로 빠르게 유지하고 Playwright는 `npm run test:e2e` 및 CI `e2e-security` 작업에서 실행).
- 고의 제거 확인 후 프로덕션 코드의 `esc()` 제거 상태를 커밋하지 않는다.
- 테스트를 통과시키기 위해 CSP를 느슨하게(`'unsafe-inline'` 추가 등) 바꾸지 않는다.
- 다음 묶음(C0, K3-1)을 이어서 진행하지 않는다.
