## 2. 시그니처·동작

### 2.1 `public/data.js` — `window.ULData`

파일 첫 줄 주석 `// 서버 데이터 접근(로그인 사용자): 곡·플레이어 저장·녹음 업로드·기기 기록 이관`, 다음 줄 `'use strict';`, `auth.js`처럼 `window.ULData = (function () { … return { … }; })();`.
`window.ULAuth`(K0-4)의 `getSession()`, `apiFetch(path, opts)`, `getMe()`, `fetchMe()`만 쓴다. `auth.js`는 고치지 않는다.

| 이름 | 인자 | 요청 | 반환(Promise) |
| --- | --- | --- | --- |
| `isLoggedIn()` | — | 없음(동기) | `boolean` — `ULAuth.getSession()`에 `access_token`이 있으면 `true` |
| `songs.list(status)` | `status` 문자열 또는 생략 | `GET /api/v1/songs` (+ `?status=` + `encodeURIComponent(status)`) | `r.songs` 배열 |
| `songs.byVideo(videoId)` | 11자 id | `GET /api/v1/songs/by-video/` + `encodeURIComponent(videoId)` | `r.song` (객체 또는 `null`) |
| `songs.create(input)` | `{ videoId, title, artist, rate }` | `POST /api/v1/songs`, 본문 그 4개 키만 | `r.song` |
| `saveProgress(body, opts)` | `body`, `opts.keepalive` | `POST /api/v1/practice/save`, 본문은 `songId, pos, a, b, rate, date, addSeconds, addLoops` 8개 키만 골라 보냄 | 서버 응답 객체 그대로 (`{ ok, keep, sessionId, totalSeconds, minutes, pendingSeconds }`) |
| `takes.upload(meta, blob)` | `meta = { songId, date, recordedAt, a, b, rate, durationSec, mime }`, `Blob` | `POST /api/v1/takes`, `FormData`: `metadata` = `new Blob([JSON.stringify(meta 8개 키)], { type: 'application/json' })`, `file` = `blob`, 파일 이름 `'take.' + (EXT[mime] || 'webm')` | `r.take` |
| `runLocalMigration()` | — | 2.2절 | `{ status: 'skipped' \| 'done' \| 'failed', created, skipped, message }` |

- 로그인하지 않았으면 `isLoggedIn()` 외의 모든 함수는 서버를 부르지 않고 `Error('로그인이 필요해요')`(`err.code = 'NOT_LOGGED_IN'`, `err.status = 401`)로 reject한다. `runLocalMigration`만 예외로 `{ status: 'skipped', created: 0, skipped: 0, message: '' }`를 돌려준다.
- 일반 요청은 `ULAuth.apiFetch`를 쓴다(오류 시 `err.status`·`err.code`·`err.message`가 서버 값). `FormData`는 `apiFetch`가 `Content-Type`을 붙이지 않으므로 그대로 넘긴다.
- **`saveProgress`의 `opts.keepalive === true` 경로:** `pagehide`에서도 요청이 나가도록 **`await` 없이 같은 호출 안에서 바로 `fetch`** 한다.
  - 토큰: `ULAuth.getSession().access_token` (동기). URL: `((window.ULEVELP_CONFIG && ULEVELP_CONFIG.apiBaseUrl) || '') + '/api/v1/practice/save'`.
  - `fetch(url, { method: 'POST', keepalive: true, headers: { Authorization: 'Bearer ' + token, 'Content-Type': 'application/json; charset=utf-8' }, body })`.
  - 응답 처리는 `auth.js`의 `apiFetch`와 같은 규칙(`res.ok`가 아니면 `data.message` 또는 `'요청 처리에 실패했어요 (' + res.status + ')'`로 `Error`, `err.status`·`err.code` 설정).
- `EXT = { 'audio/mp4': 'm4a', 'audio/webm': 'weba', 'audio/ogg': 'ogg', 'audio/mpeg': 'mp3', 'audio/wav': 'wav', 'audio/aac': 'aac' }`.

### 2.2 `runLocalMigration()` (FR-LOCAL-2)

1. `isLoggedIn()`이 false, `ULAuth.getMe()`가 null, `me.migratedLocalAt`이 null이 아님, 또는 이미 실행 중(모듈 변수 `migrating`) → `skipped` 반환.
2. `own = readLocal('ulp:v:')`, `sister = readLocal('pp:v:')` 중 `own`에 같은 `videoId`가 없는 것.
   - `readLocal(prefix)`: `for (let i = 0; i < localStorage.length; i++) { const k = localStorage.key(i); … }`로 `prefix`로 시작하는 키를 모아, 뒷부분이 `/^[\w-]{11}$/`인 것만, `localStorage.getItem(k)`를 `JSON.parse`(실패한 항목은 건너뜀). 항목 = `{ videoId, pos, a, b, rate, date }` — 숫자 칸은 유한한 숫자일 때만 그 값, 아니면 `null`; `date`는 문자열이면 그 값, 아니면 `null`. `localStorage` 접근 오류는 빈 배열.
3. 둘 다 비었으면 `skipped` (서버 호출 없음, 다음 로드에서 다시 확인).
4. `migrating = true` 후 확인 창(`window.confirm`):
   - `own`이 있으면 `'이 기기에서 연습하던 기록 ' + own.length + '곡을 계정으로 옮길까요?'` → 확인 시 `items`에 추가.
   - `sister`가 있으면 `'같은 기기의 guitar-practice 기록 ' + sister.length + '곡도 가져올까요? (원래 기록은 그대로 남아요)'` → 확인 시 추가.
5. `items`를 `date` 내림차순(null은 뒤)으로 정렬해 앞 100개만.
6. `ULAuth.apiFetch('/api/v1/songs/migrate-local', { method: 'POST', body: JSON.stringify({ items, markMigrated: true }) })` — **둘 다 거절해 `items`가 비어도 호출한다**(다시 묻지 않게).
7. 성공 → `await ULAuth.fetchMe()` → `{ status: 'done', created: r.created, skipped: r.skipped, message: '' }`.
8. 실패 → `{ status: 'failed', created: 0, skipped: 0, message: e.message || '기기 기록을 옮기지 못했어요' }` (`fetchMe` 안 부름).
9. 어느 경우든 끝나면 `migrating = false`. `localStorage`의 `ulp:v:*`·`pp:v:*`는 지우지 않는다.

**시작 부분 (현재 606~617줄을 바꾼다)**

```js
const q = new URLSearchParams(location.search);
const startId = videoIdFrom(q.get('v') || '');
let started = false, lastUid = null;
render();
(async function start() {
  // 저장된 로그인 세션을 먼저 읽는다 (ULAuth.init보다 먼저 실행되므로)
  if (window.ULAuth) await ULAuth.getAccessToken();
  const u = window.ULAuth && ULAuth.getUser();
  lastUid = u ? u.id : null;
  started = true;
  if (startId) {
    const params = (q.has('a') || q.has('b') || q.has('r') || q.has('t'))
      ? { a: num(q.get('a')), b: num(q.get('b')), rate: num(q.get('r')) || 1, t: num(q.get('t')) }
      : null;
    await openSong(startId, { params });
  }
})();
```
(`ULAuth.getAccessToken()`은 내부에서 오류를 처리하고 `''`을 돌려주므로 `try`를 두지 않는다.)

**로그인 상태 변화 (시작 부분 바로 뒤에 추가)**

```js
if (window.ULAuth) ULAuth.onChange((state) => {
  if (!started) return;
  const uid = state.user ? state.user.id : null;
  if (uid !== lastUid) {
    lastUid = uid;
    st.song = null; songsCache = null;
    if (uid && st.videoId) refreshSong();
    render();
  }
  if (state.me && !state.me.migratedLocalAt) runMigration();
});
```
- `refreshSong()`: `const id = st.videoId;` → `D.songs.byVideo(id)` → 응답이 왔을 때 `st.videoId !== id`이거나 이미 `st.song`이 있으면 무시 → 곡이 있으면 `st.song = song; setSync('계정 기록 불러옴')`, 없으면 `setSync('계정에 없는 곡')` → 실패 시 `setSync(e.message, true)` → `render()`. **현재 재생 위치·구간·속도·미저장 시간은 바꾸지 않는다**(다음 저장 때 지금 값이 서버로 감).
- `runMigration()`: `D.runLocalMigration().then((r) => { … })` — `done`이면 `setSync('기기 기록 ' + r.created + '곡을 계정으로 옮겼어요')`, `songsCache = null`, `st.videoId && !st.song`이면 `refreshSong()`; `failed`면 `setSync(r.message, true)`; `skipped`면 아무것도 안 함.

## 5. 처리 순서

1. 페이지 로드: `config.js` → supabase UMD → `auth.js` → `data.js` → `practice.js`.
2. `practice.js` 시작: `ULAuth.getAccessToken()`으로 세션 확인 → `openSong(startId)` — 우선순위 URL 값 > 계정(`byVideo`, 로그인 시) > `ulp:v:` 기기 기록.
3. `ULAuth`가 `/me`를 받아 `notify` → `onChange` → `me.migratedLocalAt == null`이면 `runLocalMigration()`(확인 창) → 완료 시 `ULAuth.fetchMe()`로 `migratedLocalAt`이 채워져 다시 묻지 않음.
4. 재생 중 30초마다·변경 4초 뒤·탭 숨김·`pagehide`에 `save('auto')` — 숨김·`pagehide`는 `keepalive: true`. 기존 `st.saving`/`savePending` 중복 방지 그대로.
5. 녹음 멈춤 → `uploadTake()` → `D.takes.upload` → 실패 시 `다시 올리기`·`파일 저장` 유지(지금 UX 그대로, FR-TAKE-1).

## 9. 금지 사항

- `auth.js`, CSP meta, `settings.js`, `site.js`, 다른 HTML을 고치지 않는다.
- `pp:v:*` 키를 쓰거나 지우지 않는다(읽기만, `data.js`에서만).
- `keepalive` 저장 경로에서 `fetch` 앞에 `await`를 두지 않는다.
- 로그인 상태가 바뀔 때 이전 사용자의 `st.song`·`songsCache`를 남기지 않는다.
- 서버 오류를 삼키지 않는다. `catch`마다 화면 문구(`setSync`/`setRec`)나 반환값으로 남긴다.
- 1절 표에 없는 `ULData` 함수를 만들지 않는다(쓰지 않는 코드 금지).
- 다음 묶음(B0, K2-1)을 이어서 하지 않는다.
