## 2. 시그니처

### 2.1 `NotionPushWorker.pushNoteUpsert` (`src/main/kotlin/ulevelp/notion/NotionPushWorker.kt`)

```kotlin
private suspend fun pushNoteUpsert(
    userId: UUID,
    noteId: UUID,
    notion: DecryptedNotionIntegration,
    workerId: String? = null
): String?
```
- **동작 규칙:**
  1. `val notesDb = notion.notesDb?.takeIf { it.isNotBlank() } ?: return null` (`notesDb`가 미설정이면 에러 없이 건너뛰고 outbox `done_at` 처리).
  2. `NotesTable`에서 `(id eq noteId) and (userId eq userId)` 조회(삭제되어 없으면 `return null`).
  3. `NotionLinksTable`에서 `("note", noteId)` 조회:
     - **이미 링크(`existingPageId`)가 존재할 때 (메모·태그·제목 수정):**
       - `NotionNoteBlockBuilder.buildPageProperties(...)`로 8개 속성을 만들어 `notionClient.updatePage(notion.token, existingPageId, buildJsonObject { put("properties", properties) })` 호출 후 `NotionLinksTable.syncedAt` 갱신.
     - **링크가 없을 때 (신규 노트 노션 발행):**
       - `diagramsSvg` JSON 배열의 각 SVG 문자열(인덱스 `idx`)에 대해: 비어 있지 않으면 `try { notionClient.uploadFile(notion.token, "voicing_${idx + 1}.svg", "image/svg+xml", svg.toByteArray(Charsets.UTF_8)) } catch (e: CancellationException) { throw e } catch (e: Exception) { log.warn(...); null }`로 업로드해 `harmonyUploadIds: List<String?>`를 준비한다(SVG 업로드가 실패해도 노트 페이지 생성은 계속 진행 — `scripts/analyze.py:319`와 동일).
       - `val blocks = NotionNoteBlockBuilder.buildBlocks(url, tags, analysisObj, harmonyUploadIds)`
       - 첫 100개 블록(`blocks.take(100)`)과 `properties`로 `notionClient.createPage` 호출:
         `{ "parent": { "database_id": notesDb }, "properties": properties, "children": blocks.take(100) }`.
       - 생성된 `pageId`를 즉시 짧은 트랜잭션으로 `NotionLinksTable`에 `("note", noteId, userId, pageId)`로 INSERT(멱등성 보장).
       - `blocks.size > 100`이면 `for (i in 100 until blocks.size step 100)` 루프에서 lease를 연장하고 `notionClient.appendBlockChildren(notion.token, pageId, JsonArray(blocks.subList(i, minOf(i + 100, blocks.size))))`를 호출한다.

### 2.2 `public/data.js` 추가 시그니처 (`window.ULData.notes`)

모든 함수는 `async` 함수이며 첫 줄에서 `requireLogin()`을 호출한다(비로그인 시 동기 throw가 아닌 Promise reject 반환):

| 이름 | 인자 | 요청 | 반환(Promise) |
| --- | --- | --- | --- |
| `notes.analyze(input)` | `{ url, tags, memo }` | `POST /api/v1/notes/analyze` | `{ jobId, status }` |
| `notes.listJobs()` | 없음 | `GET /api/v1/notes/jobs` | `Array<AnalysisJobDto>` (`r.jobs \|\| []`) |
| `notes.getJob(jobId)` | `jobId` | `GET /api/v1/notes/jobs/{jobId}` | `AnalysisJobDto` |
| `notes.list(tag)` | `tag` (선택) | `GET /api/v1/notes` (`?tag=...`) | `Array<NoteSummaryDto>` (`r.notes \|\| []`) |
| `notes.get(noteId)` | `noteId` | `GET /api/v1/notes/{noteId}` | `NoteDetailDto` (`r.note \|\| null`) |
| `notes.update(noteId, patch)` | `noteId, { memo, tags, title }` | `PATCH /api/v1/notes/{noteId}` | `NoteDetailDto` (`r.note \|\| null`) |
| `notes.remove(noteId)` | `noteId` | `DELETE /api/v1/notes/{noteId}` | `{ ok: true }` |

- **키 무효화 연동 (`FR-KEY-5` — 요청 시점 + 비동기 잡 폴링 시점 모두 처리):**
  1. `notes.analyze` 호출이 `err.code === 'NO_KEY'`(412)로 실패하면 `clearCachedGeminiKey()`를 호출해 `localStorage`의 `ulp:keys`에서 `gemini: null`로 갱신한다.
  2. Gemini API 호출은 비동기 `executeJob`에서 수행되므로 키가 거부(400/401/403)된 경우 `analysis_jobs` 행이 `status === 'failed'` 및 `error`가 `'PROVIDER_KEY_INVALID:'`로 시작하는 문자열로 기록된다(`K5-1` 2.4절). 따라서 **`notes.listJobs()`와 `notes.getJob(jobId)`가 응답을 반환할 때** `status === 'failed' && typeof job.error === 'string' && job.error.startsWith('PROVIDER_KEY_INVALID:')`인 작업이 있으면 즉시 `clearCachedGeminiKey()`를 호출해 `ulp:keys`의 `gemini`를 `null`로 무효화한다.

1. **쿼리 파라미터:** `new URLSearchParams(location.search).get('id')`. `id`가 없으면 `"노트 ID가 없어요."` 안내 표시.
2. **화면 섹션 구성 (`FR-NOTE-3`):**
   - 상단 네비게이션(`.site-nav`) + `← 학습 노트 목록`(`notes.html`)
   - 헤더 패널(`#noteHeader`): 제목(`#noteTitle`), 채널·모델·날짜(`#noteMeta`), 난이도 배지(`#noteDifficulty`), 태그 목록(`#noteTags`), 액션 버튼(`<a id="notePracticeLink" class="cta">▶ 플레이어에서 연습</a>`, `<a id="noteYoutubeLink" class="sec" target="_blank" rel="noopener">유튜브 원본 ↗</a>`, `<button id="btnDeleteNote" class="ghost">노트 삭제</button>`).
   - 핵심 요약 콜아웃(`#noteSummaryBox`): 한 줄 요약(`#noteHeadline`), 핵심 포인트 트리(`#notePoints`), 핵심 키워드 칩(`#noteKeywords`).
   - 태그별 상세 섹션(`#noteSections`):
     - **화성 (`harmony`):** 각 진행(`progressions[idx]`)마다 소제목(`name (key) · instrument`), 코드 진행 화살표(`symbol → symbol`), 7열 표(`코드, 로마숫자, 기능, 보이싱, 뉘앙스, 근거, 시간`), 그리고 `note.diagramsSvg[idx]`가 비어 있지 않으면 `<div class="scroll svg-box"></div>` 안에 아래 **`renderSanitizedSvg`**로 지판/건반 SVG를 렌더링한다. 하단에 `concepts` 용어 목록.
     - **사운드 디자인 (`sound_design`):** 각 패치(`target · instrument`)별 5열 표(`단계, 설정, 효과, 근거, 시간`).
     - **DAW/MIDI (`daw`):** 사용 DAW 문구, 4열 표(`작업, 방법, 단축키, 시간`), 팁 목록.
     - **리듬 (`rhythm`):** 각 패턴(`name (time_signature)`)별 16분 그리드 `<pre class="mono-grid">`, 그루브 설명(`feel`), 근거·시간, `concepts` 용어 목록.
     - **편곡 (`arrangement`):** 5열 표(`구간, 마디, 악기, 기법·의도, 시간`), `techniques` 용어 목록.
     - **믹싱 (`mixing`):** 6열 표(`트랙, 프로세서, 설정, 목적, 근거, 시간`), 팁 목록.
   - **타임스탬프 링크 규칙:** 모든 표의 `시간` 열과 `주요 구간`(`#noteMoments`)의 타임스탬프 문자열(`mm:ss` 또는 `h:mm:ss`)은 `parseTimestampSec(ts)`로 초(`sec`)를 계산해 유효하면 `<a href="practice.html?v=${encodeURIComponent(note.videoId)}&t=${sec}">` 링크로 만들고, 파싱할 수 없으면 일반 텍스트로 표시한다.
   - **주요 구간 (`#noteMoments`) & 연습 과제 체크리스트 (`#notePractice`):**
     - `practice` 배열의 각 항목은 `<label class="check"><input type="checkbox"><span>...</span></label>`로 렌더링한다.
   - **메모·태그 편집 패널 (`#noteEditPanel`):**
     - 태그 토글 버튼 7개(`화성`, `사운드 디자인`, `DAW/MIDI`, `리듬`, `편곡`, `믹싱`, `TAB`) + 메모 `<textarea id="noteMemoInput">` + `<button id="btnSaveNote" class="sec">메모·태그 저장</button>` + 상태 메시지 `#noteEditMsg`.
3. **안전한 SVG DOM 렌더링 (`renderSanitizedSvg(container, svgText)`):**
   - `innerHTML`을 쓰지 않고 `new DOMParser().parseFromString(svgText, 'image/svg+xml')`로 파싱한 뒤, 허용된 7개 SVG 태그(`svg`, `g`, `rect`, `line`, `path`, `circle`, `text`)와 허용된 22개 속성(`xmlns`, `width`, `height`, `viewBox`, `font-family`, `transform`, `fill`, `stroke`, `stroke-width`, `x`, `y`, `x1`, `y1`, `x2`, `y2`, `cx`, `cy`, `r`, `d`, `font-size`, `font-weight`, `text-anchor`)만 `document.createElementNS('http://www.w3.org/2000/svg', tagName)`와 `el.setAttribute(attrName, attrVal)`로 복제해 `container`에 추가한다(`text` 노드는 `el.textContent`만 복사).
   - 이렇게 하면 `test/security.test.js`의 (a)·(c)·(d) 규칙을 100% 통과하고, 설령 `diagramsSvg`에 `<svg onload="window.__xss=1">`나 `<script>`가 주입되어도 원천 차단된다.

### 2.5 CSP 및 `test/security.test.js` 정리

- `test/security.test.js`의 `CSP` 상수에서 `https://api.github.com`을 제거하여 `connect-src`를 아래와 같이 맞춘다:
  ```js
  "connect-src 'self' https://vefrfhafmiiivpgjhqiu.supabase.co",
  ```
- 모든 `public/*.html` 8개 파일(`index.html`, `chords.html`, `practice.html`, `log.html`, `notes.html`, `note.html`, `settings.html`, `privacy.html`)의 `<meta http-equiv="Content-Security-Policy">`를 위 `CSP`와 글자 하나까지 똑같이 맞춘다.
- `test/security.test.js`의 `STORAGE_LEGACY`에서 `sn-token`과 `sn-repo` 2개 항목을 제거한다.
- `test/security.test.js`의 `HTML_ALLOW`에서 `{ file: 'public/notes.js', kind: 'html', expr: /^(?:cls|label)$/, ... }` 항목을 제거한다(`notes.js`를 DOM API로 작성하므로 미사용 항목이 되어 남겨 두면 `stale` 검사가 실패함).

## 4. 검증·에러 표

백엔드 에러 응답은 `K5-1_구현명세.md` 4절과 동일하며, 프런트엔드는:

- `429 RATE_LIMITED` 수신 시 서버가 내려준 `err.message`를 `#msg`에 `.err`로 표시한다.
