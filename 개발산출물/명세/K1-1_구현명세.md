## 2. 시그니처

### 2.1 `api/JsonInput.kt` (package `ulevelp.api`)

`MeRoutes.kt`의 `parseJsonObjectBody`를 **그대로 옮겨** 이름만 바꾼다(메시지 3개 동일). 나머지는 새로 만든다. 모든 오류는 `InvalidInputException(message)` → `400 INVALID_INPUT`.

```kotlin
suspend fun ApplicationCall.receiveJsonObject(): JsonObject

fun JsonObject.requireString(name: String, maxLength: Int): String      // trim 후 반환(빈 문자열 허용)
fun JsonObject.optString(name: String, maxLength: Int): String?         // 키 없음·null → null
fun JsonObject.requireUuid(name: String): UUID
fun JsonObject.requireDate(name: String): LocalDate                     // 형식 + 범위(아래)
fun JsonObject.requireDouble(name: String, min: Double, max: Double): Double
fun JsonObject.optDouble(name: String, min: Double, max: Double): Double?
fun JsonObject.optInt(name: String, min: Int, max: Int, default: Int): Int
fun JsonObject.optBoolean(name: String, default: Boolean): Boolean
fun JsonObject.requireArray(name: String, maxSize: Int): JsonArray
fun parsePathUuid(raw: String?): UUID                                   // 경로 변수용. 틀리면 404
```

| 헬퍼 | 키 없음 / JSON `null` | 타입 틀림 | 범위·길이 틀림 |
| --- | --- | --- | --- |
| `requireString` | `"$name 값이 필요합니다."` | 문자열 아님 → `"$name 형식이 올바르지 않습니다."` | trim 후 길이 > `maxLength` → `"$name은(는) ${maxLength}자 이하여야 합니다."` |
| `optString` | `null` 반환 | 위와 같음 | 위와 같음 |
| `requireUuid` | 필요 메시지 | 문자열 아님 또는 정규식 `^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$` 불일치 → 형식 메시지 | — |
| `requireDate` | 필요 메시지 | 문자열 아님, `^\d{4}-\d{2}-\d{2}$` 불일치, `LocalDate.parse` 실패 → 형식 메시지 | `2000-01-01` 미만 또는 `LocalDate.now(ZoneOffset.UTC).plusDays(1)` 초과 → `"$name은(는) 2000-01-01부터 내일(UTC)까지만 쓸 수 있습니다."` |
| `requireDouble` | 필요 메시지 | `JsonPrimitive`가 아니거나 `isString == true`이거나 `doubleOrNull == null` → 형식 메시지 | `< min` 또는 `> max` → `"$name은(는) $min~$max 범위여야 합니다."` |
| `optDouble` | `null` 반환 | 위와 같음 | 위와 같음 |
| `optInt` | `default` 반환 | `isString == true` 또는 `content.toLongOrNull() == null`(소수 `30.5` 포함) → 형식 메시지 | 위 범위 메시지 |
| `optBoolean` | `default` 반환 | `isString == true` 또는 `booleanOrNull == null` → 형식 메시지 | — |
| `requireArray` | 필요 메시지 | `JsonArray` 아님 → 형식 메시지 | 크기 > `maxSize` → `"$name은(는) 최대 ${maxSize}개까지 보낼 수 있습니다."` |
| `parsePathUuid` | `null` → `NotFoundException()` | UUID 정규식 불일치 → `NotFoundException()` (기본 메시지) | — |

### 2.2 `db/OutboxRepository.kt` (package `ulevelp.db`)

```kotlin
object OutboxRepository {
    /** 반드시 DatabaseFactory.dbQuery { } 트랜잭션 안에서 부른다. */
    fun enqueueIfSyncEnabled(userId: UUID, entity: String, entityId: UUID, op: String)
}
```
- 처리(Exposed DSL, raw SQL 금지):
  1. `NotionSyncTable`에서 `userId eq userId and enabled eq true` 행이 없으면 끝.
  2. `op == "upsert"`이고 `SyncOutboxTable`에 `(userId, entity, entityId, op = 'upsert', doneAt IS NULL)` 행이 있으면 끝(중복 방지).
  3. `SyncOutboxTable.insert { userId, entity, entityId, op }`.
- `op == "delete"`는 대기 중인 `upsert`가 있어도 **항상** 넣는다(04 3.3절 A0 수정분).
- `entity` 값: `"song"`, `"session"`, `"take"`, `"note"`. `op` 값: `"upsert"`, `"delete"`. 다른 값은 넘기지 않는다(DB CHECK).

### 2.3 `service/VideoMetaClient.kt` (package `ulevelp.service`)

```kotlin
data class VideoMeta(val title: String, val author: String)

interface VideoMetaClient {
    /** 실패(네트워크·비 200·파싱·빈 제목)는 null. 예외를 던지지 않는다(CancellationException 제외). */
    suspend fun fetch(videoId: String): VideoMeta?
}

class YoutubeOEmbedClient(
    private val endpoint: URI = URI("https://www.youtube.com/oembed"),
    private val timeout: Duration = Duration.ofSeconds(3),
    private val httpClient: HttpClient = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(3)).build()
) : VideoMetaClient
```
- 요청: `GET $endpoint?format=json&url=` + `URLEncoder.encode("https://www.youtube.com/watch?v=$videoId", UTF_8)`, 헤더 `Accept: application/json`, `HttpRequest.timeout(timeout)`. 호출은 `withContext(Dispatchers.IO)` 안에서(`SupabaseJwtVerifier.kt`의 `HttpJwksProvider`처럼).
- 응답 200이면 JSON 객체의 `title`(trim, 앞 300자), `author_name`(trim, 앞 200자, 없으면 `""`). `title`이 비면 `null`.
- 그 밖(비 200, `IOException`, `HttpTimeoutException`, JSON 오류)은 `org.slf4j.LoggerFactory` 로거로 `warn("oEmbed 조회 실패 videoId={}: {}", videoId, 원인)` 후 `null`. `catch (e: CancellationException) { throw e }`를 먼저 둔다.

### 3.2 요청 본문

**`POST /api/v1/songs`**

| 필드 | 타입 | 필수 | 규칙 | 예시 |
| --- | --- | --- | --- | --- |
| `videoId` | String | 예 | `VIDEO_ID_REGEX` | `"dQw4w9WgXcQ"` |
| `title` | String | 아니오 | `optString(…, 300)`, 없음·null → `""` | `""` |
| `artist` | String | 아니오 | `optString(…, 200)`, 없음·null → `""` | `""` |
| `rate` | Number | 아니오 | `optDouble(0.25, 2.0)`, 없음·null → `1.00` | `1.0` |

**`PATCH /api/v1/songs/{songId}`** — 아래 셋 중 하나 이상(키가 있고 null 아님) 필요.

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `status` | String | `normalizeStatus` 결과가 null이면 400. 코드·한글 둘 다 허용 |
| `memo` | String | `optString(…, 2000)` (빈 문자열 허용 = 메모 지우기) |
| `title` | String | `optString(…, 300)`, trim 후 빈 문자열이면 400 |

**`POST /api/v1/songs/migrate-local`**

| 필드 | 타입 | 필수 | 규칙 |
| --- | --- | --- | --- |
| `items` | Array | 예 | `requireArray("items", 100)`. 항목은 `parseLocalItem`로 느슨하게 읽는다(6.1 S9) |
| `markMigrated` | Boolean | 아니오 | `optBoolean(…, false)` |

`parseLocalItem` 규칙(항목 하나라도 틀려도 요청 전체를 거부하지 않는다):
- `JsonObject`가 아니거나 `videoId`가 `VIDEO_ID_REGEX`에 안 맞으면 → `null`(= skipped).
- `pos`·`a`·`b`: 숫자이고 `0.0..86400.0`이면 소수 1자리 반올림, 아니면 `null`. 둘 다 있고 `a >= b`이면 `a = b = null`.
- `rate`: 숫자이고 `0.25..2.0`이면 소수 2자리, 아니면 `1.00`.
- `date`: `YYYY-MM-DD`이고 `2000-01-01..today+1`이면 그 날짜, 아니면 `null`.

**`POST /api/v1/practice/save`**

| 필드 | 타입 | 필수 | 규칙 | 단위·예시 |
| --- | --- | --- | --- | --- |
| `songId` | String | 예 | `requireUuid` | |
| `pos` | Number | 예 | `requireDouble(0.0, 86400.0)` → 소수 1자리 | 초, `45.0` |
| `a` | Number | 아니오 | `optDouble(0.0, 86400.0)` → 소수 1자리. **키 없음·null이면 DB를 null로 쓴다(구간 지움)** | 초, `38.0` |
| `b` | Number | 아니오 | `a`와 같음. 반올림 뒤 둘 다 있고 `a >= b`면 400 | 초, `55.2` |
| `rate` | Number | 아니오 | `optDouble(0.25, 2.0)` → 소수 2자리. null이면 기존 값 유지 | 배속, `0.75` |
| `date` | String | 예 | `requireDate` (사용자 기기 현지 날짜, FR-SESSION-3) | `"2026-10-30"` |
| `addSeconds` | Integer | 아니오 | `optInt(0, 21600, 0)` | 초, `30` |
| `addLoops` | Integer | 아니오 | `optInt(0, 100000, 0)` | 회, `2` |

그 밖의 키(`videoId`, `title`, `resumeUrl` 등)는 무시한다.

### 3.3 `resumeUrl` 규칙 (`public/practice.js`의 `resumeUrl()`과 같은 결과)

`publicAppUrl + "practice.html?" + 파라미터`. 파라미터 순서 `v`, `t`, `a`, `b`, `r`.
- `v` = videoId.
- `t` = `pos ?: a`가 null이 아니고 0이 아니면 `floor(값)`을 정수 문자열로. (`42.5` → `42`, `0.5` → `0`, `0.0` → 생략)
- `a`·`b` = null이 아니면 `stripTrailingZeros().toPlainString()` (`38.0` → `38`, `55.2` → `55.2`).
- `r` = `rate`가 `1`과 다르면(`compareTo(BigDecimal.ONE) != 0`) 같은 방식 (`0.75` → `0.75`).

예: `pos=42.5, a=38.0, b=55.2, rate=0.75` → `…/practice.html?v=dQw4w9WgXcQ&t=42&a=38&b=55.2&r=0.75`. `pos=null, a=null, b=null, rate=1.00` → `…/practice.html?v=dQw4w9WgXcQ`.

## 5. 처리 순서·트랜잭션 경계

### 5.1 `list(userId, statusCode)`
1. 트랜잭션 1개: `SongsTable`에서 `userId eq userId` (+ `statusCode`가 있으면 `status eq statusCode`) 전체 행.
2. 같은 트랜잭션: `SessionsTable.select(songId, seconds.sum()).where { userId eq userId }.groupBy(songId)` → `songId → 합계` 맵.
3. 정렬은 Kotlin에서: 상태 순위(`practicing` 0, `paused` 1, `done` 2) 오름차순 → `lastDate` 내림차순(null은 맨 뒤) → `updatedAt` 내림차순.

### 5.2 `findByVideo(userId, videoId)`
트랜잭션 1개: `(userId, videoId)` 1행 + 그 곡 합계. 없으면 `null`.

### 5.3 `create(userId, input)`
1. 트랜잭션 A: `(userId, videoId)` 곡이 있으면 `CreateSongResult(dto, created = false)` 반환하고 끝(oEmbed 호출 안 함).
2. 트랜잭션 밖: `input.title`이 빈 문자열이면 `meta = videoMetaClient.fetch(videoId)`. `title = meta?.title ?: UNTITLED`, `artist = input.artist.ifEmpty { meta?.author ?: "" }`. `input.title`이 있으면 oEmbed를 부르지 않고 `title = input.title`, `artist = input.artist`.
3. 트랜잭션 B: `newId = UUID.randomUUID()`; `SongsTable.insertIgnore { id, userId, title, artist, videoId, rate }`.
   - `insertedCount == 1` → `OutboxRepository.enqueueIfSyncEnabled(userId, "song", newId, "upsert")` → `created = true`.
   - `insertedCount == 0`(동시에 다른 요청이 만듦) → 기존 곡을 읽어 `created = false`.
4. 라우트: `created`면 `201`, 아니면 `200`.

### 5.4 `update(userId, songId, input)`
트랜잭션 1개: `SongsTable.update({ (id eq songId) and (userId eq userId) }) { 받은 필드만 }` → 0행이면 `NotFoundException("곡을 찾을 수 없습니다.")` → `enqueueIfSyncEnabled(userId, "song", songId, "upsert")` → DTO 반환. (`updated_at`은 DB 트리거가 갱신)

### 5.5 `delete(userId, songId)` (04 3.2.1절)
트랜잭션 1개:
1. `(id, userId)` 곡이 없으면 `NotFoundException("곡을 찾을 수 없습니다.")`.
2. `TakesTable`에서 `userId, songId, storage = 'supabase'`인 `storageKey`마다 `StorageTrashTable.insert { storageKey } get StorageTrashTable.id` → id 목록.
3. `enqueueIfSyncEnabled(userId, "song", songId, "delete")`, 그 곡 세션 id마다 `enqueueIfSyncEnabled(userId, "session", sessionId, "delete")`.
4. `SongsTable.deleteWhere { (id eq songId) and (userId eq userId) }` (sessions·takes는 CASCADE).
5. 2번 id 목록 반환. K1-1 라우트는 반환값을 쓰지 않고 `{ "ok": true }`.

### 5.6 `migrateLocal(userId, items, invalidCount, markMigrated)`
라우트가 `requireArray` → 항목마다 `parseLocalItem` → null 개수를 `invalidCount`로, null이 아닌 것을 `items`로 넘긴다.
1. `items`에서 같은 `videoId`는 **처음 것만** 남긴다 → 버린 개수 `dupCount`.
2. 트랜잭션 A: 그 videoId 중 이미 내 곡인 것 → 제외, 개수 `existingCount`.
3. 트랜잭션 밖: 남은 항목마다 `videoMetaClient.fetch` — `coroutineScope { val sem = Semaphore(8); map { async { sem.withPermit { … } } }.awaitAll() }`.
4. 트랜잭션 B: 항목마다 `insertIgnore { id = UUID.randomUUID(), userId, title = meta?.title ?: UNTITLED, artist = meta?.author ?: "", videoId, pos, a, b, rate, lastDate = date }` → `insertedCount == 1`이면 `created++` + `enqueueIfSyncEnabled(…, "song", id, "upsert")`, 0이면 `conflictCount++`. `markMigrated`면 `ProfilesTable.update({ id eq userId }) { migratedLocalAt = OffsetDateTime.now(ZoneOffset.UTC) }`. 마지막에 `profiles.migrated_local_at` 읽기.
5. `skipped = invalidCount + dupCount + existingCount + conflictCount`.

### 5.7 `saveProgress(userId, input)` (04 3.1절 — 트랜잭션 1개)
1. `SongsTable.select(SongsTable.lastDate).where { (id eq songId) and (userId eq userId) }.forUpdate(ForUpdateOption.ForUpdate).singleOrNull()` → 없으면 `NotFoundException("곡을 찾을 수 없습니다.")`. (`import org.jetbrains.exposed.sql.vendors.ForUpdateOption`. 이 잠금으로 같은 곡 저장은 차례로 처리된다)
2. `newLast = maxOf(기존 lastDate ?: date, date)`. `SongsTable.update(같은 조건) { pos = input.pos; a = input.a; b = input.b; if (input.rate != null) rate = input.rate; lastDate = newLast }`.
3. `addSeconds == 0 && addLoops == 0` → `enqueueIfSyncEnabled(…, "song", songId, "upsert")` → 3.4 첫 줄 응답.
4. 합산 시도: `SessionsTable.update({ (userId eq userId) and (songId eq songId) and (date eq input.date) }) { it.update(seconds) { seconds + input.addSeconds }; it.update(loops) { loops + input.addLoops }; if (input.rate != null) it[rate] = input.rate; it[a] = input.a; it[b] = input.b }`.
5. 4번이 0행이면:
   - `addSeconds < MIN_NEW_SESSION_SECONDS` → `enqueueIfSyncEnabled(…, "song", …)` → `keep = true` 응답(세션 INSERT 없음).
   - 아니면 `SessionsTable.insertIgnore { id = UUID.randomUUID(), userId, songId, date, seconds = addSeconds, loops = addLoops, rate = input.rate, a, b }`. `insertedCount == 0`이면 4번 UPDATE를 한 번 더 실행.
6. `(userId, songId, date)` 세션의 `id`, `seconds` 읽기.
7. `enqueueIfSyncEnabled(…, "song", songId, "upsert")`, `enqueueIfSyncEnabled(…, "session", sessionId, "upsert")`.
8. 3.4 셋째 줄 응답.

외부 호출(oEmbed)은 5.3·5.6의 "트랜잭션 밖" 단계에서만 한다.

## 9. 금지 사항

- 3절 표에 없는 응답 필드·요청 필드·엔드포인트(`GET /songs/{id}` 포함)를 만들지 않는다.
- 조건별 상태 코드를 바꾸지 않는다(`POST /songs`는 새로 만들 때만 201).
- oEmbed 호출을 `dbQuery { }` 안에 넣지 않는다. raw SQL(`exec`)을 쓰지 않는다.
- 남의 곡 접근을 403으로 응답하지 않는다(항상 404 `NOT_FOUND`). 쿼리마다 `userId` 조건을 넣는다.
- `catch`에서 예외를 삼키고 빈 값·`null`을 돌려주지 않는다. 예외는 `VideoMetaClient.fetch`(로그 후 null)만.
- `ktor`의 `call.receive<T>()`로 DTO를 받지 않는다(역직렬화 오류가 500이 됨). `receiveJsonObject()` + 헬퍼를 쓴다.
- `/api/*` 계산 API, `AuthAndProfileApiTest.kt`, `Tables.kt`, `V1__init.sql`, `build.gradle.kts`를 고치지 않는다.
- 실패하는 테스트의 단언을 완화하거나 `@Disabled`로 건너뛰지 않는다.
- K1-2 이후 step을 이어서 하지 않는다.
