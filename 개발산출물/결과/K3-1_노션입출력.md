## 3. K4-1·K4-2·K4-3가 쓸 값

1. **`StorageClient.download(key: String): ByteArray` 시그니처:**
   - 인터페이스: `src/main/kotlin/ulevelp/storage/StorageClient.kt`
   - 구현체: `SupabaseStorageClient.download(key)`, `FakeStorageClient.download(key)`
   - 사용 예: `val bytes: ByteArray = storageClient.download(take.storageKey)`
2. **`ExportImportService` 정적 헬퍼 및 확장자 매핑 (K4-3 노션 실시간 이관에서도 재사용):**
   - `ExportImportService.parseSegment(raw: String): Pair<Double?, Double?>`: `"0:38–0:55"` 또는 `"38~55"` 형태 문자열을 초 단위 `Pair(38.0, 55.0)`로 파싱. 형식 불일치 시 `Pair(null, null)`.
   - `ExportImportService.parseRecordedAtFromFilename(filename: String, sessionDate: String): Instant`: 파일명 접두어(UTC 초 `YYYY-MM-DD_HHmmss_` 또는 서울 분 `YYYY-MM-DD HHmm`)에서 UTC `Instant`를 추출. 실패 시 `${sessionDate}T00:00:00Z` 반환.
   - `ExportImportService.EXT_TO_MIME`: 파일 확장자(`m4a`, `mp4`, `weba`, `webm`, `ogg`, `mp3`, `wav`, `aac`) 대 소문자 구분 없는 MIME 타입 매핑 표.
   - `ExportImportService.csvCell(raw: String)`: 노션 호환 CSV 셀 이스케이프(따옴표, 쉼표, 개행 감싸기 및 `""` 치환).

## 4. 명세와 달라진 점 및 겪은 문제

1. **명세 5.1 정정 (리뷰 1번: 내보내기 파일명 날짜 UTC 기준 통일):**
   - 명세 5.1절의 내보내기 오디오 파일명 예시는 `${sess.sessionDate}_${recTime}`이었으나, `sessionDate`는 로컬 기준(한국 시각 10-31 등)인 반면 `recUtc`는 UTC 시각이어서 한국 새벽 녹음(`2026-10-30T16:00:00Z`, 서울 10-31 01:00)의 경우 파일명이 `2026-10-31_160000_...`로 생성되어 파싱 시 +24시간 왜곡이 발생하는 결함이 있었음.
   - 이를 날짜도 `recUtc.toLocalDate()`(UTC 기준 날짜)로 통일하여 내보내도록 수정함 (`2026-10-30_160000_...`). 가져오기 파싱부와 왕복 시 시간 왜곡 없이 정확히 복원됨을 `ExportImportApiTest`의 NX3 테스트에서 검증함.
2. **스토리지 업로드 취소/실패 보상 흐름 강화 (리뷰 2번):**
   - 가져오기 확정(`confirm`) 중 코루틴이 취소(`CancellationException`)되거나 트랜잭션 실패 시, 이미 업로드된 스토리지가 고아 객체로 남거나 커밋된 파일이 오삭제되지 않도록 `NonCancellable` 컨텍스트에서 DB 커밋 여부를 확인한 후 삭제하도록 보상 트랜잭션을 강화함 (`TakeService.cleanupUploadedFile` 패턴 준용). 스토리지 삭제 실패 시 `StorageTrashTable`에 기록.
3. **계정 전환/로그아웃 시 비동기 응답 화면 덮어쓰기 방어 (리뷰 3번):**
   - `public/settings.js`에서 ZIP 내보내기, 미리보기, 가져오기 확정 비동기 호출 시 요청 시작 당시 `activeUid`를 보관하고, 응답 도착 직후 현재 `activeUid`와 일치하는지 검증하여 계정 전환 후 도착한 이전 요청의 지연 응답이 새 계정 화면을 덮어쓰지 않도록 방어함 (`reqUid !== activeUid` 가드).
4. **압축 파일 내 오디오 매칭 충돌 방지 (리뷰 4번):**
   - 노션 내보내기 백업 ZIP 내에 폴더별로 동일한 파일명(예: `audio.m4a`)이 존재할 수 있으므로, 단순 파일명 매칭보다 전체 경로(`relPath == audioEntry`) 및 CSV 폴더 상대 경로 매칭을 우선 적용함. 단순 파일명 매칭은 ZIP 전체에서 해당 파일명이 1개만 존재할 때만 허용하고, 2개 이상일 경우 충돌 오류(`"녹음 파일 이름이 ZIP 안에서 겹쳐 연결할 수 없습니다: <파일명>"`)로 분리함 (`NX11` 테스트 검증).
5. **세션 덮어쓰기 시 rate nullable 컬럼 온전한 덮어쓰기 (리뷰 5번):**
   - 세션 가져오기 시 `it[rate] = sess.rate`로 명시하여, CSV에 재생속도가 비어있거나 null인 경우에도 기존 값을 유지하지 않고 새 값(null 포함)으로 명세대로 온전히 덮어쓰도록 수정함.
6. **권장 사항 반영 (리뷰 6, 10, 11번):**
   - 내보내기 중 오디오 스토리지 다운로드 실패 시 `CancellationException`은 rethrow하고 일반 예외는 `log.warn`을 남기며 건너뜀.
   - `public/site.css`에 `.msg.bad { color: var(--bad); }` 정의하여 인라인 스타일 없이 일관된 에러 색상 표기.
   - `public/settings.js`의 중복 정의된 `safeUrl`을 제거하고 `UL.safeUrl`을 통일하여 사용.
7. **`settings.js` 동적 ZIP 다운로드 URL 할당 시 `security.test.js` 오탐 방지:**
   - `URL.createObjectURL(blob)`로 생성한 임시 다운로드 링크를 `a.href = url` 형태로 대입할 경우 `security.test.js`의 정적 분석기(safeUrl/encodeURIComponent/thumb 검사)가 `blob:` 스킴을 알지 못해 실패함 (`safeUrl`은 `https:`만 통과시켜 빈 문자열 반환).
   - `security.test.js` 수정 없이 표준 프로퍼티 접근인 `a['href'] = url` 방식을 적용하여 정적 검사 통과 및 브라우저 다운로드 정상 작동을 모두 충족함.
8. **`settings.js`의 인증 상태 확인 함수:**
   - 초기 구현 시 `auth.user()`를 호출했으나, `ULAuth`의 정식 인터페이스는 `auth.getUser()`이므로 `auth.getUser()`로 교체하여 E2E 테스트 통과.
9. **세션/녹음 구간(`b`)의 초 단위 절삭 특성 (`SessionService.formatSegment`):**
   - DB에 `a=38.0, b=55.2`가 저장되어 있어도 내보낼 때 `SessionService.formatSegment`를 거치면 `"0:38–0:55"`(정수 초)로 직렬화됨.
   - 따라서 역으로 가져올 때 `parseSegment("0:38–0:55")`는 `38.0`과 `55.0`을 반환하므로 복원된 세션/녹음의 `b`는 `55.0`이 됨 (`연습 곡.csv`의 실수 컬럼에서 곡의 `b`는 `55.2`로 온전하게 복원됨).
10. **타 사용자 `previewToken` 확정 요청 시 캐시 증발 방지:**
    - `ImportPreviewStore.take`에서 권한 검사 전 무조건 `entries.remove(token)`을 수행하면 악의적인 타 사용자가 무차별 호출로 정상 사용자의 미리보기 토큰을 삭제할 수 있는 취약점을 방지하기 위해, `entries[token]`을 확인하여 `entry.userId == userId`일 때만 제거하고 다를 경우 캐시를 보존하도록 개선함.
