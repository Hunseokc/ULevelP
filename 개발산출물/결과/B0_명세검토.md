## 2. 이번 묶음에서 새로 정한 메뉴얼 항목 (사용자 확인 2026-10-31, 기본안 확정)

### 2.1 백엔드 API (`K2-1`, `K2-2`)
- **`GET /api/v1/sessions` (K2-1):**
  - 쿼리 파라미터: `from`(`YYYY-MM-DD`, 선택), `to`(`YYYY-MM-DD`, 선택), `today`(`YYYY-MM-DD`, 선택 — 생략 시 `LocalDate.now(ZoneOffset.UTC)`).
  - 기본 범위: `to` 생략 시 `today`, `from` 생략 시 `to.minusDays(83)` (총 84일 = 12주).
  - 검증: 날짜 형식·범위(`2000-01-01` ~ `내일(UTC)`) 오류, `from > to`, 또는 `ChronoUnit.DAYS.between(from, to) > 365`(최대 366일 초과)이면 `400 INVALID_INPUT`.
  - 응답(`SessionListResponse`):
    - `summary`: `{ "thisWeekSeconds": Long, "thisMonthSeconds": Long }` — `from`/`to` 필터와 무관하게 `today` 기준 이번 주(월요일 `today.with(TemporalAdjusters.previousOrSame(DayOfWeek.MONDAY))` ~ 일요일 `...+6일`) 및 이번 달(`today.withDayOfMonth(1)` ~ `today.with(TemporalAdjusters.lastDayOfMonth())`)의 사용자 전체 세션 `seconds` 합계.
    - `calendar`: `List<CalendarDayDto>` — `[from, to]` 범위 내 `totalSeconds > 0`인 날짜만 `date` 오름차순으로 반환. 각 항목은 `{ "date": "YYYY-MM-DD", "totalSeconds": Long, "level": Int }`.
    - `level` 4단계 규칙(`FR-LOG-1`): `1..899`초(15분 미만) → `1`, `900..1799`초(15~30분 미만) → `2`, `1800..3599`초(30~60분 미만) → `3`, `3600`초 이상(60분 이상) → `4`.
    - `sessions`: `List<SessionWithSongDto>` — `[from, to]` 범위 내 세션을 `date DESC, updatedAt DESC` 순으로 정렬. 각 세션의 `takes`는 `recordedAt ASC` 순(`TakeDto` 12개 필드 그대로).
- **`PATCH /api/v1/sessions/{sessionId}` (K2-1):**
  - 경로 `sessionId`가 UUID가 아니면 `404 NOT_FOUND`.
  - 본문: `{ "memo": "..." }` (`requireString("memo", 2000)` — 빈 문자열 `""` 허용).
  - 없는 세션·남의 세션이면 `404 NOT_FOUND` (`"연습 기록을 찾을 수 없습니다."`).
  - 수정 후 같은 트랜잭션에서 `OutboxRepository.enqueueIfSyncEnabled(userId, "session", sessionId, "upsert")` 호출.
  - 응답: `200 OK` `{ "ok": true }`.
- **`GET /api/v1/songs/{songId}` (K2-2):**
  - 경로 `songId`가 UUID가 아니거나 없는 곡·남의 곡이면 `404 NOT_FOUND` (`"곡을 찾을 수 없습니다."`).
  - 응답(`SongDetailResponse`, `200 OK`):
    - `song`: `SongDto` (14개 필드).
    - `sessions`: `List<SongSessionDto>` — 해당 곡의 모든 세션을 `date DESC, updatedAt DESC` 순으로 반환 (`id, date, seconds, minutes, loops, a, b, segment, rate, memo` 10개 필드).
    - `takes`: `List<TakeDto>` — 해당 곡의 모든 녹음을 `recordedAt DESC` 순으로 반환 (`TakeDto` 12개 필드).
  - 라우트 등록 주의: `SongRoutes.kt`에서 `get("/{songId}")`는 `get("/by-video/{videoId}")`와 경로 세그먼트 개수가 다르므로 충돌하지 않으나, 가독성과 안전을 위해 `/by-video/{videoId}` 아래에 등록한다.
- **`segment` 문자열 포맷 공통 규칙 (`SessionService.formatSegment`):**
  - `a`와 `b`가 둘 다 `null`이 아닐 때만 `"${formatMmSs(a)}–${formatMmSs(b)}"` (가운데 기호는 en dash `\u2013`, `Code.gs` `mmss`와 동일하게 초를 `floor` 정수 내림하여 `m:ss` 2자리 0 패딩: 예 `38.0` → `"0:38"`, `55.2` → `"0:55"`). 둘 중 하나라도 `null`이면 `""`.

### 2.2 프런트엔드 `window.ULData` 확장 (`K2-1`, `K2-2`)
- **K2-1에서 `public/data.js`에 추가할 함수:**
  - `sessions.list(params)` (`params = { from, to, today }` 선택) → `GET /api/v1/sessions?...` → 응답 객체 `{ summary, calendar, sessions }` 반환.
  - `sessions.updateMemo(sessionId, memo)` → `PATCH /api/v1/sessions/{id}` 본문 `{ memo }` → `{ ok: true }` 반환.
  - `takes.getUrl(takeId)` → `GET /api/v1/takes/{id}/url` → `{ url, expiresIn }` 반환.
  - `takes.remove(takeId)` → `DELETE /api/v1/takes/{id}` → `{ ok: true }` 반환.
- **K2-2에서 `public/data.js`에 추가할 함수:**
  - `songs.get(songId)` → `GET /api/v1/songs/{id}` → `{ song, sessions, takes }` 반환.
  - `songs.update(songId, patch)` (`patch`에서 정의된 `status`, `memo`, `title` 키만 추려 전송) → `PATCH /api/v1/songs/{id}` → `r.song` 반환.
  - `songs.remove(songId)` → `DELETE /api/v1/songs/{id}` → `{ ok: true }` 반환.

### 2.4 XSS 브라우저 페이로드 검사 (`X2`)
- **`package.json` & Playwright 설정:**
  - `@playwright/test`를 `devDependencies`에 고정 버전으로 추가하고, `package.json`의 `"test"`는 기존 `"node --test test/*.test.js"`를 그대로 유지하며 `"test:e2e": "playwright test"` 스크립트를 추가한다 (`npm test`가 빨라야 기존 워크플로가 깨지지 않음).
  - `playwright.config.js`: `testDir: './test/e2e'`, Chromium 단일 프로젝트, `webServer`는 `node server.js` (포트 3000, 정적 파일 서빙용 — API 요청은 테스트에서 `page.route`로 모킹하므로 DB 없이도 고속 실행).
- **`test/e2e/xss.spec.js` 검사 범위:**
  - XSS 페이로드 4종:
    1. `<img src=x onerror="window.__xss=1">`
    2. `"><svg onload="window.__xss=1">`
    3. `javascript:window.__xss=1`
    4. `' onclick='window.__xss=1`
  - 모든 페이지 진입 전 `page.addInitScript`로 `window.__xss = false` 및 `securitypolicyviolation` 이벤트 수집 배열(`window.__cspViolations`)을 심는다.
  - 대상 화면 4종(`index.html`, `practice.html`, `log.html`[기록 탭·곡 탭·곡 상세], `settings.html`)에서 가짜 로그인 세션 및 API/oEmbed 모킹 응답의 `title`, `artist`, `memo`, `resumeUrl`, `email`, `displayName` 등에 페이로드 4종을 주입해 렌더링·클릭·탭 전환 후 `window.__xss === false` 및 `window.__cspViolations.length === 0`을 단언한다.
  - 대조군 테스트 1개: 페이지에서 고의로 이스케이프 없이 DOM에 주입했을 때 검출기가 실제로 작동하는지(또는 CSP가 인라인 이벤트 핸들러를 차단해 `window.__cspViolations`에 잡히는지) 검증한다.
- **`.github/workflows/ci.yml`:**
  - `e2e-security` 작업을 추가(`needs: changes`, `if: needs.changes.outputs.code == 'true'`, `npm ci` → `npx playwright install --with-deps chromium` → `npm run test:e2e`)하고, `ci-ok`의 `needs` 배열에 `e2e-security`를 추가한다.
