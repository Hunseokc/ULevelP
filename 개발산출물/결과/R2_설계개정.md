### 진행 파일 지시와 다르게 정한 것 (이유)

- **`notes`·`analysis_jobs` RLS에 "키 등록 확인"을 넣지 않았다.** `is_owner()`를 빼고 `user_id = auth.uid()`만 둔다. 이 두 테이블은 클라이언트 insert가 없고(행은 `analyze-video`만 만듦) 키 확인은 만드는 순간 Edge Function이 한다. 읽기에 키 조건을 걸면 키를 지운 사용자가 자기 노트를 못 보고 내보내기(FR-NX-2)도 못 한다 → FR-NOTE-6으로 명시.
- **FR ID를 바꿨다**: `OWN`(owner)이 남으면 "소유자 전용"으로 읽혀서. 대응표는 2절.

`profiles`, `songs`, `sessions`, `takes`, `notes`, `analysis_jobs`, `integrations`, **`notion_sync`(새로)**, `notion_links`, `sync_outbox`. (P0-1 완료 기준을 "테이블 9개" → **10개**로 고침)

| 테이블 | 바뀐 점 |
| --- | --- |
| `profiles` | `role`은 운영 표시로만(주석). 컬럼 그대로 |

## 7. XSS 방어 결정 (X1 입력)

### 7.1 외부 스크립트: UMD + SRI

- supabase-js: `https://cdn.jsdelivr.net/npm/@supabase/supabase-js@<정확한 버전>/dist/umd/supabase.js` → `window.supabase` (버전은 P0-5에서 정함)
- JSZip: `https://cdn.jsdelivr.net/npm/jszip@3.10.1/dist/jszip.min.js` → `window.JSZip` (P3-1)
- 태그: `integrity="sha384-…" crossorigin="anonymous" defer`. 해시: `curl -sL <주소> | openssl dgst -sha384 -binary | openssl base64 -A`
- `vendor/` 복사를 버린 이유: D9(CDN에서 정확한 버전)와 다르고 갱신 절차가 하나 더 생김
- SRI 예외(제공자가 주소 고정 안 함, CSP에서 경로로만 허용): YouTube IFrame API(`https://www.youtube.com/iframe_api`, `https://www.youtube.com/s/player/`), GIS(`https://accounts.google.com/gsi/client`, P6), Google Fonts CSS(`<link>`)

### 7.2 X1 시점의 CSP 원문 (모든 `public/*.html`에 그대로)

지금 화면이 실제로 쓰는 것(Google Fonts, YouTube 플레이어·썸네일, Apps Script·GitHub API 옛 경로, 녹음 `blob:`)만 넣었다. 다른 항목은 03 2.3 표의 "들어가는 step"에서 추가한다.

```
default-src 'self'; script-src 'self' https://www.youtube.com/iframe_api https://www.youtube.com/s/player/; style-src 'self' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data: https://i.ytimg.com; media-src 'self' blob:; connect-src 'self' https://script.google.com https://script.googleusercontent.com https://api.github.com; frame-src https://www.youtube.com; object-src 'none'; base-uri 'none'; form-action 'self'; worker-src 'none'
```

최종(모든 step 뒤) 원문은 03 2.3. step별 추가: P0-5 supabase-js 경로·Supabase 주소(`connect-src`), P1-2 `https://www.youtube.com`(oEmbed, `connect-src`), P1-3 Supabase(`media-src`), P3-1 JSZip 경로, P6-1 GIS·`www.googleapis.com`·`accounts.google.com`(frame). P4-5에서 Apps Script 두 주소, P5-3에서 `api.github.com` 뺌.

## 8. S1 대체안 (03 7.1, P5-0 입력)

옛 대체안(Actions + 저장소 시크릿의 Gemini 키)은 사용자마다 키가 달라서 불가(시크릿은 하나, 입력값은 실행 기록에 남음). P5-0에서 측정값으로 아래 순서로 정한다.

1. **구간 나눠 분석 (추천)**: `videoMetadata.startOffset/endOffset`으로 한도의 70% 길이씩, 구간마다 Edge Function 한 번, pg_cron이 다음 구간을 이어 부름, 마지막에 텍스트 호출로 `build(tags)` 스키마로 합침. P5-0에서 40분 영상의 한 번 분석(로컬 `analyze.py`) 결과와 비교
2. **길이 제한 + 구간 고르기**: 1의 품질이 나쁠 때
3. **Actions 실행기**: 입력은 `job_id`만, 실행 중 service role로 `get_gemini_key(user_id,'ulevelp')` → `::add-mask::`. 저장소 시크릿에 service role 키가 필요해 위험이 가장 큼. 이 경우 `analyze.yml`·`scripts/*.py`는 P5-3에서 지우지 않음

### 11.4 RPC

**저장 (브라우저, 로그인한 사용자):**

```
POST /rest/v1/rpc/save_notion_key
헤더: apikey: <publishable>, Authorization: Bearer <access 토큰>, Content-Type: application/json
본문: { "p_app_id": "guitar-practice", "p_token": "ntn_…" | null, "p_songs_db": "<32 hex>", "p_sessions_db": "<32 hex>" }
     (p_notes_db는 생략. p_token = null이면 키는 그대로 두고 DB ID만 바꿈. 처음엔 키 필수)
응답: [ { "hint": "abcd", "updated_at": "…" } ]
```

시그니처: `save_notion_key(p_app_id text, p_token text, p_songs_db text, p_sessions_db text, p_notes_db text default null) returns table (hint text, updated_at timestamptz)` — `security definer`, 사용자는 `auth.uid()`. 오류는 HTTP 400과 `message`: `invalid_app_id`, `missing_key`, `invalid_notion_token`(`^(ntn_|secret_)[A-Za-z0-9]{20,}$`), `invalid_notion_db_id`(`^[0-9a-f]{32}$`. 노션 링크·하이픈 UUID는 브라우저가 32자리 소문자로 바꿔서 보냄). 로그인 없음 → `not_authenticated`.

**원문 조회 (Apps Script만, service role):**

```
POST /rest/v1/rpc/get_notion_key
헤더: apikey: <secret 키>, Content-Type: application/json   (secret 키 사용 방식은 G5에서 실제로 확인: 새 sb_secret_ 키는 apikey 헤더만, 옛 service_role JWT면 Authorization: Bearer 도)
본문: { "p_user_id": "<auth/v1/user로 확인한 user.id>", "p_app_id": "guitar-practice" }
응답: [ { "token": "ntn_…", "songs_db": "…", "sessions_db": "…", "notes_db": null, "updated_at": "…" } ]   (키가 없으면 [])
```

시그니처: `get_notion_key(p_user_id uuid, p_app_id text) returns table (token text, songs_db text, sessions_db text, notes_db text, updated_at timestamptz)` — `anon`·`authenticated` 실행 권한 없음(테스트로 확인).

- 캐시 키(가이드 GAS 방식): `uid + updated_at` 해시. 노션이 401을 주면 그 캐시를 지움.
- 사용자 확인: `GET https://vefrfhafmiiivpgjhqiu.supabase.co/auth/v1/user` (헤더 `Authorization: Bearer <토큰>`, `apikey: <publishable>`) → `id`. 토큰 해시 → user_id를 토큰 만료까지 캐시.
- Gemini(`save_gemini_key`/`get_gemini_key`)도 `app_id = 'guitar-practice'`로 쓸 수 있지만, guitar-practice 계획(보안 정리 4절)은 Gemini를 지금처럼 Actions + 저장소 시크릿으로 두므로 쓰지 않는다.
