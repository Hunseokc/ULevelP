### 2.1 `K3-1` — 노션 호환 ZIP 내보내기/가져오기 (`Export & Import`)
- **`StorageClient.download(key: String): ByteArray` 추가:**
  - `SupabaseStorageClient`: `GET $supabaseUrl/storage/v1/object/$bucket/$key` (`Authorization: Bearer $secretKey`, `apikey: $secretKey`) 호출, `200..299`이면 바이트 배열 반환, 실패 시 `StorageException`.
- **`GET /api/v1/export/zip?includeAudio=true`:**
  - 쿼리 파라미터 `includeAudio`: 생략·`"true"`이면 `true`, `"false"`이면 `false`, 그 외 값은 `400 INVALID_INPUT`.
  - 사전 DB 조회 및 스트리밍 분리: 라우트에서 먼저 `val data = exportImportService.loadExportData(user.id)`를 호출해 DB 미연결(`503 DB_UNAVAILABLE`) 등이 스트리밍 시작 전에 표준 JSON 에러로 응답되게 한 뒤, `call.respondOutputStream(ContentType.Application.Zip, HttpStatusCode.OK) { exportImportService.writeExportZip(data, includeAudio, this) }`를 실행한다.
  - ZIP 엔트리 구성:
    1. `읽어주세요.txt`: 템플릿 복제 및 CSV 병합 안내문(UTF-8).
    2. `연습 곡.csv`: UTF-8 BOM(`\uFEFF`) + 헤더 `곡명,아티스트,상태,유튜브 링크,이어서 연습,마지막 위치(초),구간 시작(초),구간 끝(초),속도,마지막 연습일,메모` (11열).
    3. `연습 기록.csv`: UTF-8 BOM(`\uFEFF`) + 헤더 `기록,곡,날짜,연습 시간(분),반복 횟수,속도,구간,메모,녹음` (9열). `연습 시간(분)`은 `round(seconds / 60.0, 2)`, `구간`은 `SessionService.formatSegment(a, b)`, `녹음`은 해당 세션의 녹음 ZIP 상대 경로(`녹음/{date}_{HHmmss}_{safeTitle}_{takeId8}.{ext}`)를 `, `로 연결.
    4. `학습 영상 노트.csv`: UTF-8 BOM(`\uFEFF`) + 헤더 `제목,URL,태그,채널,요약,키워드,난이도,메모` (8열).
    5. `학습 영상 노트/{safeTitle}_{noteId8}.md`: 노트별 마크다운 본문.
    6. `녹음/{date}_{HHmmss}_{safeTitle}_{takeId8}.{ext}`: `HHmmss`는 `recordedAt`의 **UTC 시각**(같은 분에 여러 번 녹음해도 파일명과 초 단위 시각이 보존되도록 UTC 초 단위로 기록. 반면 `K4-2` 노션 업로드는 기존 `Code.gs` 호환을 위해 서울 시각 `HHmm`을 사용). `includeAudio == true`이고 `storage == "supabase"`이며 `storageClient != null`일 때 바이트 수록.
- **`POST /api/v1/import/notion/preview` (`multipart/form-data`, 파트 `file`):**
  - 크기 제한 및 메모리 보호(단일 인스턴스 `max-instances=1` 전제):
    - 업로드 ZIP 최대 100MB(`104_857_600L`, 초과 시 `413 ZIP_TOO_LARGE`), 압축 해제 총량 최대 200MB(`209_715_200L`, 초과 시 `400 INVALID_INPUT`), 최대 엔트리 1,000개.
    - `ImportPreviewStore`는 원본 `zipBytes`를 보관하지 않고 파싱된 행 데이터와 오디오 바이트(미리보기당 오디오 총량 최대 50MB `52_428_800L`)만 보관하며, **사용자당 최대 1개(`MAX_PREVIEWS_PER_USER = 1`)**, 서버 전체 최대 10개(`MAX_TOTAL_PREVIEWS = 10`), TTL 15분으로 제한한다.
  - **가져온 녹음(`takes`) 필수 컬럼 복원 규칙 (`K3-1`·`K4-3` 공통):**
    - `recordedAt`: 파일명(확장자 제외)이 ① `^(\d{4}-\d{2}-\d{2})_(\d{2})(\d{2})(\d{2})_` (ZIP 내보내기 형식)이면 UTC `YYYY-MM-DDTHH:mm:ssZ`로 파싱, ② `^(\d{4}-\d{2}-\d{2})\s+(\d{2})(\d{2})(?:\s+|$)` (노션 업로드 형식)이면 `Asia/Seoul`(`+09:00`) 기준 `YYYY-MM-DDTHH:mm:00+09:00`을 UTC로 변환, ③ 둘 다 아니거나 파싱 실패 시 소속 세션의 `${session.date}T00:00:00Z`.
    - `durationSec`: `0` (ZIP·노션 파일 속성에 길이 정보가 없으므로 `0`으로 고정).
    - `mime`: 파일 확장자 소문자 역매핑(`m4a`/`mp4` → `audio/mp4`, `weba`/`webm` → `audio/webm`, `ogg` → `audio/ogg`, `mp3` → `audio/mpeg`, `wav` → `audio/wav`, `aac` → `audio/aac`). 표에 없는 확장자는 `K3-1`에서 `errors`에 기록 후 건너뜀.
    - `sizeBytes`: 오디오 바이트 길이(`1..52_428_800`).
    - `a`, `b`, `rate`: 소속 세션(`session`)의 `a`, `b`, `rate` 복사. `memo`: `""`.
  - 응답(`200 OK`, `ImportPreviewResponse`):
    `{ "ok": true, "previewToken": "f1000000-0000-4000-8000-000000000001", "newSongs": Int, "updatedSongs": Int, "sessions": Int, "takes": Int, "songsSample": List<ImportSongSampleDto>, "errors": List<ImportRowErrorDto> }`.
- **`POST /api/v1/import/notion/confirm`:**
  - 요청 본문: `{ "previewToken": "<uuid>" }`. 없거나 만료됐거나 타 사용자 토큰이면 `404 NOT_FOUND` (`"미리보기 내역이 없거나 만료되었습니다. ZIP 파일을 다시 선택해 주세요."`).
  - **트랜잭션 경계:** ① 트랜잭션 1에서 곡(`(user_id, video_id)` Upsert)과 세션(`(user_id, song_id, date)` 덮어쓰기 Upsert)을 일괄 반영하고, ② 각 녹음에 대해 `(session_id, recorded_at, size_bytes)` 중복 여부 및 `profiles FOR UPDATE` 쿼터를 확인한 뒤 트랜잭션 밖에서 스토리지에 업로드하고 짧은 트랜잭션으로 `takes` INSERT(실패 시 보상 삭제)를 수행한다.
  - 응답(`200 OK`, `ImportConfirmResponse`):
    `{ "ok": true, "createdSongs": Int, "updatedSongs": Int, "upsertedSessions": Int, "importedTakes": Int, "skippedTakesByQuota": Int }`.

### 2.3 `K4-2` — 노션 실시간 동기화 — 보내기 (`NotionPushWorker` & Cron)
- **`NotionClient` (`src/main/kotlin/ulevelp/notion/NotionClient.kt`):**
  - 노션 API(`2022-06-28`) 호출, `429 Retry-After` 재시도(최대 3회), `Code.gs` `upload()`와 동일한 파일 업로드(20MB 이하 단일 파트, 20MB 초과 10MB 멀티파트) 구현.
- **`NotionPushWorker` 정렬·부모 보장·크론 격리 규칙:**
  - Outbox 정렬 순서: `("upsert","song")=1` → `("upsert","session")=2` → `("upsert","take")=3` → `("upsert","note")=4` → `("delete","take")=5` → `("delete","session")=6` → `("delete","song")=7` → `("delete","note")=8`, 동일 순위 내 `id ASC`.
  - 부모 `notion_links` 부재 시: `session` Push 시 곡 링크가 없으면 `pushSongUpsert`를 먼저 수행(곡이 DB에서 삭제되었으면 `done_at = now()` 처리 후 건너뜀, 노션 API 실패 시 해당 `session` 항목도 `attempts + 1` 실패 기록). `take` Push 시 세션 링크가 없으면 `pushSessionUpsert`를 먼저 수행.
  - `runCronBatch()`: 사용자별 Push는 개별 `try/catch`로 감싸 한 사용자의 `NO_KEY`·`CRYPTO_UNAVAILABLE` 오류가 다른 사용자나 `storage_trash`·`analysis_jobs` 정리를 중단시키지 않도록 격리. `purgedTrash`는 `storageTrashService.purge(ids)` 호출 전후 `StorageTrashTable`에 남아 있는 `ids` 행 수 차이(`ids.size - remaining`)로 계산.
  - `CronOidcVerifier`: `HttpJwksProvider`·`JwksParser`를 재사용하고, RS256 서명 검증은 `SupabaseJwtVerifier.kt:377`의 RS256 분기를 `CronOidcVerifier` 내부 private 함수로 작성. 실패 시 메시지 `"유효한 크론 OIDC 토큰이 아닙니다."`로 통일.

### 2.4 `K4-3` — 노션 실시간 동기화 — 가져오기 (`NotionPullService` & `full` 모드) + 레거시 제거
- **노션 `last_edited_time` 분 단위 절삭 보정 및 로컬 충돌 방지:**
  - 증분 `pull` 시 노션이 `last_edited_time`을 분 단위로 버림 저장하는 특성을 보정하기 위해 `after: (lastPullAt - 2분)`으로 쿼리한다.
  - 노션에서 가져온 곡·세션에 대해 로컬 `sync_outbox`에 미처리(`done_at IS NULL AND attempts < 5`) 항목이 존재하면 **로컬 변경을 우선하여 Pull 덮어쓰기를 건너뛴다**.
  - 페이지네이션은 최대 `MAX_PAGES_PER_SYNC = 500`개까지만 읽고 정상 종료한다.
- **초기 전체 동기화(`enable`) 녹음 중복 방지:**
  - 다운로드 전에 `NotionLinksTable`(`entity = "take"`, `notionExtra = "$sessionPageId:${file.name}"`) 또는 같은 세션의 분 단위 `recordedAt` 일치 여부를 먼저 확인해 이미 이관된 녹음은 다운로드 자체를 건너뛴다(2회 연속 실행 시 오디오 재다운로드 0건 및 중복 0건 보장).
