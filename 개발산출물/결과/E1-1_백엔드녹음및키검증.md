## 3. 체크리스트 점검 완료 보고

- [x] **주니어 체크리스트 점검 완료:**
  - 외부 API 호출(`checkClient.checkGemini`)은 DB 트랜잭션 밖에서 수행
  - `replaceOldSongTakes = true` 시 `storage == "drive"`인 파일은 보존되고 `supabase` 파일만 선별 삭제
  - 삭제된 녹음의 실제 바이트 크기만큼 `takeUsedBytes` 정상 회수
  - 테스트 시 Docker 임시 컨테이너만 사용, 원격 DB 격리 유지
  - DTO 및 시그니처 1:1 준수
- [x] **명세와 달라진 점 (PR #33 리뷰 2번 반영):**
  - `IntegrationCheckClient.kt`: 명세 파일 목록의 1토큰 `generateContent` 추가 핑 대신 기존 `GET /models/{model}` 조회를 유지함 (사유: 키 유효성·권한 및 모델 식별 검증이 경량 메타 조회로 충족되며, 추가 토큰 생성 비용 및 기존 테스트 목 서버 호환성을 유지하기 위함).
- [x] **시니어 PR #33 리뷰 반영 내역:**
  - 1번·2번: `TakeService.kt` 트랜잭션 B 첫머리에 `ProfilesTable` `FOR UPDATE` 잠금을 선배치하고, 그 뒤에 최근 연습 곡·타 곡 녹음·쿼터 검사를 수행하도록 순서 재정렬. 삭제 시에도 조건식 대신 조회한 `oldIds` 목록(`inList`)으로 삭제하여 "trash 적재 = 삭제" 일치 보장
  - 3번: `IntegrationService.kt`에서 `apiKey` 생략 시 복호화는 `input.verify == true`일 때만 수행하도록 변경하여, 단순 모델 변경 시 불필요한 복호화 실패로 인한 500 오류 방지
  - 4번: `TakeApiTest.kt` T33에 사전 차단 시 스토리지 파일 미생성(`fake.objects.size == 0`) 및 DB 녹음 미생성(`0건`) 단언 추가
  - 주니어 체크리스트에 3대 신규 규칙(동시성 FOR UPDATE 순서 및 inList 삭제, 조건부 복호화, 실패 사전차단 단언) 반영 완료
