## 2. 외부 설정 및 남은 완료 기준 확인 (사람 · 리뷰 2·3·7번)

K0-4를 `완료`로 닫기 위해 아래 설정값 확인 및 실제 로그인 검증이 필요합니다:

1. **Supabase Publishable Key (`public/config.js` `supabaseAnonKey`, 리뷰 3번):**
   - Supabase 대시보드 (`vefrfhafmiiivpgjhqiu`) → `Project Settings` → `API`의 Publishable key(`sb_publishable_...`) 또는 `anon` public key를 알려주시면 `public/config.js`에 반영합니다.
2. **Google Cloud OAuth & Supabase Auth Google 공급자 설정 확인:**
   - Google Cloud Console OAuth 2.0 클라이언트 리디렉션 URI: `https://vefrfhafmiiivpgjhqiu.supabase.co/auth/v1/callback`
   - Supabase 대시보드 `Authentication` → `Providers` → `Google` 활성화 및 `URL Configuration` (`Site URL`: `https://hunseokc.github.io/ULevelP/`, `Redirect URLs`: `https://hunseokc.github.io/ULevelP/**`, `http://localhost:3000/**`)
3. **API 서버 출처(`apiBaseUrl` 및 CSP `connect-src`, 리뷰 2번):**
   - 로컬 Ktor 서버(`http://localhost:3000`)에서는 같은 Origin(`'self'`)으로 `/api/v1/me`가 동작합니다.
   - GitHub Pages 배포본에서 호출할 Cloud Run URL이 정해져 있다면 `public/config.js`의 `apiBaseUrl`과 HTML 5개·`test/security.test.js`의 CSP `connect-src`에 함께 추가합니다(KZ-1에서 배포 시 확정하거나, 이미 생성된 URL이 있으면 지금 반영).
4. **원격 DB `V1__init.sql` 적용 및 실제 로그인 → `GET /api/v1/me` 200 확인 (리뷰 7번):**
   - `.env`의 `REMOTE_DB_PASSWORD`를 채운 뒤 서버 기동 시 Flyway 마이그레이션 적용 및 실제 로그인 복귀 후 `GET /api/v1/me` 200 응답을 확인합니다.
