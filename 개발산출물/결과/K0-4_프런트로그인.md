## 3. 다음 단계(`K1-1`) 전달 사항

- **원격 DB 상태:** Supabase PostgreSQL(`aws-0-ap-northeast-2.pooler.supabase.com:5432`)에 `V1__init.sql` 12개 테이블(`users`, `profiles`, `songs`, `sessions`, `takes`, `notes`, `analysis_jobs`, `integrations`, `notion_sync`, `notion_links`, `sync_outbox`, `storage_trash`)이 `v1`으로 적용 완료되었습니다.
- **프런트엔드 인증 유틸 (`window.ULAuth`):**
  - `ULAuth.getAccessToken()`: 현재 세션의 Bearer 토큰 반환
  - `ULAuth.fetchApi(path, init)`: `apiBaseUrl` + `Authorization: Bearer <token>` 헤더를 자동으로 붙여 호출
  - `ULAuth.getUser()`, `ULAuth.getMe()`: 현재 로그인 사용자 및 `/api/v1/me` 프로필 캐시 조회
- **Cloud Run 배포 및 `apiBaseUrl`:**
  - 현재 멀티스테이지 `Dockerfile` 및 Ktor 서버(`Main.kt`: `/api/health`, `/api/*`, `/api/v1/me`, 정적 파일 서빙, Flyway 자동 마이그레이션)는 **지금 바로 Cloud Run에 배포 가능**합니다.
  - 로컬 Ktor 서버(`http://localhost:3000`)나 Cloud Run 자체 도메인에서 열 때는 같은 Origin(`'self'`)이므로 `apiBaseUrl: ''` 상태로 즉시 동작합니다. GitHub Pages(`https://hunseokc.github.io/ULevelP/`)에서 교차 출처로 호출할 때는 Cloud Run 배포 URL을 `public/config.js`의 `apiBaseUrl`과 HTML 5개·`test/security.test.js`의 CSP `connect-src`에 추가하면 됩니다.
