## 1. 핵심 흐름 (목표: 수집 → 연주·보이싱 탐구가 끊기지 않게)

```
[수집]                          [CHORDS 코드 진행 모음]                  [LEARN 연습실 · 진행 연주 탭]
코드 진행 영상 URL ─┐            ┌ 진행 행 ───────────────────┐
직접 입력 ──────────┼─ 저장 ──▶ │ FM9 - Dm9 - Gm7 - C7        │──"연습실에서 직접 연주해볼까요?"──▶ 진행 칩 + 보이싱 경로 + 재생
붙여넣기 ───────────┘   │        │ IM7 - vim7 - iim7 - V7      │                                   │ 코드 칩 → 매트릭스/코드톤 지도
                        │        │ [▶ 연습실] [구간 반복] [노트] │◀──────── "← 코드 진행 모음" ───────┘
                        └ 저장 직후 안내: "방금 넣은 진행, 연습실에서 바로 연주해볼까요?" [연주하기]
홈 "취향 코드 진행 꺼내보기" 카드 ──[연주하기]──▶ 연습실 진행 연주 탭
```

- 연습실로 넘어가는 입구는 세 군데: ① 진행 행/상세의 주 버튼 ② 저장 직후 안내 ③ 홈 취향 카드
- 영상에서 온 행은 "구간 반복"(`practice.html?v=&t=<시작(초)>`)도 같이 둔다 → 영상 보며 듣기 ↔ 연습실에서 내 손으로 연주를 오갈 수 있다

## 2. CHORDS 페이지 프레임 (데스크톱 기준, 좁은 폭은 세로로 쌓음)

```
┌ 코드 진행 모음 ──────────────────────────────────────────────────────────┐
│ 범위 ( 레퍼런스 | 분석 | 합산 )                          [ + 진행 넣기 ]     │
├────────────────────────────────────────────┬────────────────────────────┤
│ 진행 목록                                    │ 취향 코드 진행               │
│ ┌──────────────────────────────────────┐   │  자주 나오는 진행 Top 5       │
│ │ Just the Two of Us · Grover W. Jr.    │   │  코드 빈도 / 코드 이동 Top     │
│ │ F Major · 직접                         │   │  Mood · Genre · 키 분포       │
│ │ FM7 - E7 - Am7 - Gm7 C7                │   │  [ 랜덤으로 꺼내보기 ]         │
│ │ IVM7 - III7 - vim7 - vm7 I7            │   │   └ 꺼낸 진행 카드 + [연주하기]│
│ │ [▶ 연습실에서 연주] [수정] [⋯]           │   │                            │
│ └──────────────────────────────────────┘   │                            │
│ ┌ (분석 행) 네오소울 진행 · 채널명 · AI · 근거 화면 ┐                           │
│ │ ... [▶ 연습실에서 연주] [구간 반복] [노트]  │   │                            │
└────────────────────────────────────────────┴────────────────────────────┘
```

- **진행 넣기**(펼침 영역 또는 모달, 탭 3개)
  - `코드 진행 영상`: URL + 메모, CH-0의 안내 문구(기획 메모 §4). 분석은 작업 큐라 "분석 중" 행이 목록 맨 위에 생기고 끝나면 채워진다
  - `직접 입력`: 곡·아티스트(필수), 코드 심볼(칩 입력, `-`·공백 구분), 키(자동 추정 → 드롭다운으로 확인/수정), 로마숫자 미리보기(자동 계산), Mood·Genre·Tag·URL·메모(선택)
  - `붙여넣기`: 코드 사이트에서 복사한 텍스트 → 뽑힌 코드 줄과 "반복 구간 후보"(예: 4코드 ×8회) → 하나 골라 `직접 입력` 폼으로 넘김
  - `직접 입력`·`붙여넣기` 옆에 접이식 **읽는 법 안내**(마디는 몰라도 순서만, 사이트에서 코드가 적힌 줄을 보는 법, 예시 하나)
- **행 상세**(행 클릭 시 펼침): 코드별 칩(심볼·로마숫자·근거), 메모, 출처·수집 경로, 수정·삭제. 주 버튼은 언제나 "연습실에서 직접 연주해볼까요?"
- 노트 상세에는 "코드 진행 수집에 넣기" 토글을 두고, 켜면 "CHORDS에서 보기" 링크를 보여 준다
- 비로그인: 범위 토글·목록은 기본 시드만, `진행 넣기`는 로그인 안내. 연습실 연동은 비로그인도 그대로 된다(아래 §3, URL로 넘기므로)

## 3. 연습실 쪽 — 새 탭 "진행 연주" (제안)

지금 연습실 7개 모드는 모두 **코드 하나**(또는 2-5-1 고정)를 다룬다. 수집한 진행을 그대로 받는 모드가 없어서 8번째 탭을 만드는 것을 제안한다.

```
┌ 진행 연주 ─────────────────────────────────────────── ← 코드 진행 모음으로 ┐
│ Just the Two of Us (F Major)                     키 옮기기 [ F ▾ ]        │
│ ( FM7 ) → ( E7 ) → ( Am7 ) → ( Gm7 ) → ( C7 )      ← 지금 코드 강조          │
│ 프렛 범위 [5]–[9]   보이싱 경로 ( 1 | 2 | 3 )   BPM [70]  코드당 [4]박  [▶ 재생] │
│ ┌지판┐ ┌지판┐ ┌지판┐ ┌지판┐ ┌지판┐   ← 코드마다 다이어그램, 경로 내 이동 최소     │
│ 고른 코드: E7  [다른 보이싱 보기] [보이싱 매트릭스에서 열기] [코드톤 지도에서 열기] │
└──────────────────────────────────────────────────────────────────────────┘
```

- **보이싱 경로**: 코드마다 `genVoicings(root, q)` 후보를 만들고, 이웃 코드 사이 이동 비용(`trans`: 7도→3도 가이드톤 이동 + 탑노트·평균 프렛 차이)이 가장 작은 연결을 상위 3개 고른다. 2-5-1 탐색(`search251`)을 길이 N 진행으로 넓힌 것(DP)
- **재생**: 기존 오디오 엔진(루트 베이스 + 코드), BPM·코드당 박 수, 반복
- **코드 칩에서 기존 모드로 깊이 들어가기**: 매트릭스(Q4 9종 퀄리티일 때: drop 2/3·전위 비교), 코드톤 지도(아르페지오). 기존 탭에 루트·퀄리티를 넘겨 여는 입구를 같이 만든다
- **키 옮기기**: 로마숫자가 있으니 다른 키로 바로 옮겨 연주(탐구용, 저장은 안 함)
- **진행 없이 탭을 열면**: 빈 상태 + 기본 시드 진행 고르기 + 코드 심볼 직접 입력란(비로그인도 사용 가능)

### 3-1. 진행 전달 방식 (제안: URL)

- `chords.html#prog?c=FM7,E7,Am7,Gm7,C7&k=F&t=<제목>&from=<진행 id>`
- 장점: 비로그인·기본 시드·홈 카드 모두 같은 방식, 새로고침·북마크 유지, 연습실이 서버 API를 몰라도 됨. `from`이 있으면 "← 코드 진행 모음으로"가 그 행으로 돌아간다
- 지금 연습실은 `#탭` 해시만 읽는다(`ChordsPage.tsx:113`) → `#prog?...` 해시 뒤 파라미터 파싱을 추가. 기존 `#matrix` 등 링크는 그대로 동작해야 한다(회귀 e2e)

### 3-2. 코드 지원 범위와 대체

- 연습실 엔진 지원 퀄리티: 보이싱 엔진 `GE.CH` 17종(`6 7 9 13 maj7 maj9 maj7s11 m7 m9 m11 m6 m7b5 7b9 7#9 7#11 7b13 7sus4`), 매트릭스 `Q4` 9종(`maj7 maj7sus2 7 7sus4 6 m7 m6 m7b5 dim7`)
- 지원 밖 코드(예: `Ab9sus4`, `C(add9)`, 슬래시 코드 `G7/B`)는 **가장 가까운 지원 퀄리티로 바꿔 연주하고 칩에 표시**("Ab7sus4로 연주 · 9 생략"). 슬래시 베이스는 재생 베이스음에만 반영
- 심볼 → (루트, 퀄리티) 변환은 CH-2 코드 파서가 맡는다(같은 파서를 진행 페이지 로마숫자 계산에도 씀)

### 3-3. 건반 진행

- 연습실은 **기타 지판 기준**이다. 건반 영상에서 온 진행도 코드 심볼로 기타 보이싱을 만들어 연주한다
- AI가 뽑은 건반 원본 보이싱(lh/rh)은 이미 노트 상세의 건반 다이어그램에 있다 → 진행 연주 탭에 "원본 건반 보이싱 보기(노트)" 링크

## 4. 구현 단계 영향 (확정되면 진행 파일 표 반영)

- CH-2 코드 파서: 심볼 → (루트, 퀄리티, 베이스, 생략 텐션) + 지원 퀄리티 대체 규칙까지
- CH-5b 연습실 연동: ① `#prog?...` 파싱 ② 진행 연주 탭(경로 DP — `trans`는 `voicing.js`에서 export되지 않으므로 레거시 파일을 고치지 않고 `frontend/src/lib`에 옮겨 둔다) ③ 기존 탭(매트릭스·코드톤 지도) 루트·퀄리티 입구 ④ 진행 페이지·홈 카드 버튼 ⑤ e2e(진행→연습실→돌아오기, 기존 7개 모드 회귀)
- 연습실 탭 목록 `CHORD_MODES`(`progressions.ts`)와 홈 BETTER "7개 연습 모드" 문구에 8번째 탭이 생긴다 → 홈에 노출할지 CH-5b에서 결정

### 5-1. "엔진에 퀄리티 추가"로 바뀐 점 (§3-2 대체)

- 진행에 나오는 코드를 보이싱 엔진(`GE.CH`)이 직접 연주하도록 퀄리티를 늘린다. 대체 표시는 **추가한 뒤에도 남는 예외**(파서가 읽었지만 엔진에 없는 코드)에만 쓴다
- **지금 `GE.CH`에는 3화음이 없다**(메이저·마이너 트라이어드 `C`, `Am`). 팝 레퍼런스 대부분이 3화음이라 추가 목록 1순위
- 추가 후보(CH-1b에서 확정): 3화음 `maj`·`m`·`dim`·`aug`, `sus2`·`sus4`, `add9`·`m(add9)`, `6/9`·`m6/9`, `9sus4`·`13sus4`, `m(maj7)`, `7b5`·`7#5`·`maj7#5`, `dim`, `m7b5` 계열 확장 등. 기준은 "코드 파서(CH-2)가 읽는 퀄리티 = 엔진이 연주하는 퀄리티"
- 슬래시 코드(`G7/B`): 위쪽 코드는 엔진 보이싱, 베이스음은 재생 베이스 + 지판 최저음 조건(가능하면)으로 반영 — 방식은 CH-1b
- **고칠 파일 범위 — 결정(2026-11-04): 엔진을 먼저 `frontend/src/lib/engine/`으로 옮기고(CH-E) 퀄리티는 새 위치에서만 추가한다.** 아래 "추가만 허용" 안은 쓰지 않는다(기록용):
  - `public/lib/voicing.js`(·필요하면 `theory.js`)는 React가 직접 import하는 **공용 엔진**이다(`musicEngine.ts`). "레거시 `public/*`는 손대지 않는다" 결정과 부딪힌다 → 제안: 엔진 파일은 **추가만**(기존 퀄리티·함수 결과 불변) 허용하고, `test/engine.test.js`·`test/r2_chords.test.js`로 기존 결과 회귀를 확인. 옛 화면 HTML·JS(`public/*.html`, `public/app.js` 등)는 계속 손대지 않는다
  - 서버 `VoicingEngine.kt`(`/api/voicings`, "server.js 100% 호환")에도 같은 퀄리티를 넣을지 — 진행 연주 탭은 브라우저 엔진만 쓰므로 1차는 JS만 고치는 안을 기본으로 한다
  - 매트릭스(`Q4`, drop 4음 구조)는 바꾸지 않는다. "매트릭스에서 열기"는 Q4 9종 퀄리티일 때만 보인다
- 단계 영향: 엔진 퀄리티 추가는 CH-2(코드 파서)와 짝이다 → **CH-2b "보이싱 엔진 퀄리티 추가"** 를 CH-2 뒤에 둔다(진행 파일 표 반영)
