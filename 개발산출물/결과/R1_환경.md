## 2. 겪은 문제: 루트 `.env`가 로컬 DB 포트를 덮어씀

- 증상: `supabase start`가 `DbConnectError ... password 인증 실패 (SQLSTATE 28P01)`(한글 메시지)로 끝나고 컨테이너를 내림.
- 원인: Supabase CLI는 루트 `.env`를 읽고 `SUPABASE_<섹션>_<키>` 변수로 `config.toml`을 덮어쓴다. 원격 접속용 `SUPABASE_DB_PORT=5432`가 `[db] port = 54322`를 덮어써서, CLI가 5432에서 돌고 있는 Windows Postgres(`postgresql-x64-16` 서비스)에 붙었다.
- 처음 확인은 명령 앞 `SUPABASE_DB_PORT=54322`로 우회해서 했다(셸 변수가 `.env`보다 우선).
- 해결(사용자 승인, 2026-10-29): `.env`의 `SUPABASE_DB_*`를 `REMOTE_DB_*`로 바꿨다(저장소 코드에서 읽는 곳 없음). 이후 우회 없이 `supabase status`와 원격 `migration list`가 동작한다. **`.env`에 `SUPABASE_`로 시작하는 변수를 두지 않는다.**

## 4. 원격 확인에 쓴 방법

- `--db-url` 방식: `.env`의 `REMOTE_DB_USER/PASSWORD/HOST/PORT/NAME`으로 `postgresql://<user>:<encodeURIComponent(pw)>@<host>:<port>/<name>`을 만들어 `npx --yes supabase@2.122.0 migration list --db-url <url>`. 출력의 비밀번호를 `***`로 바꿔 찍었다.
- psql: 로컬에 psql이 없어서 로컬 DB 컨테이너 안의 것을 썼다 — `docker exec -e PGPASSWORD=… supabase_db_ULevelP psql -h <host> -p 5432 -U postgres.<ref> -d postgres -Atc "select current_setting('server_version')"` → `17.11`.
