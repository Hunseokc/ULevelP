## 2. 남은 문제 2건 처리 방침

### 2-1. `Main.kt` spa.html 서빙 → **RZ-3에서 구현 (Cloud Run만 React 전환, 롤백 스위치 포함)**

시니어가 실측한 근거(로컬 임시 패치, 커밋 안 함):
- `server.js`가 HTML 진입 경로에 React 빌드를 서빙하게 바꾸고 **기존 E2E 12개를 그대로 실행 → 12 passed**. 단언이 내용까지 검사함(`#songs` 텍스트, `#songTitle` 등). 즉 React 화면의 DOM ID·동작 계약이 레거시와 일치한다
- 같은 조건에서 `csp_check.js` **13개 화면 실패 0**(코드 연습실은 2-2 수정 적용 시 SVG 50개 정상)
- 9개 HTML(`public/*.html` 8개 + `frontend/index.html`)의 CSP meta가 모두 같은 값

결정:
1. Ktor는 `public/spa.html`이 있고 `ULP_UI != legacy`이면 8개 HTML 진입 경로(`/`, `index`, `chords`, `practice`, `log`, `notes`, `note`, `settings`, `privacy` `.html`)에 `spa.html`을 서빙한다. 헤더·캐시·HEAD 처리는 기존 경로를 그대로 탄다. 명세 RZ-2 §2.4의 목록엔 `notes.html`이 빠져 있었다
2. **롤백 스위치 `ULP_UI=legacy`**를 둔다. `deploy-cloudrun.sh`가 `--set-env-vars`로 env를 통째로 교체하므로 콘솔에서만 바꾸면 다음 배포 때 사라진다. 그래서 스크립트·워크플로 변수(`vars.ULP_UI`, 기본 `spa`)로 넣는다
3. `server.js`(E2E·csp_check용)는 `ULP_UI=spa`일 때만 같은 규칙으로 `dist/`를 서빙한다(기본 legacy). CI E2E를 `legacy`·`spa` 두 번 돌려 **운영(Cloud Run=React)과 테스트 대상이 어긋나지 않게** 한다
4. **GitHub Pages는 레거시 유지**(이번 범위 밖). Pages는 `/ULevelP/` 하위 경로라 React 빌드의 절대 경로(`/assets/`, `/config.js`)와 `BrowserRouter` 라우트가 맞지 않는다. Pages를 React로 바꾸거나 닫는 결정은 따로 한다(§4-R1)

### 2-2. Vite CommonJS 변환 → **RZ-3에서 `vite.config.ts`에 `build.commonjsOptions.include` 추가**

- 원인: `public/lib/theory.js`·`voicing.js`는 브라우저 전역 겸용 CJS(`if (typeof module !== 'undefined') module.exports = …`)이다. Rollup은 `node_modules` 밖 파일엔 CJS 변환을 하지 않아 import 결과가 비어 있게 된다 → `ChordsPage` `reading 'g6'`
- 해결: `commonjsOptions: { include: [/node_modules/, /public[\\/]lib[\\/]/] }`. 시니어 실측으로 빌드 결과에서 코드 연습실이 정상 마운트되고 csp_check도 통과
- 버린 대안: `theory.js`를 ESM으로 바꾸기. 레거시 `<script>` 로드와 `server.js`의 `require`가 깨진다
- **알려진 제약:** `npm run dev:client`(vite dev)는 이 설정이 적용되지 않아 같은 크래시가 난다. 또 dev 모드는 CSS를 인라인 `<style>`로 주입하므로 CSP(`style-src 'self'`)에 막힌다. 실측 결과 `style-src-elem inline` 위반 10건. 따라서 화면 확인은 `npm run build` 후 `ULP_UI=spa node server.js`로 한다. 진행 파일에 적는다
