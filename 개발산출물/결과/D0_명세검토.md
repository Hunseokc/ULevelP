### 2.1 `K5-1` — Gemini 학습 노트 분석 엔진 & Notes API (`/api/v1/notes`)
- **Cloud Run Job `analyze` 실행 진입점 및 54분 타임아웃 보장 (`KC-D6`):**
  - 단일 컨테이너 이미지의 `Main.kt` `main(args: Array<String>)`에서 `--analyze-job <jobId>` 인자(또는 `ANALYZE_JOB_ID` 환경변수)가 주어지면 Ktor HTTP 서버를 띄우지 않고 `NoteService.executeJob(UUID.fromString(jobId))`만 실행한 뒤 종료한다.
  - 웹 서버의 `POST /api/v1/notes/analyze`는 `AnalyzeJobDispatcher.dispatch(jobId)` 인터페이스를 호출한다:
    - `CLOUD_RUN_ANALYZE_JOB_URI` 환경변수가 설정된 운영 환경에서는 `CloudRunJobDispatcher`가 GCP 메타데이터 서버 토큰으로 Cloud Run Jobs `run` API(`containerOverrides.env = [{"name":"ANALYZE_JOB_ID","value":jobId}]`)를 호출한다. (PR #27 리뷰로 수정: `args` 덮어쓰기는 `ENTRYPOINT` 없는 이미지의 CMD를 통째로 바꿔 Job이 시작되지 않는다.)
    - 미설정 로컬 환경에서는 `LocalAsyncJobDispatcher`가 백그라운드 코루틴으로 `executeJob`을 실행하며, 테스트에서는 `FakeAnalyzeJobDispatcher`로 제어한다.
    - 만약 `dispatcher.dispatch(jobId)` 호출 자체가 실패하면 방금 만든 `analysis_jobs` 행을 즉시 `status = "failed"`로 변경하고 `502 JOB_DISPATCH_ERROR`를 반환하여 사용자의 동시 1건 제한이 잠기지 않게 한다.
  - **타임아웃 정합 (리뷰 3번 반영):** `HttpGeminiClient`의 1회 요청 타임아웃을 **12분(`Duration.ofMinutes(12)`)**으로 두어 4회 시도(48분) + 대기(30s+60s+90s = 3분) 최악값이 **51분**이 되게 하고, `NoteService.executeJob`에 **54분 애플리케이션 타임아웃(`withTimeout(54분)`)**과 `withContext(NonCancellable)` 정리 블록을 걸어 Cloud Run Job의 60분 강제 종료 전에 반드시 DB에 `status = "failed"`가 기록되고 동시 1건 잠금이 풀리도록 보장한다.
- **비동기 Gemini 키 무효 감지 규칙 (`FR-KEY-5`, 리뷰 1번 반영):**
  - Gemini 호출은 비동기 `executeJob`에서 일어나므로 키가 401/403이거나 응답 본문에 `"API_KEY_INVALID"`를 포함한 400으로 거부되면 `analysis_jobs.status = "failed"`, `analysis_jobs.error = "PROVIDER_KEY_INVALID: Gemini API 키가 유효하지 않거나 요청이 거부되었습니다 (HTTP $status)."` 형태로 저장한다. `"API_KEY_INVALID"`가 없는 일반 400(비공개·길이 초과 영상)은 `GEMINI_API_ERROR`로 저장하여 키 캐시를 유지한다.
  - 프런트엔드는 `POST /notes/analyze`의 `412 NO_KEY`뿐 아니라 `GET /notes/jobs`(또는 `/jobs/{id}`) 폴링 결과에서 `status === 'failed'`이고 `error`가 `'PROVIDER_KEY_INVALID:'`로 시작하는 작업을 발견하면 즉시 `ulp:keys`의 `gemini` 캐시를 `null`로 무효화하고 키 재확인 안내를 표시한다.
- **태그 구분 (`GeminiSchemas.TAGS` vs `ALLOWED_NOTE_TAGS`):**
  - 분석 요청(`POST /api/v1/notes/analyze`)의 `tags`는 `scripts/schemas.py`와 동일한 6종(`화성`, `사운드 디자인`, `DAW/MIDI`, `리듬`, `편곡`, `믹싱`) 중 1~6개여야 한다.
  - 노트 수정(`PATCH /api/v1/notes/{noteId}`) 및 목록 필터(`GET /api/v1/notes?tag=`)는 `docs/03-api-spec.md` 8.3절·`docs/04-db-design.md` 4.3절에 따라 위 6종에 `"TAB"`을 더한 7종(`ALLOWED_NOTE_TAGS`)을 허용한다.
- **`diagramsSvg` 저장 규칙:**
  - `analysis.harmony.progressions` 배열의 각 진행(인덱스 `i`)에 대해 `instrument == "기타"`이면 `GuitarSvgRenderer.progressionSvg(chords) ?: ""`, 아니면 `KeyboardSvgRenderer.progressionSvg(chords) ?: ""`를 계산하여 `progressions`와 동일한 길이·인덱스의 `List<String>`으로 `notes.diagrams_svg`에 저장한다.
- **Notes API 7종 요청·응답 규격 (`docs/03-api-spec.md` 8절 정합, 리뷰 2번 반영):**
  - `POST /api/v1/notes/analyze` → `202 Accepted` `{ "jobId": "<uuid>", "status": "queued" }`. (동시 실행 1건 초과 시 `429 RATE_LIMITED` `retryAfter = 30`, UTC 당일 20건 초과 시 `429 RATE_LIMITED` `retryAfter = 1..86400`).
  - `GET /api/v1/notes/jobs` → `200 OK` `{ "jobs": List<AnalysisJobDto> }` (최근 20건, `createdAt DESC`).
  - `GET /api/v1/notes/jobs/{jobId}` → `200 OK` `AnalysisJobDto` (9개 필드: `id, url, tags, status, error, noteId, createdAt, startedAt, finishedAt`).
  - `GET /api/v1/notes?tag=` → `200 OK` `{ "notes": List<NoteSummaryDto> }` (14개 필드: `id, videoId, url, title, channel, tags, memo, headline, points, keywords, difficulty, model, createdAt, updatedAt`).
  - `GET /api/v1/notes/{noteId}` → `200 OK` `{ "note": NoteDetailDto }` (16개 필드: `NoteSummaryDto` 14개 + `analysis: JsonObject`, `diagramsSvg: List<String>`).
  - `PATCH /api/v1/notes/{noteId}` → 요청 `{ "title": String?(1..300자), "memo": String?(0..2000자), "tags": List<String>?(1..7개, ALLOWED_NOTE_TAGS) }` (셋 중 하나 이상 필수, 조건별 에러 메시지 4절 표에 전수 명시) → `200 OK` `{ "note": NoteDetailDto }`.
  - `DELETE /api/v1/notes/{noteId}` → `200 OK` `{ "ok": true }`.

- **배포 자동화 파일 및 `CLOUD_RUN_ANALYZE_JOB_URI`·IAM 규격:**
  - `.github/workflows/deploy-cloudrun.yml` 및 `scripts/deploy-cloudrun.sh` 추가.
