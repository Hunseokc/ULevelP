## 3. K2-2가 쓸 값

1. **`SessionService` 공용 헬퍼 함수 시그니처:**
   - `SessionService.formatSegment(a: BigDecimal?, b: BigDecimal?): String` — 둘 다 null이 아니면 `"m:ss–m:ss"` (en dash `\u2013`), 아니면 `""`. K2-2 곡 상세 세션 목록 매핑 시 재사용.
   - `SessionService.toMinutes(seconds: Int): Double` — 초 -> 소수 첫째 자리 반올림 분 (`Math.round(seconds / 60.0 * 10) / 10.0`).
   - `SessionService.rowToTakeDto(row: ResultRow): TakeDto` — `TakesTable ResultRow` -> `TakeDto` 12개 필드 변환. K2-2 `SongService.getDetail`의 `takes` 조회 시 그대로 사용.
2. **`log.html` DOM ID 구조:**
   - `#logTabs`: 상단 탭 바 (`#tab-log`, `#tab-songs`).
   - `#pane-log`: 기록 탭 패널 (`aria-labelledby="tab-log"`).
   - `#pane-songs`: 곡 보관함 탭 패널 (`aria-labelledby="tab-songs"`, 기본 `hidden`). K2-2에서 곡 목록 및 필터 렌더링.
   - `#pane-song-detail`: 곡 상세 패널 (기본 `hidden`). K2-2에서 `log.html?song={id}` 또는 곡 클릭 시 렌더링.

## 4. 명세와 달라진 점 및 겪은 문제

1. **Exposed innerJoin 명시적 컬럼 지정:**
   - `SessionsTable`과 `SongsTable` 간에 Exposed Table 정의 상 FK `.references()`가 선언되어 있지 않아 암시적 `SessionsTable innerJoin SongsTable` 호출 시 `IllegalStateException: Cannot join ... as there is no matching primary key/foreign key pair`가 발생함.
   - `SessionsTable.innerJoin(SongsTable, { SessionsTable.songId }, { SongsTable.id })`로 명시적 조인 컬럼을 지정하여 정상 해결함.
2. **PostgreSQL video_id 정규식 제약조건:**
   - `V1__init.sql`에 `CHECK (video_id ~ '^[A-Za-z0-9_-]{11}$')` 제약조건이 있어 `SessionApiTest`의 모의 `videoId`가 정확히 11자리(예: `"11111111111"`, `"aaaaaaaaaaa"`, `"dQw4w9WgXcQ"`)여야 함을 확인하고 테스트 데이터를 규격에 맞게 설정함.
3. **XSS 정적 검사 (d) 규칙 준수:**
   - `log.js`에서 녹음 재생 주소 할당 시 `audio.src = safeUrl(r.url)`로 감싸 `test/security.test.js`의 `(d)` 규칙을 완벽하게 통과함.
4. **Node VM sandbox URLSearchParams:**
   - `test/data.test.js`의 가상 환경 sandbox에 `URLSearchParams`를 전달하여 D11 테스트가 브라우저와 동일하게 동작하도록 함.
