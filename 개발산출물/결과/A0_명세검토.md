## 2. 이번 묶음에서 새로 정한 메뉴얼 항목 (사용자 확인 2026-10-30, 모두 추천안 승인)

### 2.1 API 응답·오류 코드
- `POST /api/v1/songs`: 새로 만들면 `201`, 같은 `videoId`가 이미 있으면 `200`(기존 곡 그대로).
- 없는·남의 곡/세션/녹음: 모두 `404 NOT_FOUND`(403 안 씀). 경로 id가 UUID가 아니어도 404.
- 새 오류 코드: `TAKE_TOO_LARGE`(413, 파일 50MB 초과), `STORAGE_UNAVAILABLE`(503, 저장소 미설정), `STORAGE_ERROR`(502, Supabase Storage 실패).
- 녹음 객체(`TakeDto`) 12개 필드: `id, sessionId, recordedAt, a, b, rate, durationSec, mime, sizeBytes, storage, storageKey, memo` — 업로드 응답·곡 상세·기간별 기록 공통.
- `POST /api/v1/practice/save` 응답 6개 키 고정: `ok, keep, sessionId, totalSeconds, minutes, pendingSeconds`.
- 곡 객체(`SongDto`) 14개 필드: `03` 3.1 예시 그대로(`id, title, artist, status, statusCode, videoId, pos, a, b, rate, lastDate, memo, totalSeconds, resumeUrl`).

### 2.2 서버 구성
- 환경변수 `SUPABASE_SECRET_KEY`(서버 전용, Storage 호출). 버킷 이름 `takes` 고정.
- 환경변수 `PUBLIC_APP_URL`(기본 `https://hunseokc.github.io/ULevelP/`) — `resumeUrl` 앞부분.
- `Application.module()`에 인자 추가: `videoMetaClient: VideoMetaClient = YoutubeOEmbedClient()`, `publicAppUrl: String = parsePublicAppUrl(env)`(K1-1), `storageClient: StorageClient? = SupabaseStorageClient.fromEnvOrNull()`(K1-2). 테스트는 가짜를 넣는다.
- 저장소 구현체는 `SupabaseStorageClient` 하나 + 테스트용 `FakeStorageClient`. 키가 없으면 녹음 업로드·재생 URL은 503(로컬 파일 구현체 없음).

### 2.3 프런트엔드
- K1-3에서 `practice.js`의 Apps Script(`pp-api`·`pp-key`) 저장 경로와 `#api=&k=` 해시 설정을 **완전히 제거**한다. → K4-2(노션 Push)까지 플레이어에서 노션으로 직접 저장되는 길이 없다(로그인 사용자는 서버 DB에 저장). `settings.js`의 `pp-api` 칸은 K4-3에서 정리.
- `window.ULData` 공개 함수(K1-3): `isLoggedIn`, `songs.list`, `songs.byVideo`, `songs.create`, `saveProgress`, `takes.upload`, `runLocalMigration`. 나머지(`sessions`, `takes.url/remove`, `songs.update/remove`)는 B 묶음에서 화면과 함께 추가.
- 기기 기록 키 `ulp:v:{videoId}` = `{ videoId, pos, a, b, rate, date }`(`date` 추가).

## 4. 남은 위험·확인할 것

- **Supabase 새 secret 키(`sb_secret_…`)와 `Authorization: Bearer` 헤더:** 명세는 `apikey`와 `Authorization`에 같은 값을 넣는다(supabase-js와 같은 방식). 게이트웨이가 Bearer의 비 JWT 값을 거부하면 K1-3 실환경 M4에서 401/403이 난다 → 그때는 레거시 `service_role` JWT로 바꿔 확인한다. K1-2 단위 테스트는 요청 모양만 검증한다.
- **GitHub Pages 배포본:** `apiBaseUrl`이 비어 있어 Pages에서 연 플레이어는 로그인해도 서버 저장이 안 된다(같은 Origin에 `/api`가 없음). Ktor로 서빙한 화면(localhost, Cloud Run)에서만 동작한다. KZ-1에서 `apiBaseUrl`·CSP `connect-src`를 함께 바꾼다.
- **테스트 메모리:** K1-2 T7은 50MB 배열을 몇 개 만든다. Gradle 테스트 JVM 기본 힙에서 OOM이 나면 `build.gradle.kts`를 고치지 말고 멈추고 보고한다.
- **K1-1 분량:** 엔드포인트 7개 + 테스트 26개로 묶음 A에서 가장 크다. 한 세션을 넘기면 진행 파일에 끝낸 테스트 번호를 적고 다음 세션에서 이어 간다.
