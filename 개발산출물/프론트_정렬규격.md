## 1. 작업 순서 (새 화면·배치 변경 모두)

1. **배치 약속을 먼저 쓴다.** 결과 파일(또는 진행 파일)에 아래 세 가지를 표로 적는다
   - 상태 목록: 이 화면이 보일 수 있는 데이터 상태(§5-1의 표준 상태 중 고른다)
   - 폭별 열 구성: 390·768·1150·1280에서 몇 열인지, 어느 칸이 어디로 가는지
   - 맞춤 그룹: 무엇을 무엇에 맞추는지(§3 형식 그대로)
2. **spec을 먼저 쓰고 실패를 본다.** `test/e2e/layout/<화면>.spec.js`(§5-2 본보기 20줄)를 만들고 지금 코드에서 돌린다. 고치는 작업이면 고칠 항목이 실패 문구로 나와야 하고, 새 화면이면 화면이 없어서 실패해야 한다
3. **구현한다.** 마크업에 `data-align-group`을 함께 쓴다. §2의 자주 깨지는 원인을 피한다
4. **검사를 통과시킨다.** 실패 0건. 경고는 지우거나, 남기면 결과 파일에 "경고 n건 — 사유"로 적는다
5. **스크린샷을 검토한다.** `LAYOUT_SHOTS=1`로 캡처(§6), 질문 목록으로 판정해 결과 파일에 표로 남긴다
6. **예외는 사유와 함께.** `data-layout-ignore`(§4)를 쓴 곳은 결과 파일에 목록으로 남긴다

> 순서를 지키는 이유: 생성형으로 화면을 만들면 "무엇을 무엇에 맞출지"를 정하지 않은 채 그럴듯한 CSS를 고른다. 약속을 먼저 쓰면 검사가 그 약속을 그대로 확인한다.

## 3. 배치 약속 — `data-align-group`

### 3-1. 형식

```
data-align-group="<그룹이름>:<맞출 선>[,<맞출 선>…][@<최소폭>]"
여러 그룹에 속하면 ; 로 잇는다:  "row1:top,bottom@821; btns:height"
```

| 맞출 선 | 판정(그룹 안 보이는 구성원끼리, 허용 오차 1px) |
| --- | --- |
| `top` · `bottom` | 윗선·아랫선 y가 같다 |
| `left` · `right` | 왼쪽선·오른쪽선 x가 같다 |
| `height` · `width` | 높이·폭이 같다 |
| `center-x` · `center-y` | 가로·세로 중심이 같다 (버튼을 칸 가운데에: 버튼과 칸을 같은 `center-x` 그룹에) |

- **그룹 이름:** 화면 안에서 고유한 짧은 영문(`row1`, `songBody`, `betterA`). 화면을 넘어 같은 이름을 써도 서로 상관없다(검사는 화면 단위)
- **나란할 때만 판정:** `top`·`bottom`·`height`·`center-y`는 구성원이 **위아래로 쌓이지 않았을 때**(세로 범위가 겹침 — 옆으로 나란하거나 한쪽이 다른 쪽 안에 있음), `left`·`right`·`width`·`center-x`는 **옆으로 나란하지 않을 때**(가로 범위가 겹침 — 쌓였거나 안에 있음) 판정한다. 좁은 폭에서 한 칼럼으로 쌓이면 자동으로 건너뛴다(마크업에 반응형 구간을 적지 않는다). 안에 든 구성원(글 칸과 그 안 링크의 `left`, 칸과 그 안 버튼의 `center-x`)도 판정된다
- **비교 기준:** 그룹의 첫 구성원(문서 순서)과 나머지 각각을 비교한다
- **`@<최소폭>`:** "이 폭 이상에서는 반드시 나란해야 한다". 그 폭 이상에서 쌓여 있으면 그 자체가 실패다(2열이어야 할 화면이 1열로 무너진 것을 잡는다). CSS 구간과 같은 값을 쓴다(예: 홈 2열 `@821` — `HomePage.module.css`의 `max-width: 820px` 바로 위)
- **상태에 따라 다른 약속:** React에서 조건부로 붙인다. `data-align-group={empty ? 'player:bottom@821' : undefined}`
- **구성원이 하나뿐인 그룹:** 경고(이름 오타일 가능성). 보이지 않는 구성원(접힘·`hidden`)은 세지 않는다

### 3-2. 예 (홈)

```tsx
<section id="weeklyStreakCard" data-align-group="top1:top,bottom@821">…</section>
<section id="recentSongCard"   data-align-group="top1:top,bottom@821">…</section>

<div id="recentSongBody">
  <img  data-align-group="songBody:top" … />
  <div  data-align-group="songBody:top; songText:left">
    <a  data-align-group="songText:left">이어서 구간 연습하기</a>
  </div>
</div>
```

### 3-3. 실패 문구

```
A1 top1 아랫선 차이 4px (#weeklyStreakCard ↔ #recentSongCard)
A1 top1 1280px에서 나란해야 하는데 쌓임
A1 songBody 윗선 차이 -6px (img ↔ div.recentInfo)
```

## 4. 예외 표시 — `data-layout-ignore`

```
data-layout-ignore="<규칙 ID>[ <규칙 ID>…]: <사유>"
예) data-layout-ignore="G3: 곡 제목은 한 줄 말줄임(목록 높이 고정)"
    data-layout-ignore="G1 G2: 재생 위치 표시 핀이 막대 밖으로 나오는 장식"
```

- 붙인 요소와 그 자손 전부에서 해당 규칙만 건너뛴다. `*`는 쓰지 않는다(전부 끄면 검사가 무의미)
- **사유가 비었거나 규칙 ID가 틀리면 G0 실패**다
- 예외를 쓴 곳은 그 step 결과 파일에 "예외 목록"(위치·규칙·사유)으로 남긴다. 리뷰 때 예외가 늘었는지 본다

## 5. 공통 검사 G0~G8

### 5-1. 대상과 판정 기준

- **폭:** 1280 · 1150 · 768 · 390 (높이 900). 1150은 컨테이너 최대폭(1120) 근처, 768은 태블릿, 390은 폰
- **테마:** 라이트 전체 + 다크는 화면당 1개(가장 데이터가 많은 상태 × 1280)
- **애니메이션:** `reducedMotion: 'reduce'`로 끄고, 글꼴 로드(`document.fonts.ready`) 뒤 판정
- **"보이는 요소":** `checkVisibility({ opacityProperty: true, visibilityProperty: true })`가 참이고 폭·높이가 1px 넘는 것. `.srOnly`(1px)·접힌 `details` 내용·`hidden`은 빠진다
- **검사 밖:** `svg` 안쪽 요소, `iframe`·`video`·`canvas`의 안쪽(상자 자체는 대상), `position: fixed` 요소의 G2
- **스크롤 상자 안:** `overflow: auto|scroll`인 조상 안의 요소는 그 상자 안에서만 판정한다(가로 스크롤 칩 목록이 화면 밖으로 나가는 것은 의도)

**카드 자동 인식** (G1·G6의 대상): 다음을 모두 만족하는 상자

1. 태그가 `html·body·button·a·input·select·textarea·label·summary·img·svg·video·iframe·canvas`가 아니고, `display`가 `inline`·`contents`·`none`이 아니다
2. 곡률 0(왼쪽 위 `border-radius` < 1px) — DESIGN.md 확정 규칙상 카드는 직각, 컨트롤은 필이라 이것으로 컨트롤을 거른다
3. **네 변 모두 테두리**(폭 ≥ 1px, 투명 아님)가 있거나, **배경색이 가장 가까운 조상의 배경색과 다르다**(목록 줄 구분선처럼 한 변만 있는 것은 카드가 아니다)
4. 크기 ≥ 48×32px

### 5-2. 규칙표

| ID | 수준 | 규칙 | 판정식 | 기준값 | 화면별 설정 |
| --- | --- | --- | --- | --- | --- |
| G0 | 실패 | 약속·예외 표기 오류 | `data-layout-ignore` 사유 없음·없는 규칙 ID, `data-align-group` 형식 오류·없는 선 이름 | — | 없음 |
| G1 | 실패 | 넘침 | 보이는 요소마다 **가장 가까운 카드** 조상을 찾아 요소 rect가 카드 rect 안인지. 요소와 카드 사이에 잘라내는 상자(`overflow`가 `visible` 아님)나 `fixed` 상자가 있으면 건너뛴다(그 상자가 대신 검사된다). `overflow: hidden|clip` 카드 안의 `img·video·picture·iframe`은 제외(사진 잘림 허용 — DESIGN.md). 넘친 요소의 자손은 다시 내지 않는다(바깥쪽 하나만) | 오차 0.5px | 없음 |
| G2 | 실패 | 형제 겹침 | 같은 부모의 보이는 흐름 안 형제(`position`이 `absolute·fixed`가 아니고 `display`가 `inline`이 아님)끼리 **보이는 범위**(자기 rect ∪ 흐름 안 자손 rect, 잘린 것 제외)가 겹치는지. 그리드 칸보다 넓은 자식이 옆 칸으로 넘어간 것도 여기서 잡힌다 | 겹친 폭·높이 둘 다 > 0.5px | 없음 |
| G3 | 실패 | 글자 잘림·넘침 | **글자를 직접 가진 요소**(빈칸 아닌 텍스트 노드 자식이 있음)에서 `scrollWidth > clientWidth + 1`, 또는 `overflow-y`가 `hidden|clip`이고 `scrollHeight > clientHeight + 1`(줄 수 제한). `input·textarea·select`·스크롤 상자 제외 | 1px | 의도한 말줄임만 `data-layout-ignore="G3: 사유"` |
| G4 | 실패 | 가로 스크롤 | `documentElement.scrollWidth − clientWidth > 0`. 실패 문구에 오른쪽으로 가장 많이 나간 요소 3개를 붙인다 | 0px | 없음 |
| G5a | 실패 | 금지 색 | 계산된 색(아래)이 금지 토큰의 RGB와 같음(알파 무시) | 채널별 ±1 | `forbidColors: ['--link']` (홈) |
| G5b | 경고 | 팔레트 밖 색 | 계산된 색의 RGB가 현재 테마 `tokens.css` 색 토큰 어느 것과도 다름(알파 무시 — `color-mix(… var(--ink) 12%, transparent)`는 통과). 그려지지 않는 값은 안 본다: 체크박스·라디오·범위 입력의 `color`, svg `line`의 `fill`(v1.2) | 채널별 ±1 | 없음 |
| G6 | 실패 | 처짐 | 카드의 흐름 안 첫 두 자식이 위아래로 쌓였을 때 `둘째.top − 첫째.bottom` | ≤ 24px | `sagMax`(기본 24) |
| G7a | 실패 | 터치 대상 최소 | `a[href]·button·input(hidden 제외)·select·textarea·summary·[role=button|tab|switch|checkbox|radio]·label[for]`의 폭·높이. 문장 속 링크(인라인이고 부모에 글자가 직접 있음)는 제외. **24px 미만이어도 WCAG 2.5.8 간격 예외**를 만족하면 통과: 대상 상자 중심에 지름 24px 원을 그려 다른 대상의 rect나 다른 작은 대상의 원과 겹치지 않음(v1.1) | ≥ 24px (WCAG 2.2 2.5.8) | 없음 |
| G7b | 경고 | 터치 대상 권장 | 같은 대상, **390·768폭에서만** 높이 | ≥ 44px (앱 전환 대비, iOS 44pt) | 없음 |
| G8 | 경고 | 간격 스케일 | 흐름 안 형제(인라인 제외)가 2개 이상인 상자에서 이웃 간격(세로로 쌓인 것은 `top − 이전 bottom`, 같은 줄은 `left − 이전 right`, 반올림)이 스케일 밖이거나, 같은 상자 안 같은 방향 간격이 두 가지 이상(들쭉날쭉) | 스케일 `0 2 4 6 8 10 12 14 16 20 24 28 32 40 48 56 64` | `spacing: { scale, level: 'fail' }`로 화면별 강화(설정 화면 6·12·16) |

**G5에서 보는 색:** 글자를 직접 가진 요소와 폼 컨트롤의 `color`, 알파 > 0인 `background-color`, 폭 ≥ 1px이고 `border-style`이 `none`이 아닌 변의 `border-*-color`, 밑줄이 있을 때 `text-decoration-color`, `svg` 도형의 `fill`·`stroke`(`none`·`url()` 제외). 계산값이 `color(srgb …)` 형식으로 나오면 0~255로 바꿔 비교한다. 배경 그라디언트(`background-image`)는 보지 않는다.

**수준:** 실패는 테스트를 깨뜨린다. 경고는 테스트를 깨뜨리지 않고 annotation(`layout-warn`)과 첨부 파일(`layout-warnings.txt`)로 남는다. `LAYOUT_STRICT=1`이면 경고도 실패로 돈다(점검 step에서 전체 목록을 볼 때).

**A1(배치 약속, §3)은 실패 수준이다.**

### 5-3. 실패 문구 형식

`<규칙 ID> <대상> <무엇이> <얼마나>` — 한 줄, 수치는 반올림한 px. 대상 표기는 `#id` → `[그룹이름]` → `태그.모듈클래스(해시 뺀 이름)` + 글자 앞 16자 순.

```
G1 #recentNoteEmpty 밖으로 div.recentPlaceholder 넘침 (오른쪽 +4px)
G2 div.recentBody 안 div.recentPlaceholder ↔ div.recentInfo 4px 겹침
G3 p.progSub "코드 진행 · 출처 유…" 말줄임 (238>219)
G5a a "기록 보기" 금지 색 --link (color)
G6 #recentSongCard 제목 아래 63px 빔 (기준 24)
```

같은 문구는 한 번만 낸다. 테스트 하나 = 화면 × 상태 × 폭, 결과는 `expect(fails).toEqual([])`라 실패하면 목록 전체가 한 번에 보인다.

## 7. 데이터 상태 장치 — `test/e2e/support/mock-app.js`

가짜 인증·API 응답을 한 곳에 둔다. spec 파일끼리 함수를 export하지 않는다(체크리스트 규칙) — 공용은 `support/`에만.

### 7-1. 표준 상태

| 상태 키 | 뜻 | 만드는 법 |
| --- | --- | --- |
| `guest` | 비로그인 빈 화면 | 아무것도 안 함 |
| `guestLocal` | 비로그인 + 기기 저장 곡·노션 링크 | `localStorage` 미리 넣기 |
| `user` | 로그인 + 빈 데이터 | 가짜 세션 + `me` |
| `userData` | 로그인 + 긴 제목 곡 5개·노트·세션 | 가짜 세션 + 고정 데이터 |

화면마다 해당하는 상태만 고른다(로그인 필수 화면이면 `user`·`userData`). 필요하면 화면 spec에서 추가 상태를 정의한다(같은 `mockApp` 옵션으로).

### 7-2. 모양

```js
// test/e2e/support/mock-app.js
await mockApp(page, {
  auth: 'user',                 // 'guest' | 'user'
  me: { /* DEFAULT_ME 위에 덮어쓴다 */ },   // 나중에 tier·credits(M1-1)·locale(L1-1)을 여기 덧붙인다
  sessionUser: { email, user_metadata },    // 가짜 Supabase 세션 사용자(xss가 공격 문자열을 넣는 곳)
  songs: [], notes: [], sessions: { calendar: [], sessions: [] }, songDetail, takeUrl,
  local: { 'ulp:notion-practice': '…' },   // localStorage 미리 넣기
  routes: [[match, handler], …],            // 화면 전용 추가 응답(나중 등록이 먼저 매칭)
});
FIXTURES.longSongs(n), FIXTURES.note, LONG_TITLE   // 긴 제목 고정 데이터
```

- **옵션으로 준 API만 응답한다**(`songs`·`notes`·`sessions`·`takeUrl`; `me`는 `auth: 'user'`면 항상). 나머지 `/api/v1/*`는 `unknownApi`: `'empty'`(기본) = `{}` 200, `'pass'` = 실제 서버로(xss가 예전 동작을 지키려고 씀)
- HTML의 `integrity` 제거, supabase-js CDN 스텁(`guest`면 세션 없음, `window.__supabaseAuthListener`에 인증 콜백 보관), YouTube는 IFrame API 스텁, ytimg는 빈 이미지. Google Fonts는 막지 않는다(실제 글꼴로 판정 — 느리면 `page.goto` 타임아웃이 날 수 있음)
- 표준 상태는 `STATES`(§7-1 키 → `mockApp` 옵션)로 export한다. 화면 전용 상태는 `layoutSuite`의 `states`에 `{ name, mock }`으로 준다
- `xss.spec.js`의 `setupMockAuthAndApi(page, opts)`는 이름·인자를 그대로 두고 안에서 `mockApp`을 부른다(감시 스크립트 주입만 그 파일에 남김)

## 8. 화면 spec — `test/e2e/layout/<화면>.spec.js`

```js
// test/e2e/layout/home.spec.js
'use strict';
const { layoutSuite } = require('../support/layout-check');

layoutSuite({
  name: 'home',
  path: '/index.html',
  states: ['guest', 'guestLocal', 'userData'],
  ready: async (page, state) => {             // 판정 전에 기다릴 것
    await page.locator('#weeklyStreakCard').waitFor();
    if (state === 'userData') await page.locator('#recentNoteBody').waitFor();
  },
  options: { forbidColors: ['--link'] },      // 화면별 설정(§5-2 마지막 칸)
  dark: 'userData',
});
// 화면 전용 추가 검사(예: 모듈 CSS에 var(--link) 없음)는 이 파일 아래에 일반 test()로
```

- **필 글자 한 줄 검사(v1.3):** `settings.spec.js`의 `collectWrappedPills` — `main button, main a.pillBtn, main a.ghostBtn` 각각의 지금 높이가 `white-space: nowrap`으로 잰 높이 + 1px보다 크면 "두 줄" 실패. 접힌 `details`는 모두 펼쳐서 guest·user × 390·768·1280으로 잰다. 옛 문구(`🔑 무료 API 키 발급 가이드 (1분)`)로 되돌리면 390에서 `#btnOpenGeminiModal … 두 줄(높이 75px > 한 줄 48px, 폭 270px)`로 실패하는 것을 확인했다. 다른 화면에 버튼 문구가 긴 필이 생기면 이 함수를 그 spec에 옮겨 쓴다(공통 검사 G 규칙으로 올릴지는 M2·L1-2에서 다른 화면 오탐을 본 뒤 정한다)

- `layoutSuite`가 상태 × 폭 테스트와 다크 1개를 만든다. legacy 모드(`#root` 없음)면 skip
- 테스트 이름: `FT home userData 1280px`
- 검사 함수만 쓰고 싶으면 `checkLayout(page, options) → { fails, warns, cards }` (`cards` = 자동 인식된 카드 표기 목록, 인식 확인용)
- 모든 상태에 덧붙일 응답은 `layoutSuite({ mock: { routes: [...] } })`

### 8-1. 실행

```bash
npm run build && ULP_UI=spa node server.js            # 별도 터미널(win은 Git Bash)
npx playwright test test/e2e/layout/                  # 전 화면
npx playwright test test/e2e/layout/home.spec.js      # 한 화면
LAYOUT_STRICT=1 npx playwright test test/e2e/layout/  # 경고까지 실패로
LAYOUT_SHOTS=1  npx playwright test test/e2e/layout/home.spec.js   # 스크린샷 검토용 캡처
```

- CI는 기존 `e2e-security` 작업의 `npm run test:e2e`가 `test/e2e/` 아래를 전부 돌리므로 따로 추가하지 않는다(spa 행렬에서 돌고 legacy 행렬에서는 skip). FT-4 확인(`결과/FT-4_규칙연결.md`): `playwright.config.js` `testDir: './test/e2e'`, PR #74 CI spa 189 passed 중 128개가 layout. `layoutSuite`가 만든 테스트는 위치가 `support/layout-check.js`로 찍혀 CI 로그에 `layout/` 문자열이 안 보일 수 있다 — 개수는 `npx playwright test --list test/e2e/layout/`로 본다
- 문서(`*.md`·`개발산출물/`)만 바꾼 PR은 CI `changes` 작업이 E2E를 건너뛴다. 화면·spec을 바꾼 PR에서만 layout 검사가 돈다
- `test/e2e/layout.spec.js`(가로 스크롤, legacy 포함 9개 화면)는 레거시를 지울 때까지 둔다. React 화면의 가로 스크롤은 G4가 같이 본다

### 8-2. 알려진 실패 — `known` (v1.2)

점검만 하고 아직 고치지 않는 실패는 `layoutSuite({ known: [{ match, why }] })`로 적는다.

```js
known: [{ match: /^G6 #logGuest 제목 아래 /, why: '원인 한 줄 + 고칠 step(FT-3-chords, M2-n 등)' }],
```

- 실패 문구가 `match`에 맞으면 테스트는 통과하고 annotation `layout-known` + 첨부 `layout-known.txt`로 남는다. **맞지 않는 실패는 그대로 실패**(새로 깨진 것은 잡힌다)
- `match`는 규칙 ID와 대상 표기까지만 쓰고 px 수치는 넣지 않는다(폭마다 다르다). 대상이 하나로 정해지게 쓴다(`^G1 .* 넘침` 같은 넓은 패턴 금지)
- `LAYOUT_STRICT=1`이면 알려진 실패도 실패로 나온다(전체 목록 보기)
- 고치는 step은 해당 항목을 지우는 것으로 끝낸다. 예외(`data-layout-ignore`)와 다르다: 예외는 "의도라서 영구히 안 본다", `known`은 "문제인데 아직 안 고쳤다"

## 9. 이 규격을 바꿀 때

- 기준값·규칙 수준을 바꾸면 이 파일 버전과 `결과/`의 해당 step 파일에 "바꾼 값 · 이유 · 영향받은 화면"을 적는다
- 오탐 때문에 규칙을 끄지 않는다. 판정식을 좁히거나(예: 대상 태그 제외) 예외 표시로 처리하고 사유를 남긴다
