## 4. 세션 진행 방법 (모든 step 공통)

1. `git checkout main && git pull` — 앞 step의 PR이 머지됐는지 확인한다(머지 안 됐으면 사용자에게 알리고 멈춘다).
2. 이 파일과 해당 step의 **입력 파일만** 읽는다.
3. 브랜치 `step/<step ID>` (예: `step/P0-1`)를 만들고 작업한다. 3개 이상 파일 변경·스키마/API 변경도 이 표에 승인된 범위 안이면 따로 묻지 않는다. 표 범위를 벗어나면 먼저 묻는다.
4. 완료 기준을 **실제로 실행해서** 확인하고, 출력(끝 몇 줄)을 결과 파일에 붙인다.
5. 결과 파일을 쓴다. 다음 step에 필요한 값·결정·문서와 달라진 점을 모두 적는다.
6. 이 파일의 3절 상태 칸, 6절 겪은 문제, 7절 다음 세션 시작 지시를 고친다.
7. 커밋(`feat|fix|test|docs(scope): 요약`) → push → `main` 대상 PR. 머지는 사용자가 한다. 한 줄로 알린다: `PR #n — step/<ID> → main 머지`.
8. 마지막 답변 끝에 7절과 같은 다음 세션 시작 멘트와 권장 effort를 적는다.

공통 명령(R1에서 확정하면 여기를 고친다):
- 테스트: `npm test` (코드 연습실·순수 함수), `npx supabase test db` (DB)
- 로컬 화면: `npm start` → `http://localhost:3000`
- 로컬 DB: `npx supabase start` / `npx supabase db reset` / `npx supabase stop`

step 사이에 넘길 원본 데이터(노션 zip 샘플, 테스트 CSV 등)는 `개발산출물/자료/`에 둔다. scratchpad는 다음 세션에 사라지므로 쓰지 않는다. 비밀 값(DB 비밀번호, 서비스 키, 노션 토큰, Gemini 키)은 이 폴더에 절대 쓰지 않는다.

## 6. 겪은 문제

- 2026-10-29: ULevelP 첫 push의 CI에서 `Deploy to GitHub Pages`만 실패(`Get Pages site failed ... Not Found`). 저장소에 Pages가 꺼져 있어서다. R1에서 사람이 켠다. test·docker 작업은 통과.
- 저장소 루트 `CLAUDE.md`의 "`.env`에 `COMPOSE_FILE=compose.yml:compose.dev.yml`" 규칙은 다른 프로젝트(StockMind)용이다. 이 저장소에는 `compose.yml`이 없고 `docker-compose.yml`만 있으니 적용하지 않는다.
- `DESIGN.md`는 `.gitignore`에 들어 있는 개인 파일이라 이 저장소에 없다. 화면 step은 `public/styles.css`·`site.css` 토큰과 docs/03 8장 요약을 기준으로 한다(사용자가 파일을 넣어 주면 그것을 따른다).
