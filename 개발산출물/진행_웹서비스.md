## 4. 세션 진행 방법 (모든 step 공통)

1. `git checkout main && git pull` — 앞 step의 PR이 머지됐는지 확인한다(머지 안 됐으면 사용자에게 알리고 멈춘다).
2. 이 파일과 해당 step의 **입력 파일만** 읽는다.
3. 브랜치 `step/<step ID>` (예: `step/P0-1`)를 만들고 작업한다. 3개 이상 파일 변경·스키마/API 변경도 이 표에 승인된 범위 안이면 따로 묻지 않는다. 표 범위를 벗어나면 먼저 묻는다.
4. 완료 기준을 **실제로 실행해서** 확인하고, 출력(끝 몇 줄)을 결과 파일에 붙인다.
5. 결과 파일을 쓴다. 다음 step에 필요한 값·결정·문서와 달라진 점을 모두 적는다.
6. 이 파일의 3절 상태 칸, 6절 겪은 문제, 7절 다음 세션 시작 지시를 고친다.
7. 커밋(`feat|fix|test|docs(scope): 요약`) → push → `main` 대상 PR. 머지는 사용자가 한다. 한 줄로 알린다: `PR #n — step/<ID> → main 머지`.
8. 마지막 답변 끝에 7절과 같은 다음 세션 시작 멘트와 권장 effort를 적는다.

공통 명령(R1에서 확정. 자세한 값은 `결과/R1_환경.md`):
- Supabase CLI는 버전을 고정해 npx로 부른다: `npx --yes supabase@2.122.0 …` (아래에서는 `SB`로 줄임)

- 원격 DB: `supabase link` 없이 `--db-url`로 (URL 만드는 법은 `결과/R1_환경.md` 4절)
- `gh` 명령에는 `-R Hunseokc/ULevelP`를 붙인다(원격이 둘이라 upstream을 고를 수 있음)

step 사이에 넘길 원본 데이터(노션 zip 샘플, 테스트 CSV 등)는 `개발산출물/자료/`에 둔다. scratchpad는 다음 세션에 사라지므로 쓰지 않는다. 비밀 값(DB 비밀번호, 서비스 키, 노션 토큰, Gemini 키)은 이 폴더에 절대 쓰지 않는다.

- 2026-10-29 (R1): `supabase start`가 `DbConnectError ... password 인증 실패 (28P01)`로 실패. Supabase CLI가 루트 `.env`를 읽고 `SUPABASE_<섹션>_<키>`로 `config.toml`을 덮어쓰는데, 원격용 `SUPABASE_DB_PORT=5432`가 로컬 `[db] port = 54322`를 덮어써서 5432의 Windows Postgres(`postgresql-x64-16`)에 붙었다. 해결(사용자 승인): `.env` 이름을 `REMOTE_DB_*`로 바꿈. 이후 우회 없이 `status`·원격 `migration list` 동작 확인.
- Supabase MCP는 이 프로젝트에 권한이 없다(`You do not have permission`). 원격 확인은 CLI `--db-url`과 로컬 DB 컨테이너의 psql로 한다.
- 저장소 루트 `CLAUDE.md`의 "`.env`에 `COMPOSE_FILE=compose.yml:compose.dev.yml`" 규칙은 다른 프로젝트(StockMind)용이다. 이 저장소에는 `compose.yml`이 없고 `docker-compose.yml`만 있으니 적용하지 않는다.
- **같은 Origin 문제:** guitar-practice와 ULevelP는 둘 다 `hunseokc.github.io`라서 localStorage를 공유한다(Origin은 경로를 보지 않는다). guitar-practice는 `pp-key`(Apps Script 공유 비밀)와 `sn-token`(GitHub 토큰)을 localStorage에 둔다. 또 ULevelP가 복사본이라 키 이름까지 같아서 두 앱이 서로의 설정·기기 기록을 그대로 읽는다(→ D19로 분리). 대응: D18로 guitar-practice의 오래 사는 비밀을 브라우저에서 뺀다. 남는 위험은 "XSS가 생기면 그 순간의 로그인 세션을 빼앗김"이고, 이건 Vault로 막는 문제가 아니라 XSS 자체를 막는 문제다(두 저장소 모두 외부 텍스트는 `esc()`/`textContent`, `href`에는 `https:`만). ## 8. guitar-practice와 겹치는 기능 반영 규칙 (D17)

두 저장소는 히스토리를 같이 쓴다(guitar-practice `147ea95`에서 갈라짐). 그래서 **안 바뀐 파일은 git으로 그대로 옮길 수 있고**, 바뀐 파일만 문서를 보고 손으로 옮기면 된다. 자동으로 서로 반영하는 장치(서브모듈, 공용 패키지)는 빌드 도구 없는 구조(D9)에서 얻는 것보다 관리 부담이 커서 두지 않는다.
