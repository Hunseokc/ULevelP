# 주니어 체크리스트 (리뷰 지적 누적)

PR을 올리기 전에 모든 항목으로 diff를 점검한다. 작은 판단이 필요할 때도 이 파일을 기준으로 삼는다. 운영 방법은 [협업_시니어주니어.md](협업_시니어주니어.md) 6·7절에 있다.

- **형식:** `- [ ] 규칙 — 출처(PR #n 리뷰 k번) — 확인 방법`
- 지적을 그대로 옮기지 않고, 다음 step에도 쓸 수 있게 **일반화**해서 적는다.
- 같은 종류의 지적이 다시 나오면 새 항목을 만들지 않고, 그 항목 앞에 **`중요`** 를 붙이고 출처를 덧붙인다.

## API·호환
- [ ] 기존 API(`/api/chord` 등 계산 API)의 응답·에러 모양을 바꾸지 않는다. 새 형식(`{ ok, source, status, code, message }`)은 `/api/v1`에만 쓴다 — PR #8 리뷰 1번 — 기존 API 테스트가 원래 모양(`{error}`, 404의 `apis`)을 검사하는지 확인
- [ ] 없는 경로의 404 처리는 인증보다 앞에 둔다(토큰 없이도 404) — PR #8 리뷰 9번 — 토큰 없이 없는 경로를 curl로 호출해 401이 아니라 404가 나는지 확인
- [ ] 다른 앱(`guitar-practice`) 데이터로 대신 채워 보여 주지 않는다. 조회는 `app_id = 'ulevelp'`로 한정한다 — PR #8 리뷰 10번 — 쿼리에 `app_id` 조건이 있는지 확인

## 인증·데이터 수명
- [ ] 삭제한 사용자가 남은 토큰으로 다시 생성되지 않게 막는다(삭제 기록 확인 또는 Auth 사용자 삭제) — PR #8 리뷰 2번 — 삭제 후 같은 토큰으로 호출하는 테스트
- [ ] 로그아웃·계정 전환·`/me` 실패 시 이전 사용자 상태(`currentMe`, `ulp:keys`)를 초기화한다 — PR #9 리뷰 4번 — uid가 바뀌는 경로마다 초기화 코드가 있는지 확인
- [ ] 로그아웃은 이 브라우저만 한다(`signOut({ scope: 'local' })`) — PR #9 리뷰 5번 — `signOut` 호출 인자 확인

## 에러 처리
- [ ] 비동기 호출(`await`)은 실패 경로를 처리하고, 사용자에게 보이는 반응(메시지, 이동)을 남긴다. 빈 `catch`나 삼킨 rejection은 쓰지 않는다 — PR #9 리뷰 6번, 2번 — `catch`마다 처리 내용이 있는지 확인
- [ ] 외부 조회(JWKS, HTTP)가 실패해도 매 요청 재시도하지 않는다. 실패 시각을 기록하고 재시도 간격을 둔다 — PR #8 리뷰 3번 — 실패 테스트에서 두 번째 요청이 외부 호출을 하지 않는지 확인
- [ ] 목록 중 항목 하나가 깨져도 전체를 버리지 않는다(항목별 `runCatching`) — PR #8 리뷰 5번 — 불량 항목 1개를 넣은 테스트

## 성능·동시성
- [ ] suspend 흐름 안의 blocking 호출(HTTP, 파일)은 `withContext(Dispatchers.IO)`로 감싼다 — PR #8 리뷰 4번 — `send`/`execute`/파일 I/O 호출 위치 확인
- [ ] 요청마다 반복되는 쓰기(INSERT/UPDATE)를 만들지 않는다. 존재를 먼저 확인하거나 한 번만 실행한다 — PR #8 리뷰 8번 — 같은 요청을 두 번 보내고 쓰기 쿼리 횟수 확인
- [ ] 같은 API를 이벤트마다 중복 호출하지 않는다(필요한 이벤트·값이 바뀔 때만) — PR #9 리뷰 8번 — 페이지 로드 1회에 네트워크 호출 횟수 확인

## 테스트
- [ ] 단언을 항상 참인 조건으로 바꾸지 않는다(`A || B`에서 B가 이미 보장되는 경우 등). 테스트를 고치면 이유를 결과 파일에 적는다 — PR #8 리뷰 6번 — 단언이 실패할 수 있는 입력이 있는지 따져 본다
- [ ] 테스트 DB는 Docker 임시 컨테이너만 쓴다. 외부·공유 DB를 테스트에 연결하지 않는다 — K0-2 리뷰 — 테스트 설정에 원격 DB URL이 없는지 확인

## 보안·설정
- [ ] 암호화 데이터는 소유자 문맥(AAD: `userId:appId:provider`)에 묶는다 — K0-2 리뷰 — 다른 문맥으로 복호화하면 실패하는 테스트
- [ ] 운영 허용 목록(CSP, CORS)에 개발용 주소(`127.0.0.1`, `localhost`)를 넣지 않는다 — PR #9 리뷰 9번 — HTML meta와 `security.test.js`의 상수 확인
- [ ] 외부 주소(API 출처)를 바꾸면 config와 CSP `connect-src`를 함께 바꾼다 — PR #9 리뷰 2번 — 브라우저 콘솔에서 CSP 위반 0건 확인
- [ ] 공개 값(publishable 키)과 비밀 값을 구분한다. 공개 값은 config에 넣고, 비밀 값은 env에서만 읽는다 — PR #9 리뷰 3번 — diff에 비밀 키 형식 문자열이 없는지 확인
- [ ] 리디렉션·복귀 URL에서 hash·쿼리 토큰을 정리한 뒤 넘긴다 — PR #9 리뷰 1번 — 해시가 있는 페이지에서 로그인 왕복 확인

## 범위·검증·기록
- [ ] **중요** 완료 기준을 실제로 실행하지 않았으면 "완료"로 표시하지 않는다. 사람이 할 일이 남았으면 상태를 `진행`으로 두고 남은 일을 적는다 — PR #9 리뷰 7번 — 결과 파일에 실행 출력이 붙어 있는지 확인
- [ ] 작업과 무관한 파일(개인 백업, 메모)과 쓰지 않는 코드(DTO 등)를 커밋하지 않는다 — PR #8 리뷰 7번 — `git status`·`git diff --stat`으로 명세 파일 목록과 비교
- [ ] 의존성은 보안 패치가 반영된 고정 버전을 쓴다 — K0-2 리뷰(pgjdbc 42.7.7) — `build.gradle.kts` 버전 확인
- [ ] iframe(노션 임베드) 같은 다른 실행 환경에서도 주요 흐름(로그인 등)이 이어지는지 확인한다 — PR #9 리뷰 10번 — 임베드 분기 코드에서 다음 동작이 끊기지 않는지 확인
