# 보안 정리: 브라우저(localStorage)에 있는 비밀 값과 옮기는 방법

작성 2026-10-29 (R1 세션에서 사용자 질문으로 정리). 두 저장소(ULevelP, guitar-practice)에 같이 적용한다.
guitar-practice 작업은 **이 파일 5절 + `결과/R2_설계개정.md`의 공용 스키마 절**만 읽고 시작할 수 있게 쓴다.

## 1. 결론

- 지금 브라우저에 있는 비밀 값은 둘이다: `pp-key`(중계 서버를 부르는 공유 비밀번호)와 `sn-token`(GitHub 토큰). **노션 토큰 원문은 브라우저에 없다**(Apps Script 속성 `NOTION_TOKEN`).
- 둘 다 설계상 브라우저에 있어야 하는 값이 아니다. "로그인 없는 개인용 정적 페이지"로 만들어서 공유 비밀번호로 대신했을 뿐이다.
- 고칠 방향: 브라우저는 **Supabase 로그인 세션만** 갖고, 중계 서버(ULevelP는 Edge Function, guitar-practice는 Apps Script)가 그 세션으로 사용자를 확인한 뒤 서버 쪽에 둔 키를 쓴다(D16·D18).
- 고친 뒤에도 남는 위험: Supabase 세션 토큰(`sb-<ref>-auth-token`)은 localStorage에 있어야 한다. 이 위험은 **XSS 자체를 막아서**(D20: `esc`/`textContent`, `safeUrl`, CSP, SRI → X1·X2 테스트) 줄인다. Vault로 막을 수 있는 문제가 아니다.

## 2. 지금 브라우저에 있는 값 (두 저장소 코드가 같음, guitar-practice `147ea95` 기준)

| localStorage 키 | 정체 | 넣는 곳 | 읽는 곳 | 진짜 비밀이 있는 곳 |
| --- | --- | --- | --- | --- |
| `pp-api` | Apps Script 웹 앱 주소 | `settings.html` 노션 연결 칸, `practice.html#api=` | `site.js` `notion.url()`, `practice.js` `api.url()` | — (비밀 아님) |
| `pp-key` | 중계 서버 공유 비밀번호 `PRACTICE_KEY` | `settings.html`, `practice.html#k=` | `site.js` `notion.key()`, `practice.js` `api.key()` → 요청 본문 `{ key }` | Apps Script가 `safeEqual(req.key, PRACTICE_KEY)`로 확인한 뒤 `NOTION_TOKEN` 사용 |
| `sn-token` | GitHub fine-grained 토큰(이 저장소 + Actions 쓰기) | `settings.html` 학습 노트 칸 | `site.js` `gh.call()` → `notes.html`이 `analyze.yml` dispatch·실행 목록 조회 | 워크플로가 저장소 Secrets `GEMINI_API_KEY`·`NOTION_TOKEN` 사용 |
| `sn-repo` | 저장소 이름 | `settings.html` | `gh.repo()` | — |

`sn-token`은 배포물에 들어 있지 않다. 각자 SETTING에서 자기 브라우저에 넣는 값이다. 방문자가 소유자 토큰을 받는 일은 없다.

## 3. 훔쳤을 때 할 수 있는 일

전제: `hunseokc.github.io`는 두 저장소가 **같은 Origin**이라 localStorage를 같이 쓴다. 두 저장소 어느 페이지든 XSS가 한 곳만 있으면 소유자 브라우저의 값을 전부 읽는다.

| 값 | 공격자가 할 수 있는 일 | 수명 | 막는 법 |
| --- | --- | --- | --- |
| `pp-key` (+`pp-api`) | 중계 서버로 소유자 노션 연습 곡·기록 DB 읽기·쓰기 | 영구(직접 바꾸기 전까지) | `PRACTICE_KEY` 교체 |
| `sn-token` | `analyze.yml` 실행 → 소유자 Gemini 요금 사용, 노션 노트 DB에 글 생성, 실행 취소·재실행. Secrets 원문은 못 읽고 워크플로 파일도 못 바꿈(Actions 쓰기 권한만일 때). 입력은 `env:`로만 넘어가서 명령 주입은 없음 | 토큰 만료일까지 | GitHub에서 토큰 폐기 |
| (고친 뒤) Supabase 세션 | 그 사용자로서 RLS가 허락하는 본인 데이터 읽기·쓰기, 중계 서버 호출. **키 원문은 못 얻음** | access 1시간, refresh는 회전 + 재사용 감지 | 로그아웃·세션 폐기, XSS 방어(D20) |

## 4. 목표 구조

```
브라우저 ── Supabase 세션(access 토큰) ──▶ 중계 서버 ── 토큰 확인 → user_id
                                              └─ user_id로 서버 쪽 키를 꺼내 노션/Gemini/GitHub 호출
```

| | ULevelP | guitar-practice |
| --- | --- | --- |
| 중계 서버 | Supabase Edge Function | Apps Script (그대로) |
| 사용자 확인 | Edge Function이 JWT 확인 | Apps Script가 `GET https://<ref>.supabase.co/auth/v1/user` (헤더 `Authorization: Bearer <토큰>`, `apikey: <publishable 키>`)로 `user.id` 확인. 결과는 `CacheService`에 토큰 해시 → user_id로 토큰 만료까지 캐시 |
| 노션 키 | Vault (사용자별, `(user_id, app_id='ulevelp')`) | Vault (사용자별, `(user_id, app_id='guitar-practice')`). Apps Script가 service role로 `get_*_key` RPC를 불러 꺼내고 `CacheService`에 캐시 (키캐싱 가이드 GAS 방식) |
| Gemini | Vault, Edge Function `analyze-video` (P5) | 지금처럼 GitHub Actions + 저장소 Secrets (소유자 키) |
| GitHub 토큰 | 없앰(P5-3에서 `gh`·`analyze.yml` 삭제) | 브라우저에서 빼서 Apps Script 속성 `GH_TOKEN`으로. Apps Script에 `/analyze` 경로 추가, **소유자 user_id만** 허용(워크플로가 소유자 키를 쓰므로) |
| 브라우저에 남는 것 | Supabase 세션, `ulp:*` 설정·기기 기록 | Supabase 세션(ULevelP와 공유), `pp:v:*` 기기 기록, `pp-api`(주소, 비밀 아님) |

테이블·RPC 이름과 권한(`get_*_key`는 service_role 전용, `save_*_key`는 본인만)은 **R2에서 확정**해 `결과/R2_설계개정.md` 공용 스키마 절에 적는다. 아래 5절의 `get_*_key`는 그 이름으로 바꿔 읽는다.

## 5. guitar-practice 적용 체크리스트

guitar-practice 저장소에서 별도 진행 파일로 한다(D18). 순서대로, 각 줄이 한 커밋 정도.

| # | 할 일 | 바꿀 파일 | 확인 |
| --- | --- | --- | --- |
| G1 | Supabase 로그인 추가: ULevelP P0-5의 `auth.js`·`config.js`를 가져와 같은 프로젝트로 로그인. 세션 키 `sb-<ref>-auth-token`은 그대로(두 앱이 로그인 공유) | `public/auth.js`, `public/config.js`, 각 HTML | ULevelP에서 로그인하면 guitar-practice도 로그인 상태 |
| G2 | Supabase Auth Redirect URLs에 `https://hunseokc.github.io/guitar-practice/**` (ULevelP docs/03 3장에 이미 적힘) | Supabase 대시보드 **(사람)** | 로그인 후 원래 페이지로 돌아옴 |
| G3 | SETTING에 노션 키 등록 칸: `save_*_key` RPC(`app_id='guitar-practice'`)로 저장, 저장 후 끝 4자리만 표시 | `settings.html`, `site.js` | 응답·네트워크 탭에 키 원문이 다시 안 내려옴 |
| G4 | Apps Script: `PRACTICE_KEY` 확인 → Supabase 토큰 확인(4절)으로 바꿈. 요청 본문 `{ key }` → `{ token }` (Apps Script는 커스텀 헤더를 못 받으므로 본문으로) | `apps-script/Code.gs` | 로그아웃 상태 요청 거부, 다른 사용자 토큰으로는 그 사용자 키만 사용 |
| G5 | Apps Script: `NOTION_TOKEN`·`SONGS_DB`·`SESSIONS_DB` 속성 → user_id로 Vault에서 꺼내기(service role 키는 Apps Script 속성 `SUPABASE_SERVICE_KEY`) + `CacheService` 캐시, 키 삭제·오류 때 캐시 지움 | `apps-script/Code.gs` | 키 바꾼 뒤 캐시 무효화 확인 |
| G6 | 플레이어가 `pp-key` 대신 세션 토큰을 보냄. `#k=` 주소 처리 삭제 | `public/practice.js`, `public/site.js` | `pp-key` 없이 저장 동작 |
| G7 | GitHub 토큰 이동: Apps Script 속성 `GH_TOKEN`, 경로 `/analyze`(dispatch)·`/runs`(목록), 속성 `OWNER_USER_ID`와 같은 사용자만 허용. `notes.html`은 `gh.call` 대신 중계 서버 호출. SETTING 학습 노트 칸 삭제 | `apps-script/Code.gs`, `public/notes.html`, `public/settings.html`, `public/site.js` | 소유자만 분석 요청 가능, 다른 계정은 거부 |
| G8 | 옛 값 청소: 새 버전 첫 실행 때 `localStorage.removeItem('pp-key')`, `removeItem('sn-token')`, `removeItem('sn-repo')` | `public/site.js` | 브라우저 저장소에 두 키가 없음 |
| G9 | 키 재발급 **(사람)**: `PRACTICE_KEY` 삭제, GitHub 토큰 폐기, 노션 통합 토큰 재발급 후 G3로 다시 등록 | GitHub·노션·Apps Script 설정 | 옛 값으로 호출하면 실패 |
| G10 | XSS 방어 동일 적용: `esc`/`textContent`, `safeUrl`, CSP meta, SRI. ULevelP X1 `test/security.test.js`를 복사해서 돌림 | `public/*`, `test/` | 테스트 통과, 콘솔에 `Refused to` 없음 |

**G7·G8·G9는 같이 해야 의미가 있다**: 옛 값이 브라우저에 남아 있거나 아직 유효하면 같은 Origin의 XSS로 여전히 훔칠 수 있다.

## 7. 그 전까지 할 수 있는 임시 조치 (소유자)

- GitHub 토큰은 fine-grained, 저장소 1개, Actions 쓰기만, **만료일을 짧게**(예: 30일).
- 노션 통합은 연습 곡·기록·노트 DB 3개에만 연결(워크스페이스 전체 연결 금지).
- `practice.html#api=…&k=…` 주소를 노션 블록·임베드에 넣지 않는다(키가 블록에 남음. apps-script README에도 적혀 있음).
