## 3. 설계 (2026-11-05 사용자 승인)

### 3-1. 실패 원인 코드 (GA-1)

서버는 `analysis_jobs.error` 문자열 앞에 `<코드>: ` 를 붙인다(기존 `PROVIDER_KEY_INVALID:` 와 같은 방식 — 필드·스키마는 그대로).

| Gemini 응답 | 코드 | 재시도 | 화면 제목 | 화면 안내 |
| --- | --- | --- | --- | --- |
| 402 | `GEMINI_BILLING` | 안 함 | 크레딧 부족 | AI Studio에서 결제·크레딧을 확인한 뒤 다시 시도 |
| 429 (재시도 4회 뒤) | `GEMINI_RATE_LIMIT` | 함(기존) | 호출 한도 초과 | 잠시 뒤 다시 시도. 무료 등급이면 짧은 영상·구간으로 |
| 500·503 (재시도 4회 뒤) | `GEMINI_OVERLOADED` | 함(기존) | Gemini 일시 장애 | Google 쪽 과부하. 잠시 뒤 다시 시도 |
| 401·403·400+`API_KEY_INVALID` | `PROVIDER_KEY_INVALID`(기존) | 안 함 | Gemini 키 오류 | 설정에서 키 확인 |
| 그 밖 400·기타·네트워크 | `GEMINI_API_ERROR` | 기존대로 | 분석 실패 | Google 오류 문구(있으면) 표시 |
| 코드 없음(시간 초과·응답 파싱 등) | — | — | 분석 실패 | 서버 문장 그대로 |

- Google 응답의 `error.message`가 있으면 문장 끝에 덧붙인다(200자 이내). 화면은 제목 + 안내, 원문은 `title`(마우스 올림)
- 순수 함수 `frontend/src/lib/jobError.ts`가 문자열 → `{ code, title, hint, detail }` 변환. CHORDS·노트 두 화면이 같이 씀
- **대체 모델은 넣지 않음**(사용자 결정 — 비즈니스 운영에선 불필요). 옵션 메모: 503이 계속되면 `gemini-flash-lite-latest`로 1~2회 더 시도, 모델은 env `GEMINI_FALLBACK_MODEL`. 대체 모델이 `thinkingLevel`을 받지 않으면 400 가능 → 그때 빼고 호출

### 3-2. 구간 + 코드 진행 변화 속도 (GA-2)

**DB `V4__analysis_job_options.sql`**

```sql
ALTER TABLE analysis_jobs
  ADD COLUMN start_sec INTEGER CHECK (start_sec BETWEEN 0 AND 86400),
  ADD COLUMN end_sec   INTEGER CHECK (end_sec BETWEEN 0 AND 86400),
  ADD COLUMN pace      TEXT CHECK (pace IN ('slow', 'normal', 'fast')),
  ADD CONSTRAINT analysis_jobs_range_chk CHECK (start_sec IS NULL OR end_sec IS NULL OR start_sec < end_sec);
```

- 모두 NULL 허용. NULL이면 지금 동작(노트 분석·기존 행 영향 없음)

**API `POST /api/v1/progressions/analyze` 요청 본문 — 선택 필드 추가**

| 필드 | 형식 | 검증(실패 400) |
| --- | --- | --- |
| `startSec` | 정수 초 | 0 이상 86400 이하 |
| `endSec` | 정수 초 | 0~86400, `startSec`이 있으면 그보다 커야 함(1초 이상) |
| `pace` | `slow` / `normal` / `fast` | 그 밖은 400. 없으면 `normal` |

- 작업 응답(`/notes/jobs`, `/notes/jobs/{id}`)에 `startSec`·`endSec`·`pace` 선택 필드 추가(없으면 null)

**Gemini 호출** — `video_metadata`에 `fps` + (구간이 있으면) `start_offset`·`end_offset`(`"40s"` 형식)

| pace | 화면 | fps | 초당 토큰(추정, LOW 해상도 프레임 ~66 + 오디오 32) |
| --- | --- | --- | --- |
| `slow` | 느림 | 0.5 | ~65 |
| `normal` | 보통(기본) | 1 | ~100 |
| `fast` | 빠름 | 3 | ~230 |

- 노트 분석은 지금처럼 `GEMINI_FRAME_FPS`(기본 0.2)
- `GeminiClient.generateNoteAnalysis`에 기본값 null인 인자 추가(메뉴얼 — 승인됨): `videoOptions: GeminiVideoOptions? = null` (`fps`, `startSec`, `endSec`)
- 토큰 수·허용 fps 범위·구간 지정 시 응답 타임스탬프 기준은 추정 → GA-3에서 실측

**화면 (CHORDS → 입력 "코드 진행 영상", `VideoAnalyzeForm.tsx`)**

- 구간: 시작·끝 입력(`1:20` 또는 `80`, 비우면 전체). 파싱은 `model.mts` 순수 함수
- `코드 진행 변화  느림 ← 보통 → 빠름` 3단 바(기본 보통). 안내: "코드가 짧은 시간 안에 많이 바뀐다면 빠름을 권장해요. 빠름은 분석량이 많아 구간을 짧게 잡는 게 좋아요."
- 실패·진행 줄에 구간·속도 표시(예 `0:40–1:20 · 빠름`)

### 3-4. 완료 줄 합치기 · 중복 방지 (GA-4, 2026-11-05 사용자 승인)

- 화면: 끝난 작업은 한 줄 `영상 k개 · n개 수집 · 최근 노트 보기`(1건이면 `n개 수집 · 노트 보기`), 진행 중·실패는 한 줄씩. `model.mts` `summarizeDoneJobs`
- 화면: submit을 `useRef`로 잠금(같은 순간 두 번째 클릭 무시), 진행 중 작업이 있으면 버튼 잠금 `분석 중…`
- 서버: 같은 사용자·영상·구간·속도의 queued·running·done 작업이 24시간 안이면 409 `DUPLICATE_ANALYSIS`(프로필 행 잠금 안, 동시 1건 429보다 먼저). 실패 작업은 제외. 노트 분석은 적용 안 함
- API: `/progressions/analyze` 선택 필드 `force`(boolean) → 확인 건너뜀. 화면은 409 뒤 버튼 `다시 분석` → `force: true`, 입력을 바꾸면 처음 상태
- 시그니처: `requestAnalyze(..., force: Boolean = false)`, `NoteService.DUPLICATE_WINDOW`. DB 스키마 변경 없음

## 5. 겪은 문제

- 2026-11-05 운영 실측: 첫 키 → 402 `Your prepayment credits are depleted`(결제 연결된 프로젝트는 무료 등급 아님), 둘째 키 → 503 `This model is currently experiencing high demand`(4회 재시도 모두), 선불 결제 뒤 성공 — 4마디 중 1·3마디만(0.2fps)
- 운영 DB 직접 조회(psql)는 자동 모드 권한에서 거부됨 → 확인은 Cloud Run 로그 + 화면

- GA-2: 토큰 사용량(`usageMetadata`)이 로그에 없었음 → 분석 성공 시 한 줄 로그 추가(`Gemini 분석 완료 jobId=… pace=… range=… fps=… usage=…`, 사용자 승인)
- GA-3: 사용자가 분석 요청을 여러 번 누름 → 서버 동시 1건 제한이 429로 막아 Gemini 호출은 3건뿐(결과 §4). 남은 틈은 GA-4
- GA-3: 구간 0~8초에서 마지막 코드가 잘린 듯(끝이 마디 중간) — 사용자: 이대로 쓰고 문제 생기면 수정
