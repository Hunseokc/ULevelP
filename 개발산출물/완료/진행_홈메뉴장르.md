## 3. 장르 태그 — 확인된 사실과 미결정

- 곡은 서버 DB `songs` 테이블(`V1__init.sql`, 컬럼에 장르 없음)과 `GET/PATCH /api/v1/songs`(`SongDto`)로 저장된다. 비로그인 곡은 기기(`ulp:v:*`).
- 플레이어에 장르·폴더 기능은 아직 없다.
- 선택지: (A) `songs.genre` 컬럼 + `SongDto.genre` + PATCH 허용(기기 간 유지, Flyway V2 + Kotlin 수정) / (B) 기기 저장 `videoId → genre` 맵(프론트만, 기기마다 따로).
- **결정(2026-11-04): A.** G-3에서 변경 목록 승인 완료 → 상세는 `결과/G-3_장르태그설계.md`. 설계와 구현을 나눠 G-3b를 새로 두었다(한 세션 분량).
- 비로그인 곡(`ulp:v:*`)은 장르 없음 → G-4에서 "미지정" 폴더.
- **PR 방식 결정(2026-11-04):** G-1 + G-2를 한 PR(base main)로 올린다(G-2 끝에 G-5 수행). G-3·G-4는 다음 PR.
- 제안 반영: 390px VAULT 빈 상태 문구가 칸 폭과 같아 말줄임 위험 → G-2에서 빈 상태 문구는 줄바꿈 허용.
- **재설계(2026-11-04):** 사용자가 "장르"가 아니라 사용자가 추가하는 **"분류"** 를 원함 → 곡당 여러 개(태그), 기본 분류 없이 시작, 홈 표시·순서는 서버. 상세 `결과/G-3c_분류설계.md`. G-3b 코드는 미커밋 상태로 폐기 예정(로컬 Supabase DB에만 V2 genre 적용됨 → G-3d에서 정리)
- 홈 → 플레이어 장르 전달: URL을 바꾸지 않으므로 `sessionStorage`에 한 번 쓰고 플레이어가 읽은 뒤 지운다(안).

## 5. 겪은 문제

- G-4b: 분류 체크박스를 서버 응답 뒤에만 바꾸면 Playwright `check()` 실패 → 낙관적 반영 + 실패 시 되돌림. 플레이어가 sessionStorage 값을 바로 소비해 C4a-5 단언 변경

- G-4a: e2e `getByLabel('분류 이름')`이 "새 분류 이름" 입력에도 걸려 strict 위반 → `{ exact: true }`

- G-3d: gradle 증분 컴파일이 `FileNotFoundException ... InvalidInputException.class`로 깨짐 → `./gradlew compileKotlin compileTestKotlin --rerun-tasks`로 해결

- G-3b: `.env`가 원격 DB를 가리켜 `./gradlew run`을 그대로 하면 원격에 V2가 적용된다 → 로컬 Supabase(54321/54322)로 환경변수를 덮어써서 curl 확인(방법은 `결과/G-3b_장르태그구현.md` §4)

- G-2: 테스트에서 `addInitScript`는 새로고침 때도 다시 실행된다 → 저장값 시나리오는 테스트를 나눌 것
- G-1: 노트 썸네일을 136px로 키우자 390px에서 빈 상태 문구 말줄임(H3) → 좁은 폭(≤820px)에선 104px 유지
- G-1: 스크린샷은 `document.fonts.ready` 전에 찍으면 폰트 대체로 글자가 넓어 말줄임처럼 보인다. 검사와 같은 조건으로 찍을 것
